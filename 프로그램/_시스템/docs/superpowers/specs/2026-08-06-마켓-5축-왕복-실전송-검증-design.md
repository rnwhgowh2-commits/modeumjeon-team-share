> 날짜: 2026-08-06 · 브랜치 `feature/market-roundtrip-test`
> 지도 게이트: `consult-market-map` 0~4단계 통과 (아래 §2)

## 1. 무엇을 만드나

우리 프로그램이 마켓에 **정말로 값을 바꿔 보내는지**를, 5축 각각에 대해
「바꿔 보낸다 → 마켓에서 되읽어 확인한다 → 원래대로 되돌린다 → 되읽어 확인한다」
왕복으로 증명하는 검증 하네스.

5축 = **가격 · 재고 · 상품명 · 상세페이지 · 이미지**

### 왜 필요한가

전송 코드가 200 을 받아도 마켓에 실제로 반영됐다는 뜻은 아니다. 이 저장소에는
이미 그런 사고 기록이 있다 — ESM `register_goods` 가 「HTTP 200 인데 goodsNo 없음」을
성공으로 봤던 것(거짓 성공 금지 규칙의 유래). **되읽기 없는 전송 검증은 검증이 아니다.**

| 마켓 | 가격 | 재고 | 상품명 | 상세 | 이미지 | 되읽기(조회) |

| 쿠팡 | ✅ `prices.update_price` | ✅ `inventory.update_quantity` | ❌ | ❌ | ❌ | ⚠️ 옵션재고 None |
| 롯데온 | ✅ `prices.update_price` | ✅ `inventory.update_stock` | ❌ | ❌ | ❌ | ✅ `products.get_product_detail` |
| 11번가 | ✅ `prices.update_price` | ⚠️ `update_stock_by_stock_no` 만 | ❌ | ❌ | ❌ | ⚠️ 상품명 없음 |
| 옥션·G마켓 | ✅ `esm/prices.update_price` | ✅ `esm/inventory.update_stock` | ❌ | ❌ | ❌ | ✅ `esm/products.get_goods_detail` |

- ⬜ = **엔드포인트는 이미 라이브 검증(st=ok)이고 우리 코드가 그 PUT 을 쓰고 있다.
  본문에 `name`·`detailContent`·`images` 가 그대로 실려 나가는데, 우리가 안 바꾸고
  받은 값을 그대로 되돌려 보낼 뿐이다** (`edit_product.py:86` GET → `:132` PUT).
  → 3축 전송은 새 연동이 아니라 이 함수에 **쓰기 3줄 추가**.
- ❌ = 지도에 API 는 등재돼 있으나(`coupang.products.product-modification-*`,
  `lotteon.product.update`, `auction/gmarket.esm.21`) **호출하는 코드 0줄**.

### 2-2. 상품가공정책 — 생성 코드는 완비

`lemouton/registration/process_apply.py` — 가공규칙 13항목 전부 구현:
`_build_name`(1126) · `_apply_detail`(702) · `_apply_images`(615) · `_apply_options`(509) ·
`_apply_shipping`(771) · `_apply_origin`(870) · `_apply_kc`(903).
이미지 CDN 업로드 = `lemouton/registration/image_prep.prepare_cdn_images`.

**즉 「무엇을 보낼지 만드는 쪽」은 다 있고, 「등록된 상품의 그 필드를 바꿔 쓰는 쪽」만 없다.**

### 2-3. 확인불가 (날조 금지)

- 쿠팡: 상품수정 API 는 지도에 `st=code`(문서만·코드 0줄). 재심사 유발 여부 **확인불가**.
- 롯데온 `product/modification/request`: `st=code`. 요청 필드 스펙 **확인불가**.
- ESM `esm.21 PUT /item/v1/goods`: `st=code`, 라이브 미검증(키는 있으나 호출 이력 없음).
- 11번가: 상품 상세 조회 스펙 미확보 → **상품명·상세·이미지 되읽기 불가** → 이 마켓은
  5축 중 3축을 「확인불가」로 보고한다(추측 금지).

### 2-4. ⑦과거이력에서 이 작업에 직접 걸리는 함정

| 이력 | 이 설계에 반영한 것 |
|---|---|
| 스스 수정은 `originProductNo` 인데 저장값은 `channelProductNo` (2026-07-17) | 스냅샷·전송 모두 `resolve_product_ids` 로 변환 후 호출 |
| 다계정 전송이 전역 기본 어댑터로 나가 NOT_FOUND (2026-07-17) | 반드시 `env_prefix` 로 계정 어댑터 생성. 폴백 금지 |
| 11번가 `update_stock` 은 전체교체라 형제 옵션을 지운다 | 11번가 재고는 `update_stock_by_stock_no` 만 사용 |
| ESM 재고수정은 `details[]` 전체 재전송(echo-back) | ESM 은 되읽은 봉투를 그대로 되돌려 원복 |
| 스스 429 잦음(동시성 8에서 72%) | 왕복은 **순차**. 동시 발사 금지 |
| 에러 없이 틀린 값 = 가장 위험 (2026-07-23) | 되읽기 불일치는 전부 실패로 표면화 |

## 3. 구조 — 3층

```
lemouton/uploader/roundtrip/
  ├─ snapshot.py   ① 5축 되읽기        → Snapshot
  ├─ apply.py      ② 5축 쓰기          → ApplyResult
  ├─ runner.py     ③ 왕복 절차(순수)    → RoundtripReport
  └─ journal.py    저널 파일(원복 보험)
```

### ① `snapshot.py` — 5축 되읽기

```python
@dataclass(frozen=True)
class Snapshot:
    market: str
    product_id: str
    name: str | None            # None = 그 마켓이 안 줌(확인불가). '' 와 구분
    detail_html: str | None
    image_urls: tuple[str, ...] | None
    sale_price: int | None
    options: tuple[OptionSnap, ...]   # (option_id, stock, price)
    raw: dict                    # 원본 응답 — 원복은 이걸로 한다
    missing: tuple[str, ...]     # 이 마켓이 못 주는 축 이름들
```

**규칙**: 마켓이 안 주는 축은 `None` + `missing` 에 이름. **0·빈문자로 채우지 않는다**
(`market_fetch.py:122` 의 「unknown → 품절 붕괴 금지」 관례와 동일).

### ② `apply.py` — 5축 쓰기

마켓별 어댑터. 스마트스토어부터:

```python
edit_options(origin_product_no, *,
             sale_price=None, option_updates=None, immediate_discount=None,
             name=None,            # ← 신설
             detail_html=None,     # ← 신설
             image_urls=None,      # ← 신설
             client=None)
```

기존 GET→PUT 왕복 그대로. `None` 이면 손대지 않음(현행 동작 100% 보존).

### ③ `runner.py` — 왕복 절차

```
1. before = snapshot()                      # 마켓 GET
2. journal.write(before)                    # ★ 파일 먼저. 실패하면 전송 안 함
3. try:
4.     apply(test_values)                   # 마켓 PUT
5.     after = snapshot()                   # 마켓 GET
6.     verify(after == test_values)         # 반영 확인
7. finally:
8.     apply(before)                        # 원복 — 예외 나도 반드시
9.     restored = snapshot()                # 마켓 GET
10.    verify(restored == before)           # 원복 확인
11.    journal.close(성공/🔴실패)
```

## 4. 안전 5규칙

1. **원복값 = 마켓이 실제로 준 값.** 「우리가 보내려던 값」이 아니라 4단계 직전 GET 응답에서 뜬 값.
2. **저널 먼저.** `before` 를 `shared/state_store.state_path()` 파일에 쓰기 전엔 전송 금지.
   (앱 컨테이너 `data/` 는 배포마다 사라진다 — CLAUDE.md)
3. **원복은 `finally`.** 검증이 실패해도, 예외가 나도 원복은 돈다.
4. **원복 실패 = 🔴 경보 + 저널 경로 출력.** 조용한 실패 금지. 손복구 절차를 응답에 담는다.
5. **`price_guard.assert_live_sale_price` 유지.** 0·음수·비정수 판매가는 전송 직전 abort.

추가:
6. **대상은 판매중지 상품만.** 전송 전 판매상태를 조회해 「판매중」이면 **거부**.
7. **순차 전송.** 스스 429(동시성 8에서 72%) 회피.
8. **2중 잠금 계승.** `arm=1` + 서버 `MOUM_LIVE_UPLOAD` 둘 다여야 실전송.

## 5. 5축 시험값

| 축 | 시험값 | 되읽어 확인할 것 |
|---|---|---|
| 가격 | 현재가 **+1,000원** | GET 이 +1,000 을 주는가 |
| 재고 | **7** | 7 이 오는가 |
| 상품명 | 현재명 + `" (시험중)"` | 접미가 붙었는가 |
| 상세 | 원 HTML + `<p data-roundtrip="1">시험</p>` | 그 문구가 있는가 |
| 이미지 | **PNG 1장 새로 만들어** CDN 업로드 → 대표 교체 | 대표 URL 이 바뀌었는가 |

이미지는 `Pillow` 로 시험용 PNG 를 만들어 `image_prep.prepare_cdn_images()`
(네이버 CDN 업로드, 기존 코드)로 올린 뒤 그 URL 로 교체한다.
**원복은 원래 이미지 URL 목록 그대로.**

## 9. 이 설계가 하지 않는 것 (YAGNI)

- 쿠팡·롯데온·ESM 의 상품명·상세·이미지 **수정 기능 신설** — 별건(지도 `st=code`, 재심사 정책 확인불가)
- 여러 상품 동시 왕복 — 1상품 1축씩 순차
- 자동 스케줄 — 사람이 부를 때만
