# 시안 선택 스킬 (draft-picker)

여러 후보를 채팅 텍스트로 나열하고 "어느 게 좋으세요?"라고 타이핑 답을 기다리지 않는다. 대신 탭으로 고르고 탭으로 확정하는 모바일 친화 아티팩트 하나를 발행한다.

## 언제 쓰나

- 화면/버튼/컴포넌트 시안, 색상·레이아웃 스타일, 문구(카피) 후보, 기능 구현 방식 등 — **정답이 하나가 아니라 사장님의 취향·판단이 필요한 모든 갈림길**.
- 후보가 2개 이상일 때만. 단순 "이대로 진행할까요?" 같은 예/아니오 확인은 이 스킬 대상이 아니다.

## 핵심 원칙

1. **항상 아티팩트로 만든다.** 채팅 텍스트로 "1안/2안/3안" 나열 금지. 모바일 우선(큰 탭 영역, 세로 스택), 손가락 탭만으로 끝나야 한다.
2. 시안마다 카드형 버튼 — 탭하면 즉시 선택 표시(하이라이트 + 체크 표시).
3. **선택해야 할 항목(그룹)마다** 아래 3종 보조 버튼을 같이 둔다:
   - 🔄 **다른 타입으로 더보기** — 지금 보여준 것과 다른 방향·스타일을 더 원한다는 요청(그룹당 1개).
   - 🔍 **N번 시안 더 보기** — 특정 시안과 비슷한 걸 더 보고 싶다는 요청. 카드마다 하나씩 달아서 "몇 번"인지 자연히 명확해지게 한다.
   - ✏️ **기타(직접 입력)** — 버튼 어디에도 안 맞을 때만 펼치는 짧은 텍스트칸. 기본은 접어 둔다(타이핑을 강요하지 않는 게 원칙이므로 기본 노출 금지).
4. 화면 맨 아래 **확인** 버튼 하나로 지금까지의 선택을 확정한다. 그룹별로 따로 확정하지 않는다. 확정 후 선택을 바꾸면 확정은 자동 해제된다(다시 눌러야 함) — "확정했다고 떴는데 사실 옛날 선택"이 되는 걸 막기 위함.
5. 어떤 버튼도 그 자리에서 새 시안을 즉석 생성하지 않는다(정적 페이지이므로 불가능). 버튼은 "요청을 기록"할 뿐이고, Claude가 나중에 그 기록을 보고 실제로 새 시안을 만들어 온다. 이 페이지에 그 사실을 짧게 안내해 사장님이 헷갈리지 않게 한다.

## 왜 이렇게 동작하나 — `artifact` capability

Artifact는 발행 후 고정된 정적 페이지라, 버튼을 눌러도 원래는 Claude에게 아무 것도 전달되지 않는다. 이 문제를 푸는 게 `artifact` capability다 (세션에 있으면 `artifact-capabilities` 스킬로 원문 확인 가능 — 여긴 이 스킬에 필요한 만큼만 요약):

- Artifact 발행 시 `capabilities: { artifact: {} }` 를 넘기면, 페이지 안에서 `await claude.use('artifact')` 로 쓰기 핸들을 얻는다.
- 이 핸들의 `publish(html)` 은 **완전한 새 HTML 문서**를 통째로 새 버전으로 저장한다. 즉 사장님이 카드를 탭할 때마다, 페이지 스스로 "지금 상태를 반영한 새 문서"를 만들어 자기 자신을 다시 발행하는 구조다. 부분 업데이트가 아니라 전체 문서 교체이며, 성공하면 그 화면은 자동 새로고침된다.
- 나중에 Claude가 같은 아티팩트 URL을 WebFetch로 다시 읽으면, 사장님이 마지막으로 저장한(=탭한) 상태 그대로를 보게 된다. **실시간으로 Claude에게 알림이 가는 게 아니다** — 사장님이 "확인했어" 라고 채팅으로 알려주거나, Claude가 다음에 다시 확인할 때 비로소 반영된다. 이 점을 사장님에게 짧게 안내해도 좋다.
- capability가 없거나(구버전 뷰어 등) 쓰기 권한이 거부되면(`not_writer`/`not_granted` 등) 자동 저장이 안 되므로, 화면은 조용히 "읽기 전용" 모드로 바뀌어 현재 선택 요약을 복사해서 채팅에 붙여넣도록 안내한다. 이건 예외 상황 대비용이고 기본 경로가 아니다.

이 메커니즘은 이미 `assets/template.html` 안에 다 구현돼 있다. **아래 "만드는 절차"만 따르면 이 문단의 내용을 직접 구현할 필요는 없다** — 왜 이렇게 동작하는지 이해하고 있으면 충분하다.

## 만드는 절차

1. (다른 아티팩트와 동일하게) 발행 전 `artifact-design` 스킬을 로드한다 — 이 템플릿이 레이아웃·톤 앤 매너를 이미 잡아 놨으므로 새로 디자인을 고민할 필요는 없고, 확인 차원.
2. `assets/template.html` 을 읽고 그대로 복사해서 새 아티팩트 소스로 쓴다. **CSS와 스크립트 로직은 건드리지 않는다** — `DATA` 상수(파일 상단 스크립트 안, 예시 데이터가 채워져 있음)와 파일 맨 위 `<title>` 태그만 실제 내용으로 교체한다:
   - `<title>` 태그(파일 최상단, `DATA` 보다 먼저 나옴)와 `DATA.title` 둘 다: 이번 시안 선택의 제목. **`Artifact` 툴의 `title` 파라미터가 아니라 이 `<title>` 태그가 실제로 이긴다**(발행 시 확인됨 — 파일 안에 `<title>`이 있으면 툴 파라미터는 무시된다). 파라미터만 바꾸고 태그를 안 바꾸면 갤러리에 "시안 선택"이라는 기본값 그대로 뜬다.
   - `groups[].label`: 선택해야 할 항목 이름 (예: "1. 주문 확정 버튼 색상").
   - `groups[].drafts[]`: 시안 카드들 — `id`(1부터 순번), `title`, `desc`(짧은 설명, 선택).
   - 그룹·카드 개수는 자유. 보조 버튼 3종과 확인 버튼은 로직이 자동으로 렌더링하므로 손댈 필요 없음.
3. `Artifact` 툴 호출 시 **반드시** `capabilities: { artifact: {} }` 를 넘긴다. 빠뜨리면 탭이 저장되지 않고 조용히 읽기 전용 모드로 빠진다(동작은 하지만 사장님이 매번 복사-붙여넣기 해야 해서 이 스킬의 취지가 무너짐).
4. 발행 후 사장님에게 링크 전달 + "카드 탭해서 고르고, 맨 아래 확인 누르면 끝"이라고 짧게 안내한다.
5. 사장님이 확인했다고 알리면(또는 다음 체크인 때) **같은 URL을 WebFetch로 다시 읽는다.** 페이지 중간의 "📋 현재 선택 요약" 블록이 평문으로 그룹별 선택·기타 의견·추가 요청·확정 여부를 담고 있으니 그것만 보면 된다(마크업이 바뀌어도 이 블록 텍스트 형식은 고정).
   - "다른 타입으로 더보기"나 "N번 더 보기" 요청이 있으면, 그걸 반영해 새 시안 그룹(또는 새 카드)을 만들어 **다음 절차부터 다시 진행**한다(1번부터, 새 아티팩트로).
   - 확정(✅)만 돼 있으면 그 선택대로 다음 작업을 진행한다.
6. **이미 사장님에게 넘긴 아티팩트를 Claude가 다시 발행하지 않는다.** 같은 URL로 `Artifact` 툴을 다시 부르면 사장님이 탭해서 쌓아온 상태를 Claude의 로컬 파일 내용으로 덮어써 버린다. 내용을 바꿔야 하면(요청 반영 등) 4번처럼 **새 아티팩트**를 만들어 새 링크로 안내한다.

## 체크리스트 (발행 전)

- [ ] `capabilities: { artifact: {} }` 를 넘겼는가
- [ ] `DATA` 와 `<title>` 태그만 바꿨고 CSS/스크립트 로직은 그대로인가
- [ ] 그룹마다 보조 버튼 3종(다른 타입 더보기 / N번 더보기 / 기타)이 다 보이는가 (템플릿이 자동 처리하므로 데이터만 맞으면 보장됨)
- [ ] 맨 아래 확인 버튼 하나로 전체가 확정되는가
- [ ] 카드가 모바일에서 손가락으로 누르기 충분히 큰가 (템플릿 기본값이 이미 충족 — 커스터마이즈했다면 재확인)

## 참고 자료

- 실제 코드·저장 로직: `assets/template.html` (주석으로 self-capture 트릭 등 구현 이유 설명돼 있음).
- `artifact` capability 원문 스펙: 세션의 `artifact-capabilities` 스킬 (`claude.use('artifact')`, `publish()` 에러 코드 등 더 깊은 내용 필요할 때만).
- 아티팩트 발행 자체의 일반 규칙(테마 대응, 자체완결형, 파비콘 등): `artifact-design` 스킬.
