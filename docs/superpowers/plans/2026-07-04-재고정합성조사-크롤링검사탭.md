```python
@bp.route("/crawl-check")
def crawl_check():
    """크롤링 검사 카드 — 2탭(재고 정합성 검사 / 가격 정합성 검사).

    재고 탭 = 재고 정합성 조사 프로토콜 전체 프롬프트(복사형). 순수 정적 표시 — 서버 로직·DB 무영향.
    ?bare=1 → 사이드바 없는 최소 레이아웃(_bare.html). 전체보기 팝업이 iframe 으로 띄움.
    """
    if request.args.get("bare"):
        # 전체보기의 same-origin iframe 팝업 → 전역 X-Frame-Options: DENY 예외.
        resp = make_response(render_template(
            "sourcing_guide/crawl_check.html", active="sourcing_guide", layout="_bare.html"))
        resp.headers["X-Frame-Options"] = "SAMEORIGIN"
        return resp
    return render_template("sourcing_guide/crawl_check.html",
                           active="sourcing_guide", layout="base.html")
```

재고 정합성 조사를 시작한다. 아래 프로토콜을 순서대로 실행하라.

■ 대상
- 소싱처: (소싱처명 입력, 예: 롯데온)
- URL: 해당 소싱처의 매트릭스 등록 URL 전체

■ 절대 원칙 (CLAUDE.md 데이터 무결성 3대)
- 재고 기준 = 실브라우저 상품 URL의 실제 데이터. 추정·폴백·평균 금지.
- 확인 못 하면 '있음'이 아니라 '확인 불가'로 표기.
- 크롤 = 로컬(크롬 확장/Playwright). 서버 크롤 실패는 정상.

■ 5단계
1) 크롤: 대상 소싱처 매트릭스 등록 URL 전체를 로컬 크롤 → 최신 재고를 프로그램 DB에 반영.
2) 실브라우저 엑셀 조사: 각 URL을 실브라우저로 직접 열어 색×사이즈별 실제 재고
   (상태 + 가능하면 수량)를 읽어 엑셀로 정리.
3) 대조: 크롤 결과값(매트릭스 보기 저장 데이터)과 2의 엑셀을 색×사이즈 셀 단위로 1:1 대조.
4) OK/NG 판정 + 이중 태그:
   · OK = 상태 일치 (수량 긁는 소싱처는 수량도 일치)
   · NG = 불일치. 두 태그를 모두 부착:
     [귀책] 그 URL을 실브라우저로 직접 열어 매트릭스의 그 색·사이즈와 같은 상품인지 확인
        U = URL측 문제(대체상품·다른상품·404·만료) → 사용자가 URL 정정
        P = 프로그램측 문제(URL은 맞는데 저장값 틀림) → 코드 수정
     [증상] A 품절둔갑(실=품절, 프로그램=있음) ★최고위험
            B 거짓품절(실=있음, 프로그램=품절/차단)
            C 999·센티넬둔갑(프로그램=센티넬, 실=실수량 존재 = 저장누락)
            D 미수집·확인불가 둔갑(크롤 매칭실패인데 '있음' 표기)
            E 수량불일치(상태는 맞으나 수량 상이)
5) 집계·출력:
   · 소싱처별 집계표: OK-1/OK-2, NG(귀책 U)/NG(귀책 P), 증상 A~E별 개수
   · 조치 리스트 2분리:
     - URL 정정 리스트(귀책 U): URL·색·사이즈·실값·프로그램값·왜 URL 문제인지
     - 코드 수정 리스트(귀책 P): 셀·증상·의심 코드 파일:라인
   · 색×사이즈 전수 대조 엑셀 산출

■ 진행 방식
- 크롤은 실시간 감시(사후 추측 금지). 로드된 확장 버전 먼저 확인.
