# Phase 1B — 「실전송 테스트」 화면 구현 플랜 (별도 화면 + 인라인 흐름)

> REQUIRED SUB-SKILL: subagent-driven-development / executing-plans. TDD, bite-sized.

**Goal:** 상품 하나만 골라 스스·쿠팡·롯데온에 안전하게 실제 반영하는 브라우저 화면. 별도 사이드바 메뉴 「실전송 테스트」 → 상품 검색 → 마켓 선택 → 미리보기(드라이런, 현재→보낼) → 확인 → 실제 전송 → 결과. 서버 측 실행이라 마켓 IP 문제 없음.

**Architecture:** Phase 1 의 스코프 원샷 로직을 재사용. run() 코어를 `scripts/live_send_skus.py` 에서 `lemouton/uploader/scoped_send.py` 로 옮겨(모듈화), CLI 와 웹 라우트 양쪽이 import. 라우트는 얇은 어댑터. 실전송은 기존 3중 게이트(서버키 필수) 그대로.

**Tech Stack:** Flask Blueprint, Jinja2, 기존 sets/uploader 모듈.

**작업 위치:** fresh origin/main 워크트리 `C:/dev/_wt_send_ui`, 브랜치 `feature/live-send-test-ui`.

**참조:** Phase 1 도구 `scripts/live_send_skus.py`(run·resolve_send_mode), `scripts/verify_pipeline_dryrun.py`(build_c_output only_skus), `lemouton/uploader/orchestrator.py`(run_uploader·_extract_uploads), `lemouton/sets/models.py`(ProductSet·SetProduct·SetOption·SetChannel), 시안 `바탕화면/모음전 시안 실전송테스트버튼 v1.html`.

## 완료 기준
- 별도 「실전송 테스트」 화면에서 상품 검색→마켓 선택→미리보기(현재→보낼)→확인→전송→결과.
- 실전송은 3중 게이트(서버키 필수)·price_guard·정직한 실패보고 보존(scoped_send=run_uploader 재사용).
- 스스·쿠팡·롯데온 대상. 11번가는 셀러 쓰기 API 확보 후 추가.
- 라우트·게이트·스코프 테스트 통과. 라이브 실동작은 사용자 검증.
