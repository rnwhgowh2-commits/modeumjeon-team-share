## Phase 8 — 즉시할인을 옥션·G마켓에도 건다

### 🔴 착수 전 예상이 틀렸다

설계서 §5-2 는 「옥션·G마켓 = ESM `seller-discounts` 라는 **별도 API**」라 적혀 있었다.
`consult-market-map` 게이트로 지도를 **전문** 정독하니, 즉시할인은
**등록 payload 안**에 있었다:

```
addtionalInfo.sellerDiscount = {
  isUse: bool,
  iac | gmkt: { type: 0사용안함|1정액|2정률, priceOrRate1, startDate, endDate }
}
```

새 API 를 부를 필요가 없었다. 기존 등록 요청에 칸만 더하면 된다.

### 문서에 적힌 제약을 그대로 막이로

| 제약 | 지도 원문 |
|---|---|
| 정액 최소 100원 · 10원 단위 | 「정액 설정시 : 최소 100원 이상,10원 단위」 |
| 정률 70%까지 | 「정률 설정시 : 판매가대비 70%까지 허용」 |

넘으면 **사람 말로 사유**를 돌려준다 — 마켓에 보내 놓고 「입력한 데이터가 유효하지
않습니다」를 받으면 사장님은 무엇이 잘못인지 알 수 없다.

### 🔴 옥션 = `iac` · G마켓 = `gmkt`

지도 원문: 「옥션 경우 아래 gmkt Entity대신 iac 입력」.
**바꿔 넣으면 엉뚱한 사이트에 할인이 걸린다** — 시험으로 못 박았다.

### 안 정하면 아무것도 안 보낸다

기간(start/end)을 안 주면 날짜 칸을 **아예 안 넣는다**. 오늘 날짜를 지어 넣으면
사장님이 정한 적 없는 기간이 마켓에 걸린다.

### 롯데ON = 확인 불가

「판매자할인 저장」(apiNo=122)이 지도에 **[off]·상세 미접수**다. URL 도 칸 이름도 없다.
**없다고 단정하지 않고** 「확인 불가」로 남겼다.

### 🔴 화면이 마켓 목록을 손으로 박아 두고 있었다

`{% set disc_sends = market in ('smartstore', 'coupang') %}` — 정본(`discount.SUPPORTED`)이
늘어도 화면은 옛말을 한다. 서버가 정본으로 판정해 넘기게 고쳤고, 목록이 자동으로
「스마트스토어·쿠팡·옥션·G마켓」으로 늘었다.

## Phase 7-2c — 카테고리 새 방식을 전송에도 쓴다

### 순서를 못 박았다

```
① 옛 방식 — CategoryMapRow 의 confirmed (소싱처 → 마켓 직접)
② 없을 때만 — 소싱처 → 정규 카테고리 → 마켓
```

🔴 **옛 것을 먼저 본다.** 지금까지 잘 나가던 상품의 카테고리가 **한 개도 안 바뀌게**
하기 위해서다. 새 방식은 빈자리만 채우고 **덮지 않는다**.

### 「못 올림」·「인증 필요」는 코드를 안 돌려준다

그 분류로 올리면 마켓이 거부한다. 「아직 안 이음」과 같은 자리로 떨어져 전송이 막히되,
**사유는 따로 말한다**:

> 이 분류는 「이 마켓엔 못 올림」로 표시돼 있습니다 — 계정 권한상 못 쓰는 분류 —
> 다른 분류로 이어 주세요.

안 말하면 사장님은 이으러 갔다가 「이미 이었는데?」 하고 헤맨다.

### 읽다 실패해도 전송이 안 멈춘다

새 표가 아직 없는 환경에서도 옛 방식이 그대로 돈다. 읽기 실패로 전송을 멈추면
잘 나가던 상품이 조용히 죽는다.

### 판정은 한 곳

`_mapped_category` 한 곳이다. 가공 엔진(`process_apply`)은 카테고리 표를 직접 안 본다 —
두 곳에서 판정하면 답이 갈린다. 시험으로 못 박았다.

## 후속 후보 — 옥션·G마켓 즉시할인 「실전송 검증 워크플로」

스마트스토어·쿠팡용으로는 이미 있다 — `.github/workflows/live-test-instant-discount.yml`.
안전장치 3겹이 잘 설계돼 있다:

1. 대상을 **입력으로 직접 적어야** 한다(기본값 없음 — 실수로 눌러도 안 돈다)
2. 원래 값을 먼저 읽어 두고 **끝나면 그대로 되돌린다**
3. 되돌리기 실패 시 크게 외치고 `exit 1` (조용히 끝나지 않는다)
4. 대상은 **판매중지 시험 상품만** — 검증 창 동안 고객이 살 수 없다

옥션·G마켓용으로 같은 모양을 만들면 「마켓이 실제로 받아 주고 화면에 어떻게 뜨나」까지
확인된다. 다만 지금은 **드라이런으로 payload 가 정확함이 확인**됐고
(옥션 10%→`iac`만 · G마켓 5,000원→`gmkt`만 · 안 정하면 칸 없음),
라이브 상품 10건 전수로 `iac`/`gmkt` 규약도 확정됐으므로 **급하지 않다.**

만들 때 주의: ESM 은 「수정」 전문이 등록 전문과 같은 구조에 최상위 `isSell` 만 더한
모양이다(지도 원문). 되돌리기는 `sellerDiscount.isUse=false` 가 아니라 **원래 값 그대로**
써야 한다 — 원래 할인이 걸려 있었다면 끄면 안 된다.
