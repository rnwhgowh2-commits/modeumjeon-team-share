## 목표

`bundles/<code>#tab=opt` 매트릭스의 **전체 크롤 소싱처 카드**(르무통 공홈·무신사·SSF·SSG…, 최저가 1위)
각각의 안에 **‘영수증 / 스크린샷’ 미니탭**을 넣어:
- **영수증 탭** = 그 소싱처의 매입가 브레이크다운 (예제와 동일 `.rc` 디자인: 표면가 → −선반영 → 베이스① → −최대적립 → 베이스② → 최종)
- **스크린샷 탭** = 그 소싱처 기준 스크린샷

## 어디를 고치나 (조사 결과)

1. **카드 빌더 JS** — `webapp/static/toss.js` (2,400줄+, 매트릭스 핵심).
   - 전체 크롤 소싱처 카드는 여기서 동적 생성됨. 정확한 함수는 `전체 크롤`/`최저가`/소싱처 카드 렌더 부분을 grep해 특정할 것.
2. **번들 페이지** — `webapp/templates/bundles/edit.html` (#tab=opt 컨테이너).
3. **영수증 데이터** — `webapp/routes/api_benefits.py::compute_breakdown` (이미 표면가→베이스①②→최종 브레이크다운 산출). 소싱처별 호출.
   - 또는 신규 `gate-preview`(`sourcing_guide.py`) 재사용 검토. 단 gate-preview는 크롤 라인 입력형이라, 매트릭스엔 `compute_breakdown` 직접이 자연스러움.
4. **스크린샷** — 크롤 가이드 `guide.verification.examples[].screenshot_url` (소싱처별 SourceRegistry.crawl_guide). 소싱처 id↔guide 매핑(`_SITE_BY_SRC` in api_benefits.py: 1 lemouton/3 musinsa/4 ssf/5 lotteon/6 ssg).

## 구현 단계

1. **데이터 엔드포인트** (필요 시): 소싱처별 {breakdown(=영수증 라인), screenshot_url} 반환.
   - `compute_breakdown` 결과(steps/items_used)를 예제 `.rc` 라인 형태(표면/pre/base1/deducts/base2/final)로 매핑하는 어댑터.
   - 스크린샷은 SourceRegistry.crawl_guide → verification.examples 에서 그 상품 URL 매칭분.
2. **카드 빌더 JS**: 각 소싱처 카드에 탭 UI(영수증/스크린샷) + 펼침 영역 추가. 기본 접힘.
3. **영수증 렌더**: 예제와 동일 `.rc` 마크업/CSS 재사용 (sourcing_guide detail.html 의 `.rc` 스타일을 toss.css 로 이식 또는 공통화).
4. **스크린샷 렌더**: `.exshot`/`.shot` 디자인 동일.

## 무결성 / 회귀 (필수)

- **머니 경로**: toss.js 매트릭스 = 전 가격. **회귀 테스트 필수** — 변경 전후 매트릭스 셀 값/최저가 선정 동일 스냅샷 비교 후 머지.
- 탭 추가는 **표시 전용**(가격 계산 로직 불변)으로 한정. compute_breakdown 자체는 건드리지 말 것(읽기만).
- 카드 빌더 JS 수정 시 기존 카드 동작(크롤 버튼·진행률·최저가 뱃지) 깨짐 없는지 라이브 검증.
