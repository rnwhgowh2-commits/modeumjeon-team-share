# 크롤링 가이드 전면 재구성 — 데이터·코드 지도 정본화

> 작성: 2026-06-22 / 상태: 제안(승인 대기)
> 트리거: 사용자 요청 "프로그램 내 중요한 내용 업데이트" — 크롤링 가이드에 (ㄱ) 소싱처별 재고/가격(표면노출가−혜택=최종매입가) 수집 방법, (ㄴ) 모음전 상세>셀>매트릭스보기>로그 가격/재고 표기를, **데이터 위치 + 프로그램 파일 위치**까지 담아 정리.

## 0. 목적·목표 (사용자 명세 그대로)

- **목적**: 프로그램 업데이트마다 이미 해결됐던 문제가 재발하고, 재수정하려면 처음부터 같은 추적 과정을 반복함 → **그 반복 시간을 줄인다.**
- **목표 ㄱ (Claude)**: 방향을 잃었을 때 Claude Code가 **크롤링 가이드만 읽고 바로 학습·복귀**하도록, 아주 상세한 로직 + 핵심 코드 + 파일 경로까지. (Claude가 그대로 읽음)
- **목표 ㄴ (사용자)**: 사용자도 지금처럼 **직관적이고 상세하게** 이해. Claude·사용자 둘 다 읽힘.

## 1. 확정된 결정 (2026-06-22 사용자)

1. **형식**: Markdown 정본(SSOT) + 인앱 렌더. docs의 마크다운 1벌을 진실원천으로 두고 인앱 가이드 화면에도 그대로 렌더. → 관리 1곳, 드리프트 없음.
2. **범위**: 인앱 크롤링 가이드 **전면 재구성** (기존 4단계 카드·용어사전·설치·재고 비교표 포함 재배치).

## 2. 정본 문서 구조 — 3중 레이어

각 섹션을 **🟢쉬운 설명 → 🔧상세 로직 → 💻핵심 코드 + 파일:라인** 순으로. 사용자는 🟢만 읽어도 되고, Claude는 🔧💻까지 읽어 재오리엔테이션.

문서 위치: `docs/크롤링-가이드.md` (단일 파일 우선 — Claude가 한 번에 읽기 좋음. 분량 과다 시 `docs/크롤링-가이드/소싱처-<name>.md`로 분할).

### 목차
- **0. 전체 흐름 지도** — 크롤→저장→계산→표시 한 장 요약 + 4개 층 파일 위치표
    - 크롤러: `lemouton/sourcing/crawlers/<소싱처>.py`
    - 저장: `lemouton/sources/service.py:429,519` (`dynamic_benefits_json` 화이트리스트)
    - 계산: `webapp/routes/api_benefits.py:404~776` (`compute_breakdown`) + `lemouton/pricing/unified.py:75` (`compute_market_price`)
    - 표시: `webapp/routes/api_pricing.py:309~992` (`_option_matrix_data`) + `webapp/templates/bundles/_matrix_v3.html`
- **1. 재고편 — 소싱처별 재고 수집** (주제 ㄱ의 재고 부분, **가격과 분리**)
    - 소싱처별(무신사·SSG·SSF·롯데온·롯데아이몰·스마트스토어·르무통공홈):
        - 수집 방식(HTML/API/DOM, 비로그인/로그인) + 파일(`crawlers/<소싱처>.py`)
        - 재고 판정 규칙(3상태/센티넬 0=품절·999=더미·무신사10=충분/품절임박 (N)/usablInvQty=0/statcd=SLDOUT/li.soldout) + **데이터 위치**(`stock_label·stock_qty·stock_out` ← `_resolve_stock` / `last_stock`·`current_stock`) + 파일
- **2. 가격편 — 소싱처별 가격·혜택 수집** (주제 ㄱ의 가격 부분, **재고와 분리**)
    - 공통 가격 모델: 표면노출가 − 혜택 = 최종매입가 / 베이스금액①②, %는 항상 베이스금액 기준
    - 혜택 4분류: 선반영(preapplied)·후반영(deduct/accrue)·결제(payment)·캐시백(cashback)
    - 소싱처별 혜택 종류 + **계산 분기 실제 로직**(예: SSG MONEY 무조건적립 항상활성 vs 충전결제 3%↑만 / 현대카드 2.73% fallback) + 코드 인용
    - 데이터 위치(`dynamic_benefits_json` 키·`crawled_price`·breakdown) + 프로그램 위치(`service.py:429,519`·`api_benefits.py:537~776`·`unified.py:75`)
- **3. 매트릭스 보기 > 로그 가격/재고 표기** (주제 ㄴ)
    - **두 갈래 진실**: 표면노출가(셀·크롤로그 surf) vs 최종매입가(영수증·buy) — 왜 다른가
    - 가격 출처: `DATA.options[].sources[].crawled_price` ← `api_pricing.py:395`(`last_price`/`current_price`) / 최종가 `/api/source-benefits/breakdown`
    - 재고 출처: `stock_label·stock_qty·stock_out` ← `api_pricing.py:142`(`_resolve_stock`, 센티넬 해석)
    - 크롤 로그 흐름: 확장 background → `ext_bridge.js` → `crawl_log.js`(surf=표면/ buy=매입 분리표시)
    - 파일: `_matrix_v3.html`(셀·팝업·영수증), `crawl_log.js`, `ext_bridge.js`
- **4. 무결성 원칙 (방향 복귀 기준)** — 폴백가 금지 / 크롤실패=표기 / 하드리셋 / 단일진실원천(표면가=last_price, 매입가=compute_market_price)
- **5. 자주 재발하는 문제 + 복귀 체크리스트** — 조용한실패 클래스(무결성제약·진실원천분열·누락무경고), SSG 혜택 라이브크롤 미배선(save_crawl_result가 dynamic_benefits 미저장) 등 → Claude가 방향 잡는 진입점

## 3. 인앱 재구성 (IA)

- 새 탭 **"📖 데이터·코드 지도"** 신설 → 정본 마크다운 렌더(서버 런타임 변환).
- 기존 자산 재배치:
    - 소싱처별 4단계 카드(① 샘플URL ② 구조 ③ 매입가 ④ 검증) = **유지**(가격엔진 데이터 SSOT) + 새 지도와 상호 링크.
    - 용어사전·확장 설치 = 유지(사용자 친화).
    - 재고 비교표(how_to_add) = 정본 §1로 흡수·링크(중복 제거).
    - overview 폰트 ~2배 과대확대 정리(메모리 `project_sg_guide_font_and_preview_gotcha`).
