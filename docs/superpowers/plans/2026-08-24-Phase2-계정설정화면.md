> **선행 문서**

>
> **목표**: 「판매처 관리」에서 계정을 펼치면 등록 설정을 넣을 수 있고, 한 번 넣으면

**Architecture**: 저장은 Phase 1 의 `MarketAccountSetting`(공통 10칸 컬럼 + `extra` JSON).
읽기는 `account_settings.value_of()` / `is_set()` 단일 창구. 화면은 기존
`accounts/upload.html` 의 계정 표에 「설정」 펼침을 더한다 — **새 페이지를 만들지 않는다**.

**Tech Stack**: Flask · SQLAlchemy · Jinja2 · pytest

## 🔴 이 Phase 의 절대 규칙

1. **자격증명은 안 담는다.** API 키는 `.env` 가 단일 원천(`lemouton/auth/secrets.py`).
   이 화면은 **등록 설정만** 다룬다. 기존 「API 키」 폼은 건드리지 않는다.
2. **쿠팡 출고지·반품지는 새로 만들지 않는다.** `coupang_vendor_settings` 를 읽는다
   (읽는 곳이 이미 5군데 — 두 벌이 갈리면 어느 출고지로 나갔는지 못 쫓는다).
3. **재고 기본값(999)은 만들지 않는다.** 「재고는 소싱처 실제 재고로만」이 절대 규칙이다.
   `stock_default` 컬럼은 Phase 1 에 있으나 **화면에 노출하지 않는다.**
4. **「안 정함」과 「0원」을 가른다.** 빈 칸으로 두면 NULL(안 정함)로 저장한다.
   0 을 입력하면 0 으로 저장한다. 저장할 때 빈 칸을 0 으로 바꾸지 않는다.
5. `DEFAULT_FEES`(반품 5,000 · 교환 10,000)는 **새 계정을 처음 만들 때만** 넣는다.
   기존 계정의 NULL 을 채우지 않는다.

## 실화면 검증에서 잡은 것 (2026-08-24) — 시험 59건이 다 놓친 3건

> 코드만 보고 PASS 했다면 라이브에서 조용히 틀렸을 것들이다.

### 1. 🔴 기본 배송비가 실서버에서만 안 들어갔다
- **증상**: 계정을 새로 만들면 `return_fee` 가 5,000 이 아니라 「안 정함」이었다.
- **원인**: 이 표는 Phase 1 때 **NOT NULL 로 배포**됐다. 그 뒤 「안 정함=빈 값」으로
  규칙을 바꿨지만, 이미 만들어진 표의 제약은 `create_all` 이 **안 고친다**.
  `as_phone=NULL` 이 제약에 걸려 설정 행이 **아예 안 만들어졌다**.
- **왜 시험이 못 잡았나**: 시험은 매번 **새 표**를 만든다 — 새 표는 이미 nullable 이다.
- **고침**: `shared/db.py` — PostgreSQL 은 `ALTER … DROP NOT NULL`,
  SQLite 는 표를 다시 지어 옮긴다. 시험 2건으로 잠갔다.

### 2. 🔴 폴백이 돈 칸에 0원을 지어냈다
- 처음엔 「옛 표에서도 행은 만들어지게」 빈 칸을 0·'' 으로 채우는 폴백을 넣었다.
- **그게 더 나빴다**: 제주·도서산간 배송비에 0 이 들어가면 「무료로 정함」이 돼서
  그대로 마켓에 나가고 차액은 우리가 문다. 실제로 검증 계정에 `제주=0` 이 박혔다.
- **고침**: 폴백을 없앴다. 행이 없으면 전 칸이 「안 정함」 — 그게 **사실**이다.

### 3. 🔴 표를 고치다 자료를 잃을 뻔했다
- 첫 시도는 「원본 이름 바꾸기 → 새 표 짓기 → 옮기기」 순서였다.
  새 표 짓기가 실패했고(모델의 `__table__.create()` 는 다른 메타데이터에 있는
  `upload_accounts` 를 못 찾는다) 원본이 `__old` 로 뜬 채 남아 **화면에서 자료가 사라졌다**.
- **고침**: 순서를 뒤집었다 — **새 표를 먼저 짓고 마지막에 원본을 지운다**.
  중간에 실패해도 원본이 남는다. 표 정의는 모델이 아니라 **지금 표의 CREATE 문**에서 가져온다.

- **고침**: 이름을 붙이고, 「마켓 전용 칸이 늘면 이름도 같이 는다」를 시험으로 잠갔다.
