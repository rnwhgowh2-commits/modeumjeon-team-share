## 0. 사장님 결정 사항 (2026-07-22 브레인스토밍 확정)

| # | 질문 | 결정 |
|---|---|---|
| 1 | 마켓별 카테고리 "제한항목"의 뜻 | **브랜드·지재권 제한** (특정 브랜드를 특정 마켓×카테고리에 올리면 신고 위험) |
| 2 | 제한 걸리면 시스템 동작 | **해당 마켓만 자동 제외**, 나머지는 등록 진행. 화면에 사유 표시 |

| 5 | 설계 범위 | **전체 통합 설계**(①URL→드래프트 ②카테고리 맵핑 ③필수값 검증기 ④멀티마켓 동시등록) 후 Phase 구현. **소싱처별·판매처별 카테고리 전수조사 필수, 판매처 조사는 우리가 쓰는 공식 API 로만** |
| 6 | 맵핑 확정 방식 | **하이브리드**: 자동 제안을 미리 생성하되, 실제 등록에 쓰이는 순간 사장님이 확정 → 학습되어 다음부터 자동 |

## 1. 목적

소싱처 임의 상품 URL 을 넣으면 → 가공 규칙에 따라 → 사장님이 고른 마켓들(6대: 스마트스토어·쿠팡·롯데온·11번가·옥션·G마켓)에 자동 등록한다(더망고 동작 방식). 더망고가 되는 이유 그대로:

1. 크롤값(이름·가격·옵션·이미지)으로 채울 수 있는 건 채우고
2. 나머지 필수값은 계정·카테고리별 기본값 템플릿(= 우리 가공규칙 13항목)으로 자동 보충하고
3. **못 채운 건 사유를 정직하게 보여준다** (조용한 실패 금지).

이번 스펙의 핵심 신규 축 = **카테고리 맵핑**: 소싱처의 `스니커즈>운동화>여성운동화` 를 마켓마다 있는/없는 카테고리 사정에 맞춰 유사한 곳으로 분류하고, 브랜드·지재권 제한에 걸리는 마켓은 자동 제외한다.

## 2. 전체 흐름

```
URL 입력(대량등록 ①데이터수집 탭)
  → 로컬 크롤(크롬 확장 — 옵션·가격·재고 + ★빵부스러기 카테고리 경로)
  → ProductDraft 자동채움 (크롤값 + 가공규칙 13항목 보충)
  → 카테고리 자동결정 (CategoryMap: 확정=자동 / 제안=확정 게이트 / 없음=검색)
  → 브랜드·지재권 제한표 필터 (걸린 마켓 자동 제외 + 사유)
  → 마켓별 필수값 검증기 (마켓×필수값 표 — "쿠팡은 고시정보 소재가 비어서 못 올림")
  → 멀티마켓 등록 오케스트레이션 (체크박스 → 계정 → 검증 통과분만)
  → 건별 결과표 (성공=마켓 상품ID / 실패=마켓 응답 원문 사유)
```

크롤=로컬 PC(크롬 확장) 원칙 준수. 서버 크롤 부활 금지.

## 3. 현재 코드 현실 (2026-07-22 전수 조사)

### 이미 있는 것 (재구현 금지)
- **드래프트 그릇**: `ProductDraft` / `ProductDraftMarket` (`lemouton/registration/models.py`) — `ProductDraftMarket.category_code` 컬럼 이미 존재
- **6마켓 컴파일러+등록**: `compile_smartstore.py` · `compile_coupang.py` · `compile_more.py`(옥션·G마켓·11번가·롯데온) + `service.py::register_draft`(예비 컴파일→게이트→호출, 성공=마켓상품ID 수신 시만) + `send_more.py`
- **가공규칙 13항목**: `process_policy.py`(ITEM_KEYS 13종) + `process_rule_schema.py` + `/bulk` ②데이터가공 탭. **#2 category 항목에 `auto_map`·`on_fail(hold/default)` 설정칸이 이미 있으나 엔진 미배선**
- **경계 방어 공용부**: `compile_common.py` — `CompileError`·`loads_json`·`coerce_int`·`require_category`
- **카테고리 검색 일부 배선**: `drafts.py::category_search`(`GET /bulk/api/category-search`) — 11번가 전체 트리 조회, 롯데온 본보기 상품 검색
- **실등록 게이트**: `LIVE_REGISTER_ARMED` 2중잠금, 4대마켓 실등록→판매중지 왕복검증 완료(2026-07-21)

### 없는 것 (이번 작업 범위)
- 소싱처 크롤의 카테고리(빵부스러기) 수집 — **전무** (확장 `background.js` 추출기는 color/size/price/stock 만)
- 소싱처 카테고리 사전(`source_categories`) · 마켓 카테고리 사전(`market_categories`) · 맵핑표(`CategoryMap` — 모체 스펙 §6에 이름만 존재)
- 브랜드·지재권 제한표
- URL 입력→크롤→드래프트 자동채움 파이프라인 (현재 드래프트는 수기 입력만)
- 마켓별 필수값 사전 검증 표 (현재는 등록 시도해야 CompileError 로 앎)
- 멀티마켓 동시 등록 (현재는 마켓 1개씩 prompt 로)

### 카테고리 입력의 현재 모습 (대체 대상)
`bulk_manual.js` — 마켓 고르고 카테고리 코드를 **prompt 로 수기 입력**(스스 leafCategoryId / 쿠팡 displayCategoryCode / ESM `ESM코드/사이트코드` / 11번가 dispCtgrNo / 롯데온 본보기 spdNo).

## 4. 구성요소 설계

### A. 판매처 카테고리 전수 수집기 (6마켓 · 전부 공식 API)

| 마켓 | 수집 API | 지도(marketplace_api_map.json) | 코드 배선 |
|---|---|---|---|
| 쿠팡 | `GET display-category-codes` 전체 트리 + **카테고리 추천 API**(category-recommendation) | 있음 | 없음 |
| 스마트스토어 | 커머스API 카테고리 전체 조회(`GET /v1/categories` 평면 리스트, `wholeCategoryName`=경로·`last`=리프) | 있음(`smartstore.get-category-list-product` — 2026-07-22 재확인으로 정정) | 없음 |
| 롯데온 | 표준카테고리 조회(`lotteon.category.standard.list`) | 있음 | 없음 |
| 11번가 | 전체 카테고리 조회(`/rest/cateservice/category`) | 있음 | **있음**(category_search) |
| 옥션·G마켓(ESM) | `GET /item/v1/categories/site-cats/{code}` · `/sd-cats/{code}` | 있음 | 없음 |

- **테이블 `market_categories`**: `market` · `account_key`(조회 계정) · `code` · `name` · `full_path`(구분자 `>` 통일) · `parent_code` · `depth` · `is_leaf` · `raw_json` · `harvested_at`
- **재수집**: 설정 탭에 「카테고리 재수집」 버튼(마켓별). 재수집 시 **추가/삭제 diff 표시**. 삭제된 코드를 참조하던 CategoryMap 행은 상태를 `re_confirm`(재확정 필요)으로 강등 — 낡은 코드로 몰래 등록하지 않는다.
- 마켓 API 작업이므로 구현 착수 전 **consult-market-map 스킬 전수정독 게이트** 통과 필수. 함정(11번가 트리 대용량·ESM site/sd 이원 코드 등)은 지도 idTraps 에 되채움.

### B. 소싱처 카테고리 전수 수집 (2경로 병행)

**경로 1 — 상품 크롤 시 빵부스러기 수집(주력)**
- 크롬 확장 `background.js` 추출기에 소싱처별 breadcrumb 추출 추가(무신사·SSF·SSG·롯데온·르무통·스스르무통 등 소싱처별 셀렉터/API 필드).
- 크롤 결과에 `category_path`(예: `스니커즈>운동화>여성운동화`) 포함 → ProductDraft 에 저장 + `source_categories` 사전에 자동 upsert(처음 보는 경로면 신규 행).
- `docs/sources/*/selectors.yaml` 에 breadcrumb 셀렉터 명세 추가(add-source 절차·에러 이력 축적 준수).

**경로 2 — 소싱처 카테고리 트리 전수조사(보강)**
- 소싱처마다 카테고리 목록(GNB/카테고리 API)을 통째로 수집해 `source_categories` 를 미리 채운다 → 자동 제안(§C)을 상품 크롤 전에 대량 생성 가능.
- 소싱처별 방식이 전부 달라 **add-source 스킬 절차로 한 소싱처씩** 진행(무신사부터). 수집 불가 소싱처는 경로 1만으로 축적(빈 트리를 추정으로 채우지 않는다).

- **테이블 `source_categories`**: `source_id` · `path`(전체 경로) · `leaf_name` · `depth` · `first_seen_at` · `last_seen_at` · `product_count`(이 경로로 크롤된 상품 수)

### C. 카테고리 맵핑표 — CategoryMap (하이브리드)

**테이블 `category_map`**: `source_id` · `source_path` × `market` → `market_cat_code` · `market_cat_path`(표시용) · **`status`**(`suggested` 제안 / `confirmed` 확정 / `re_confirm` 재확정필요) · `method`(**`observed`**=등록 실적 회수 / `coupang_reco` / `name_sim` / `manual`) · `confidence`(0~1, 제안 근거 점수) · `confirmed_at`

> **`observed` (2026-07-23 추가 — 사장님 제안)**: 이미 마켓에 등록한 상품에서 **그때 고른 카테고리 코드를 API 로 되받아** 만든 제안(`confidence` 0.99). 추측이 아니라 실제 선택이므로 유사도·추천보다 신뢰도가 높다. 소싱처 경로(M3 크롤)와 마켓 상품ID 가 **둘 다 있어야** 1건이 생기고, 회수한 코드가 `market_categories` 에 현존할 때만 채택한다(확정 게이트가 거부할 제안을 만들지 않는다). 자동 확정은 여전히 금지 — `status='suggested'` 로만 들어간다.

**자동 제안 생성 (배치)**
1. **앵커 = 쿠팡 카테고리 추천 API**: 그 소싱처 경로로 크롤된 대표 상품의 상품명·브랜드를 넣어 `predictedCategoryId` 획득(SUCCESS 만 채택, INSUFFICIENT_INFORMATION/FAILURE 는 제안 생성 안 함 — 추측 금지).
2. **나머지 5마켓 = 이름 유사도 검색**: `market_categories.full_path` 대상, 소싱처 리프명(여성운동화) → 정확일치 > 부분일치(운동화) > 상위어 후보 순. 쿠팡 앵커의 경로명도 검색어에 가세.
3. "여성운동화가 없는 마켓"은 유사 리프(운동화·스니커즈)를 **제안**으로 올린다 — 확정은 항상 사장님.
4. 제안 후보는 마켓당 상위 3개까지 저장(1등이 제안값, 2·3등은 확정 게이트에서 대안으로 표시).

**등록 순간의 판정 (드래프트 × 마켓)**
| CategoryMap 상태 | 동작 |
|---|---|
| `confirmed` | 그대로 자동 사용 (개입 없음) |
| `suggested` | **확정 게이트**: 후보 3개+경로 표시 → 클릭 확정 → `confirmed` 승격(학습). 이후 같은 소싱처 경로는 자동 |
| 없음 / `re_confirm` | 카테고리 검색 UI(A 의 사전에서 이름 검색) → 선택 → `confirmed` 저장 |

- **확정 없이 등록하지 않는다.** 모체 스펙 §6 「실패=보류 후 학습」 원칙 그대로. 기본 카테고리 폴백 금지.
- 롯데온 특례: 현 등록 경로가 카테고리 코드가 아닌 **본보기 상품(spdNo)** 방식 → CategoryMap 의 롯데온 열은 `market_cat_code` 자리에 본보기 spdNo 를 저장하고 화면에 「본보기: LO…」로 구분 표시. (표준카테고리 조회는 검색·표시용으로 수집)

### D. 브랜드·지재권 제한표 — BrandRestriction

**테이블 `brand_restrictions`**: `brand`(표기 변형 대응 위해 정규화 비교) · `market`(6종 또는 `*` 전마켓) · `category_prefix`(선택 — 비우면 그 마켓 전체, 채우면 그 카테고리 경로 이하만) · `reason`(자유 텍스트) · `active` · `created_at`

- **관리**: `/bulk` ⑧설정 탭에 「브랜드 제한」 카드 — 사장님이 직접 추가·수정·삭제(추가 시 브랜드 자동완성 = 기존 드래프트·크롤 브랜드 목록).
- **적용 지점**: 등록 오케스트레이션(§F)의 마켓 선택 단계. 걸린 마켓은 **체크박스 잠금 + `⚠️ 쿠팡 제외 — 브랜드X 지재권(사유)` 표시**, 나머지 마켓은 정상 진행. 결과표에도 `blocked` 행으로 남긴다(기존 `ProductDraftMarket.status='blocked'` 재사용).
- 모체 스펙 §7-3 「이미지 제외 브랜드」(BrandPolicy)와는 별개 축 — 그쪽은 이미지만 빼고 등록, 이쪽은 마켓 자체를 제외.

### E. 마켓별 필수값 검증기 (preflight)

- **API `POST /bulk/api/drafts/<id>/preflight`**: 선택 마켓들에 대해 **마켓 호출 없이** 기존 컴파일러를 예비 실행 → 마켓×문제 표 반환.
  - 재사용: `service.py::register_draft` 의 1단계(예비 컴파일)를 분리 호출. `CompileError` 메시지를 사람이 읽는 문장으로("옥션: 재고 0 불가", "스스: A/S 전화 비었음").
  - 검증 항목: 카테고리 확정 여부(§C) · 제한표(§D) · 컴파일 필수값 · 마켓별 함정(ESM price/stock required·0 불가, 롯데온 spdLst, 11번가 euc-kr 등 — 이미 컴파일러에 있음).
- **화면**: 등록 버튼 위 「사전 점검」 표 — 마켓별 ✅올릴 수 있음 / ⚠️보충 필요(항목 나열) / ⛔제외(제한표). 가공규칙 기본값으로 보충된 항목은 "세트 기본값 채움" 배지로 구분(뭘 자동으로 채웠는지 정직하게).

### F. 멀티마켓 동시 등록 오케스트레이션

- **화면**: prompt 방식 폐기 → 마켓 체크박스(제한 마켓 잠금) + 마켓별 계정 선택(기존 Phase 2 계정선택 재사용, 없는 계정 거부) + 사전 점검 표(§E) + 등록 버튼.
- **실행**: 검증 통과 마켓만. **마켓 간 병렬, 같은 마켓·계정 안에서는 순차**(기존 upload_accounts 속도정책 준수). 부분 실패 허용 — 성공 마켓은 성공으로 기록.
- **결과표**: 건별(마켓×계정) 성공=마켓 상품ID / 실패=**마켓 4xx 응답 본문 원문**(버리지 않는다) / blocked=제한 사유. `ProductDraftMarket.raw_json` 재사용.
- **게이트**: `LIVE_REGISTER_ARMED` 2중잠금 유지. 배선 완료 후 첫 실등록은 **1건 왕복검증**(등록→실물 확인→판매중지)부터.
- ESM 함정 승계: 등록 직후 2~3분 수정 API 불가 → 결과표에 "옥션·G마켓은 등록 2~3분 후 수정 가능" 안내. 옵션 PUT 실패 시 자동 판매중지 회수(기존 로직 유지).

### G. URL → 드래프트 자동채움 파이프라인

- **입력**: ①데이터수집 탭에 URL 입력(복수 줄). 동일 소싱처 URL 은 1개만 관리(모체 §7-13 중복 방지).
- **크롤**: 로컬 크롬 확장 경로 재사용(크롤=로컬 원칙). 결과 = 상품명·브랜드·가격·옵션·재고·혜택 + **★category_path(신규)** + 이미지 URL 목록.
  - 이미지·상세·고시정보 크롤 확장은 모체 스펙 Phase 3 공사와 동일 항목 — 이 파이프라인에선 **가져와지는 것만 채우고 못 가져온 항목은 비운 채 preflight 표에 노출**(추정 금지).
- **채움**: `ProductDraft` 생성(`source='crawl'`) — 크롤값 → 가공규칙 13항목 적용(상품명 조합·금지어·가격 계산·옵션 정리) → 마켓별 판매가 산출(기존 마진엔진).
- **금지어 `collect` 분류**: 수집 금지어에 걸리면 드래프트 생성 자체를 막고 사유 표시(모체 §7-1).

## 5. 데이터 정합성·정직성 규칙 (전 구성요소 공통)

1. 카테고리 미확정 = 등록 보류. 기본 카테고리 폴백 금지.
2. 마켓 응답 원문(특히 4xx 본문) 보존 — 사유가 거기 있다.
3. 자동으로 채운 값(세트 기본값·자동 맵핑)은 화면에서 수기값과 구분 표시.
4. 제안(confidence)은 절대 자동 확정하지 않는다 — 확정 주체는 항상 사장님.
5. 마켓 카테고리 개편 감지 시 관련 맵핑 `re_confirm` 강등 + 알림 (조용히 낡은 코드로 등록 금지).
6. 소싱처 트리 수집 불가 시 빈 트리를 추정으로 채우지 않고 경로 1(상품 크롤 축적)만 사용.

## 6. 구현 단계 (Phase)

| 단계 | 내용 | 선행 조건 |
|---|---|---|
| **M1** | 판매처 6마켓 카테고리 전수 수집기 + `market_categories` + 재수집 diff + 카테고리 검색·선택 UI(prompt 대체) | consult-market-map 게이트 (스스 카테고리 API 는 지도에 있음 — 2026-07-22 정정. 실측 확정 항목은 M1 플랜 Task 12) |
| **M2** | `CategoryMap` + 자동 제안 엔진(쿠팡추천 앵커 + 이름 유사도) + 확정 게이트 UI + **브랜드 제한표(테이블+설정 카드+적용)** | M1 (마켓 사전 필요) |
| **M3** | 크롬 확장 빵부스러기 수집(소싱처별) + `source_categories` + URL→드래프트 자동채움 파이프라인 | 확장 배포 경로 확인([[reference_loaded_extension_path]] — 로드된 확장=데스크톱 사본) |
| **M4** | preflight 검증기 API+표 + 멀티마켓 체크박스 등록 + 건별 결과표 | M2 (카테고리·제한 판정 필요) |

- 각 Phase = TDD(RED→GREEN→REFACTOR), 구현은 **origin/main 기준 새 워크트리**에서(_wt_reg 는 다른 세션 진행 중 — 같은 브랜치 동시 커밋 금지).
- pytest 는 인자 없이 실행 금지(라이브 접속 테스트 존재).
- M1·M2 는 크롤 공사 없음. M3 이 확장 공사 본체.

## 7. 테스트 계획 (요지)

- **수집기**: 마켓별 응답 fixture → 트리 파싱·full_path 조립·leaf 판정 골든 테스트. 재수집 diff(추가/삭제/재확정 강등) 케이스.
- **제안 엔진**: 유사도 순위 골든 케이스(정확일치>부분일치>상위어), 쿠팡 추천 FAILURE 시 제안 미생성.
- **제한표**: 브랜드 정규화 비교(대소문자·공백), category_prefix 경계, `*` 전마켓.
- **preflight**: 마켓별 CompileError → 사람 문장 변환, 카테고리 미확정·blocked 판정.
- **오케스트레이션**: 부분 실패 시 성공분 보존, 4xx 본문 보존, blocked 행 기록. 실전송은 게이트 뒤 1건 왕복검증.
