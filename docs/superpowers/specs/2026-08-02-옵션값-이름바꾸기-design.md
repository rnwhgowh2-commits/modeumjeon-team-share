# 옵션 값 이름 바꾸기 · 매트릭스 밖 옵션(유령) 관리 — 설계서

- 날짜: 2026-08-02
- 갈래: `feature/option-value-rename`
- 확정: 사장님 — 「1안(근본) + 2안(뒤처리) 둘 다」

---

## 1. 무엇이 문제였나

옵션의 신원은 **(모음전 코드 + 축 값 조합)** 으로 잡는다
(`lemouton/sourcing/option_service.py` — `existing_axes`).

그래서 축 값 글자를 고치면(`색상1` → `블랙`) 프로그램 눈에는 **처음 보는 조합**이다.

1. 새 옵션 행이 생기고 **새 옵션번호**(`U…-NN`)가 나간다
2. 옛 `색상1` 옵션들은 매트릭스 밖으로 밀려나 `else` 가지 —
   「추적 불가, 보호(건드리지 않음)」 로 **그대로 남는다**
3. 남은 옵션은 `is_active` 가 **켜진 채**다. 판매 게이트는 `is_active` 와
   `crawl_blocked` 만 보므로(`lemouton/uploader/preview.py:162`),
   **`색상1 260` 이라는 옵션명이 마켓에 올라갈 수 있는 상태**였다

실측(사장님 화면): 설계는 4색 × 6사이즈 = **24개**인데 옵션은 **42개** →
`색상1/2/3` × 6사이즈 = **18개 유령**.

> 🔴 옵션번호 낭비는 곁가지다. **본체는 유령이 판매 켜짐으로 살아 있는 것**이다.

## 2. 무엇을 만드나

> 🔴 **[2026-08-02 사장님 재확정 — 화면에 새로 만드는 것은 없다]**
> 「정정하게 되면 기존 것은 없던 것처럼 사라지고 신규만 생성되는 건데 뭐 이리 복잡해」
> → 확인창·유령 목록·정리 버튼 **전부 폐기**. 시안 v1 폐기.
> 프로그램이 알아서 하고, **치운 게 있을 때만 저장 알림 한 줄**로 알린다.

### ① 이름 바꾸기를 「바꾸기」로 인식 (근본) — 묻지 않는다

- 모달이 열릴 때 서버에서 받은 축 값 목록을 **기준선**(`state._srvAxes`)으로 잡는다
- 저장할 때 축마다 **값 개수가 같고 자리만 글자가 바뀐 것**을 짝으로 만들어 `renames` 로 보낸다
- 서버는 **기존 Option 행의 축 값만 갈아끼운다** —
  `canonical_sku`·`display_no`·소싱처 URL 매핑·재고·주문 이력이 **그대로 따라온다**
- 결과적으로 옵션은 새로 안 생기고 옛 옵션도 안 남는다 = 사장님이 기대한 그 모습

**언제 짝을 안 짓나 (확실할 때만 짓는다)**
값 개수가 달라지면(추가·삭제가 섞이면) 자리가 밀려 엉뚱하게 짝지어진다.
그 결과는 URL·재고 오배치 = 돈이 틀리는 것이므로 **아무것도 짝짓지 않고** ②로 보낸다.
자리만 맞바꾼 경우(A↔B)도 이름 바꾸기가 아니므로 건드리지 않는다.

### ② 매트릭스 밖이 된 옵션 = 없던 것처럼 치운다 (뒤처리)

- **이번 저장으로 밖이 된 옵션만** 대상. 판정 기준은 **직전 단계 설계에는 있었고
  새 설계에는 없는** 조합 — `save_step_design()` 이 옛 설계를 지우기 **전에** 읽어야 한다
- 걸린 데가 없으면 **행을 지운다**(사장님 확정 — 없던 것처럼)
- 🔴 소싱처 URL 매핑·재고·주문 등 **기록이 걸린 옵션은 지우지 않고 판매만 끈다.**
  지우면 그 옵션이 팔렸던 지난 주문·정산을 되짚을 수 없다
- 치운 개수는 저장 알림에 한 줄로 표시한다 — **말없이 지우지 않는다**

> 🔴 **이미 밖에 있던 옛 옵션은 이 길로 치우지 않는다.**
> 단계 설계가 생기기 전부터 있던 것이 섞여 있고, 그게 지금 팔리는 중일 수 있다.
> 한 번의 저장이 팔리던 상품을 조용히 내리면 그게 더 큰 사고다. → ③

### ③ 이미 쌓인 유령 — 화면 없이 창구(API)로 한 번에 치운다

- `GET  /api/bundles/<code>/options/orphans` — 매트릭스 밖 옵션 목록
  (옵션번호·옵션명·판매 여부·URL 매핑 걸림·재고 이력 걸림)
- `POST /api/bundles/<code>/options/orphans/resolve` — `{skus, action}`
  - `off` — 판매만 끈다 (되돌릴 수 있다)
  - `delete` — **걸린 데가 없는 옵션만** 실제로 지운다.
    URL 매핑·재고 이력이 걸린 옵션은 지우지 않고 `off` 로 처리하고 그 사실을 돌려준다
- **화면(버튼·목록)은 만들지 않는다.** 지금 라이브에 쌓인 것을 한 번 치우는 용도이고,
  ① 이 들어간 뒤로는 새로 생기지 않는다. 필요하면 이 창구로 처리한다

### ④ 옵션번호 규칙은 안 바꾼다

지운 번호를 다시 쓰면 옛 주문·정산이 딴 상품을 가리킨다
(`lemouton/matrix/option_no.py` 에 이미 그렇게 적혀 있다).
번호가 띄엄띄엄한 것은 **정상**이다.

## 3. 손댈 곳

| 파일 | 무엇 |
|---|---|
| `lemouton/sourcing/option_service.py` | `renames` 인자 · 옛 설계 읽기 · 새 유령 자동 끄기 |
| `lemouton/sourcing/option_orphans.py` (신규) | 유령 판정 · 목록 · 정리 (판정 규칙 단일 원천) |
| `webapp/routes/api.py` | `renames` 통과 · 유령 조회/정리 창구 2개 |
| `webapp/static/option_url_modal.js` | 기준선 기억 · 저장 시 짝 자동 계산·전송 · 인메모리 키 재매핑 · 저장 알림 한 줄 |

**새 화면 부품 0개** — 버튼·창·목록을 하나도 만들지 않는다.

**DB 칸 추가 없음** — 유령 여부는 「지금 축 값이 매트릭스 안에 있나」로 그때그때 판정한다.
칸을 만들면 두 곳이 갈린다. 사장님이 직접 끈 옵션(매트릭스 안 + 꺼짐)과
유령(매트릭스 밖)은 이 판정으로 구분된다.

## 4. 다 됐다고 말할 수 있는 조건

1. `색상1/2/3` → `블랙/화이트/다크네이비` 로 고치고 저장 → **새 옵션번호 0개**,
   URL 매핑 개수 그대로, **묻는 창 없음**
2. 축에서 값을 진짜 하나 지우고 저장 → 그 조합 옵션이 **목록에서 사라진다**
   (기록이 걸린 것만 판매 꺼짐으로 남고, 저장 알림에 그 사실이 한 줄 뜬다)
3. 창구로 지금 쌓인 것 정리 → 라이브에서 이 상품 옵션 42 → 24
4. 라이브(`https://mou-m.com`) 실화면에서 1·3 을 눈으로 확인
