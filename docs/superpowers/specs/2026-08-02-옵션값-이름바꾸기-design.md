# 옵션 값 이름 바꾸기 · 매트릭스 밖 옵션(유령) 관리 — 설계서

- 날짜: 2026-08-02
- 갈래: `feature/option-value-rename`
- 확정: 사장님 — 「1안(근본) + 2안(뒤처리) 둘 다」

---

## 1. 무엇이 문제였나

옵션의 신원은 **(모음전 코드 + 축 값 조합)** 으로 잡는다
(`lemouton/sourcing/option_service.py` — `existing_axes`).

그래서 축 값 글자를 고치면(`색상1` → `블랙`) 프로그램 눈에는 **처음 보는 조합**이다.

1. 새 옵션 행이 생기고 **새 옵션번호**(`U…-NN`)가 나간다
2. 옛 `색상1` 옵션들은 매트릭스 밖으로 밀려나 `else` 가지 —
   「추적 불가, 보호(건드리지 않음)」 로 **그대로 남는다**
3. 남은 옵션은 `is_active` 가 **켜진 채**다. 판매 게이트는 `is_active` 와
   `crawl_blocked` 만 보므로(`lemouton/uploader/preview.py:162`),
   **`색상1 260` 이라는 옵션명이 마켓에 올라갈 수 있는 상태**였다

실측(사장님 화면): 설계는 4색 × 6사이즈 = **24개**인데 옵션은 **42개** →
`색상1/2/3` × 6사이즈 = **18개 유령**.

> 🔴 옵션번호 낭비는 곁가지다. **본체는 유령이 판매 켜짐으로 살아 있는 것**이다.

## 2. 무엇을 만드나

### ① 이름 바꾸기를 「바꾸기」로 인식 (근본)

- 모달이 열릴 때 서버에서 받은 축 값 목록을 **기준 스냅샷**으로 잡는다
- 저장 직전, 축마다 `사라진 값` / `새로 생긴 값` 을 센다.
  둘 다 있으면 **짝짓기 확인창**을 한 번 띄운다 (자리 순서로 자동 추천, 사장님이 풀 수 있음)
- 확인된 짝은 `renames` 로 서버에 보낸다 →
  **기존 Option 행의 축 값만 갈아끼운다.**
  `canonical_sku`·`display_no`·소싱처 URL 매핑·재고·주문 이력이 **그대로 따라온다**
- 짝을 안 지은 값은 지금처럼 「없어진 조합」 → ②로 넘어간다

**왜 자동 판단하지 않나** — 이름 바꾸기와 값 추가를 한 번에 하면 기계가 틀리게 짝짓는다.
그 결과는 URL·재고 오배치이고, 이 프로젝트에서 그건 곧 돈이 틀리는 것이다.
확인 클릭 한 번이 훨씬 싸다.

### ② 매트릭스 밖 옵션 = 판매 끄고 접기 (뒤처리)

- **이번 저장으로 밖이 된 옵션만** 자동으로 `is_active=False`
- 판정 기준: **직전 단계 설계(BundleOptionStep)에는 있었고 새 설계에는 없는** 조합.
  `save_step_design()` 이 옛 설계를 지우기 **전에** 읽어야 한다
- 화면에서는 `매트릭스에 없음` 배지 + 기본 접힘, 펼쳐서 되돌릴 수 있다

> 🔴 **이미 밖에 있던 옵션은 자동으로 끄지 않는다.**
> 단계 설계가 생기기 전부터 있던 옛 옵션이 섞여 있고, 그게 지금 팔리는 중일 수 있다.
> 한 번의 저장이 팔리던 상품을 조용히 내리면 그게 더 큰 사고다. → ③ 으로 보낸다

### ③ 이미 생긴 유령 — 목록으로 보여주고 사장님이 고른다

- `GET  /api/bundles/<code>/options/orphans` — 매트릭스 밖 옵션 목록
  (옵션번호·옵션명·판매 여부·URL 매핑 걸림·재고 이력 걸림)
- `POST /api/bundles/<code>/options/orphans/resolve` — `{skus, action}`
  - `off` — 판매만 끈다 (되돌릴 수 있다)
  - `delete` — **걸린 데가 없는 옵션만** 실제로 지운다.
    URL 매핑·재고 이력이 걸린 옵션은 지우지 않고 `off` 로 처리하고 그 사실을 돌려준다
- 화면은 전체 선택을 기본값으로 두어 클릭 한 번에 끝나게 한다

### ④ 옵션번호 규칙은 안 바꾼다

지운 번호를 다시 쓰면 옛 주문·정산이 딴 상품을 가리킨다
(`lemouton/matrix/option_no.py` 에 이미 그렇게 적혀 있다).
번호가 띄엄띄엄한 것은 **정상**이다.

## 3. 손댈 곳

| 파일 | 무엇 |
|---|---|
| `lemouton/sourcing/option_service.py` | `renames` 인자 · 옛 설계 읽기 · 새 유령 자동 끄기 |
| `lemouton/sourcing/option_orphans.py` (신규) | 유령 판정 · 목록 · 정리 (판정 규칙 단일 원천) |
| `webapp/routes/api.py` | `renames` 통과 · 유령 조회/정리 창구 2개 |
| `webapp/static/option_url_modal.js` | 기준 스냅샷 · 짝짓기 확인창 · 인메모리 키 재매핑 · 유령 접힘 구역 |

**DB 칸 추가 없음** — 유령 여부는 「지금 축 값이 매트릭스 안에 있나」로 그때그때 판정한다.
칸을 만들면 두 곳이 갈린다. 사장님이 직접 끈 옵션(매트릭스 안 + 꺼짐)과
유령(매트릭스 밖)은 이 판정으로 구분된다.

## 4. 다 됐다고 말할 수 있는 조건

1. `색상1/2/3` → `블랙/화이트/다크네이비` 로 고치고 저장 → **새 옵션번호 0개**,
   URL 매핑 개수 그대로
2. 축에서 값을 진짜 하나 지우고 저장 → 그 조합 옵션이 **판매 꺼짐**으로 바뀐다
3. 유령 목록에서 「판매 끄기」 → 라이브에서 이 상품 활성 옵션 42 → 24
4. URL 매핑이 걸린 유령에 「삭제」 → 지워지지 않고 꺼짐으로 처리되며 그 사실이 화면에 뜬다
5. 라이브(`https://mou-m.com`) 실화면에서 1·3 을 눈으로 확인

## 5. 안 하는 것 (YAGNI)

- 옵션번호 재사용·번호 다시 매기기
- 유령 자동 일괄 삭제 (사장님 확인 없는 삭제는 안 한다)
- 매트릭스 밖 옵션을 위한 새 DB 칸
