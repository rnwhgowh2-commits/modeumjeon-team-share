# 판매처 연동 — 현재값 수집 · 변동이력 · 알림 + 카드 재디자인 (설계)

> 작성: 2026-06-29 / 상태: 설계완료·미구현
> 상위: docs/크롤링-가이드.md, project_marketplace_integration_kickoff (메모리)
> 참고 동작 목업: 바탕화면/모음전 판매처연동 재디자인 시안 v1.html, scratchpad/alert_placements.html

## 0. 배경 / 목적
판매처 연동 대시보드 = 모음전 1개당 카드 1개, 여러 마켓의 매칭·재고·가격·전송 현황 표시.
현재는 소싱처 값만 있고 판매처 현재값/변동이력/알림이 없다. 본 설계:
1. 판매처 현재값(재고·가격·API일자) 주기 수집·저장
2. 소싱/판매 출처별 값 변동 이력 누적
3. 조치 필요 상태를 알림으로 표면화
4. 마켓이 늘어도 안 깨지는 M3 표 + F10 필터 + H2 이력패널 재디자인

## 1. 제약 (확정)
- 마켓 웹훅 없음 → pull(당겨오기)만 가능
- 쿠팡: 현재 재고 조회 API 없음 → mkt_stock=null("미상"), 가격만 조회
- 스마트스토어: 옵션별 stockQuantity·price·usable 조회 가능
- 쿠팡 단일 IP 제약 → 판매처 API 호출은 서버(AWS)에서 실행
- 폴백가 금지(실패는 표면화), 중복·모순 금지

## 2. 데이터 모델
### 2.1 SetChannelOption 확장
- mkt_stock: int|null (판매처 현재 재고, 쿠팡 null)
- mkt_price: int|null (판매처 현재 판매가)
- mkt_fetched_at: datetime|null (판매처 API 마지막 조회 일자)
- (소싱 재고·가격·크롤일자는 기존 매트릭스/Option 경로 유지)
### 2.2 ChannelChangeEvent (신규 테이블)
- id, set_id, market, canonical_sku
- field: stock | price
- source: source(소싱 크롤) | market(판매처 API)
- prev_value: int|null, next_value: int|null, at: datetime
- 규칙: 값이 실제로 바뀔 때만 1행 append (동일값 재조회는 미기록)
- 인덱스: (set_id, market, canonical_sku, field, at desc)
- 보존: 초기 전량 누적, 추후 기간/개수 캡 검토(Supabase 500MB)

## 3. 수집 (자동 주기 + 수동)
### 3.1 트리거
- 정기: 하루 1~2회(새벽 + 크롤 종료 후) — 스케줄러
- 크롤 연동: 소싱 크롤 완료 직후 판매처도 조회(소싱↔판매 한 묶음 대조)
- 수동: 카드/마켓 현재값 새로고침 버튼
### 3.2 흐름 (서버)
채널별 fetch_market_options(market, market_product_id) →
- 옵션별 현재 mkt_stock/mkt_price 추출(쿠팡 stock=null)
- 기존 SetChannelOption.mkt_* 와 diff
- 바뀐 항목 → ChannelChangeEvent(source=market) append
- mkt_* + mkt_fetched_at 갱신
소싱 변동(크롤 시 Option 재고/가격 바뀜)도 ChannelChangeEvent(source=source) append (크롤 저장 경로 훅)
### 3.3 실패 처리
조회 실패 = 해당 채널 표면화(에러), 옛값 유지·덮어쓰지 않음, 폴백 금지.

## 4. 알림
### 4.1 유형 5종
- 소싱변동→판매갱신 (주의 #B45309): 소싱 최신 재고/가격 != 판매 반영값
- 판매 재고0 (위험 #e03a3e): mkt_stock==0 (스스 기준; 쿠팡 미상 제외)
- 소싱·판매 둘다0 (심각 #b91c1c): 소싱 재고0 AND 판매 재고0
- 마켓 미동기화 (정보 #185FA5): 소싱 크롤일자 > 판매 API일자 (값 다름+판매 더 오래됨)
- 가격 급변 (정보 #7c3aed): 최근 변동률 임계 초과
### 4.2 판정
저장 안 함 — 대시보드 로드/수집 후 현재 데이터로 매번 파생 계산
### 4.3 노출 위치 (확정: 2+4+9)
- 사이드바 하단 고정 조치 N건 패널 (전역 카운트)
- 카드 우상단 배지 (해당 모음전 조치 유무·유형색)
- M3 표 행 끝 경고 아이콘 (어느 마켓인지)
- 추후 텔레그램 확장 여지

## 5. UI 재디자인 (스펙 4종 규칙 준수)
### 5.1 M3 매트릭스 표
- 칼럼 [마켓|매칭|재고(소/판)|가격(소/판)|전송], table-layout:fixed + colgroup 25/13/23/23/16% → 카드 간 세로선 일치
- 마켓 = 브랜드색 로고타일(2글자)+명, 행=마켓1 (마켓 늘면 행만 추가)
- 매칭 = 매칭수/전체 (완료#0F8A4D·부분#B45309·미연동#98A2B3)
- 재고/가격 = 상단 상태 + 소(파랑#185FA5)/판(갈색#854F0B) 2줄 일자(26.06.28 위 / 09:30 아래, tabular-nums)
- 전송 = 전송됨+일자 / 미전송. 미연동행 재고·가격 표시 없음
- 셀 클릭 → H2 이력 패널
- 마켓색: 쿠팡#E03A3E·스마트스토어#03C75A·G마켓#00A862·11번가#FF0038·토스#3182F6·무신사#1a1a1a
### 5.2 F10 필터 (좌 트리 + 우 결과)
- 좌 고정: 브랜드(OR) + 등록 마켓(OR) 체크그룹 / 우 결과 + 결과 N건
- 브랜드 OR(합동전은 어느 쪽 골라도 포함), 마켓 OR, 그룹간 AND, 미선택=전체
### 5.3 H2 변동이력 패널
- 헤더 {상품} {마켓} {재고|가격} 변동 이력, 가로탭 [재고][가격]
- 2열: 좌 소싱 크롤(헤더 파랑#185FA5) / 우 판매 API(헤더 갈색#854F0B), 시간 역순, 한 줄 = 일시 + 이전 이후 + 델타
- 하락=파랑#1d4ed8 down / 상승=빨강#dc2626 up (한국 증시 관례, 일반 웹과 반대)
### 5.4 공통
- 편집/삭제 동일크기(min-width·height·padding 동일), 편집 파란외곽#3182f6·삭제 빨간외곽#e03a3e·흰배경
- Pretendard·토스톤·색 최소·일관

## 6. 빌드 순서 (한 사이클)
1. 모델(2.1·2.2) + Alembic 마이그레이션 Supabase
2. 수집 서비스(3) + 수동 새로고침 라우트 + 스케줄러/크롤훅
3. 알림 판정(4) + 노출(2+4+9)
4. UI(5: M3·F10·H2)
5. 라이브 검증 (origin/main 워크트리 PR 머지)

## 7. 비범위 (YAGNI)
- 실시간 웹훅(마켓 미지원) / 가격 전송(별도, 현재 재고만) / 알림 텔레그램(나중) / 이력 무한보존 최적화(초기 전량 누적)
