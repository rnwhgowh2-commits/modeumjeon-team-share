## 1. 배경

모음전 프로그램(Flask, mou-m.com)을 폰에서 앱처럼 쓰고 싶다는 요청.
"PC에서 하는 것 전부(169개 화면)를 폰에서도" 가 최종 목적지이고, 크롤은 **폰에서 시작 버튼을 누르면
연동된 PC가 실행**하는 방식으로 한다.

### 조사로 확인된 현재 상태 (origin/main `647c8764` 기준)

| 항목 | 실제 |
|---|---|
| 화면(템플릿) | **169개** |
| 서버 라우트 모듈 | **43개** |
| 폰 크기를 고려한 화면 | **12개뿐** (나머지 157개는 PC 전용) |
| `base.html` / `topnav.html` | `@media` 규칙 **0건** — 고정 레이아웃 |
| 모바일 PWA | **이미 존재** — `webapp/routes/mobile.py` + `templates/mobile/` 6개(홈·스캔·연속스캔·상세·재고) |
| 설치 설정 | **이미 존재** — `static/manifest.json` (`display: standalone`, `scope: "/"`, 아이콘 3종), `static/sw.js` |
| 로그인 | `flask_login`, 로그인 화면에 "로그인 유지" 체크박스 존재 |
| 크롤 통로 | **이미 매일 가동** — PC 크롬 확장(v0.7.68)이 `/api/crawl/due-bundles` · `/api/crawl/queue` 를 1~2초 주기 폴링 |
| 크롤 켜기·끄기 | `pricing.settings.crawl_auto_enabled` 존재 |
| 한 바퀴 시작 | `lemouton/sources/crawl_schedule.py::start_new_lap` 존재 |
| PC 연결 여부 | **서버가 모름** — `CrawlWorker.last_heartbeat_at` 컬럼은 있으나 채우는 코드 없음 |

> ⚠️ 이 조사는 반드시 `origin/main` 기준 워크트리에서 해야 한다.
> 주 작업폴더(`feature/crawl-worker-queue`)는 origin/main 대비 2,500커밋 이상 뒤처져 있어
> 코드를 읽는 것만으로도 오보가 난다. (실제로 이번 세션 초반 "화면 135개"로 잘못 셌다 → 169개가 맞음)

## 3. 1단계 범위

### 만드는 것

1. **앱 껍데기** — 하단 탭 4칸 + 상단 뒤로가기/제목, 폰 전용·PC 폴백 화면 모두에 공통 적용
2. **"전체" 메뉴** — PC 메뉴와 같은 원천을 읽어 169개 화면 전부 접근
3. **PC 화면 폴백** — 폰 전용이 아닌 157개 화면을 앱 안에서 여는 방식 + 안내 띠
4. **크롤 리모컨** — 상태 표시 · 자동 크롤 on/off · 지금 한 바퀴 돌리기 · 진행률
5. **설치 안내 화면** — 아이폰/안드로이드 각각
6. **로그인 유지** — 폰에서 90일
7. **오프라인 정책 교정** — 돈 관련 데이터 캐시 금지 (현재 `sw.js` 설정 변경)

### 안 만드는 것 (비범위)

- 홈 요약 대시보드 → **2단계**
- 기존 화면의 폰 전용화(표→카드 등) → **3단계 이후**
- 푸시 알림 · 스토어 앱 → **선택 · 나중**
- "PC 켜지면 자동 시작" 예약 → **제외 확정**
- 크롬 확장(v0.7.68) 수정 → **불필요** (아래 4.4 참조)

## 4. 구성요소 상세

### 4.1 앱 껍데기 (하단 탭)

탭 4칸: **홈 / 작업 / 크롤 / 전체**

| 탭 | 1단계 내용 |
|---|---|
| 홈 | 크롤 상태 요약 한 장 + 스캔·재고 바로가기 + 최근 본 화면 5개(폰에 저장, 서버 저장 안 함). **요약 대시보드는 2단계** |
| 작업 | 기존 `/mobile` 화면들(스캔·연속스캔·입출고·재고) 그대로 연결 |
| 크롤 | 4.4 크롤 리모컨 |
| 전체 | 4.2 메뉴 |

- 어느 화면에 있든(PC 폴백 화면 포함) **탭은 항상 보인다** — 길을 잃지 않게
- 기존 `templates/mobile/_base.html` 에는 헤더·FAB 은 있으나 **하단 탭이 없다** → 여기에 추가
- 탭 구성은 나중에 바꾸기 쉬운 형태로 둔다(3단계에서 주문 탭으로 교체 가능성 있음)

### 4.2 "전체" 메뉴 — 단일 원천 재사용

- **폰 전용 메뉴를 새로 정의하지 않는다.** PC 상단 메뉴가 쓰는 `data/sidebar_layout.json`
  (`webapp/routes/api_sidebar.py`)을 그대로 읽어 폰 목록으로 편다.
- **이유**: 앞으로 화면을 새로 만들 때 PC 메뉴에만 넣고 폰 메뉴엔 빼먹는 사고를 구조적으로 차단.
  이 프로젝트엔 "만든 화면을 메뉴에 안 넣어 두 달간 주소를 직접 쳐야 했던" 실제 기록이 있다.
- 각 항목에 **배지**를 붙인다: `폰 전용` / `PC 화면`. 사장님이 무엇이 이미 편해졌는지 한눈에 안다.
- 맨 아래에 로그아웃.


### 🔴 2026-08-04 정정 — "169개가 메뉴에 다 뜬다"는 틀렸다

Task 4 구현 중 실측으로 확인했다.

| 적어뒀던 것 | 실제 |
|---|---|
| "전체" 메뉴에서 **169개 화면 전부** 접근 | 메뉴가 그리는 줄은 **25개**(standalone 2 + 8묶음 23). 앱 전체 GET 페이지 라우트는 **178개** |

**왜 어긋났나:** 나머지 화면들은 그 25개 **안의 가로탭·버튼**으로 들어가는 구조다
(예: `/orders/?tab=list|ship|cs|margin` 처럼 한 화면 안에 여러 탭). PC 메뉴 자체가 원래
25줄짜리이고, 폰 메뉴는 그 **같은 원천**을 읽으므로 25줄이 나오는 게 정상이다.

**그래서 무엇이 맞나 — 약속은 여전히 지켜진다. 문장만 틀렸다.**
- "169개 화면 전부에 앱 안에서 **도달할 수 있다**" → **맞다.** 설치 범위가 `scope:"/"` 라
  사이트의 어떤 주소든 앱 안에서 열리고(§4.3), 25개 진입점이 나머지로 이어진다.
- "메뉴에 169줄이 뜬다" → **틀렸다.** 25줄이 뜬다.

**따라오는 수정**
- §3·§5 의 "169개" 표현을 "**169개 화면을 25개 진입점으로 편다**"로 읽는다.
- §5 검증 3번("전체에서 169개 항목이 다 나오는지")은 **`sidebar_layout.json` 의 줄 수(25)와
  대조**하는 것으로 바꾼다. 169 를 세면 반드시 실패한다.

### 4.3 PC 화면 폴백

- `manifest.json` 의 `scope` 가 이미 `"/"` 이므로 **사이트 전체가 설치된 앱 안에서 열린다.**
  주소창이 생기지 않는다. 새로 만들 배관 없음.
- 폴백 화면 위에 얹는 것:
  - 상단 **뒤로가기 + 화면 이름** (PC 화면엔 폰용 뒤로가기가 없다)
  - 하단 **탭 유지**
  - **안내 띠 한 줄** — "PC용 화면입니다 · 폰을 옆으로 눕히면 보기 편합니다"
  - 안내 띠는 폰 전용 화면에는 나오지 않는다
- **정직한 한계**: 이 화면들은 여전히 불편하다. 표가 30칸인 것은 그대로다.
  1단계 목표는 "예쁘게"가 아니라 **"막히지 않게"** 다.

### 4.4 크롤 리모컨

**화면은 상태에 따라 3가지**

| 상태 | 표시 | 버튼 |
|---|---|---|
| ① 돌아가는 중 | 🟢 PC 연결됨 · N초 전 응답 / 이번 바퀴 62% · 남은 148건 | ■ 크롤 멈추기 |
| ② 멈춰 있음 | 🟢 PC 연결됨 / 마지막 바퀴 완료 시각 | ▶ 지금 한 바퀴 돌리기 · 자동 크롤 on/off |
| ③ PC 꺼짐 | ⚪ PC 꺼져 있음 · 마지막 응답 3시간 전 + "폰으로 PC를 켤 수는 없습니다" | **버튼 비활성(흐리게)** |

**있는 것 / 만들 것**

| 기능 | 현재 | 할 일 |
|---|---|---|
| PC가 일감 가져가는 통로 | ✅ 가동 중 (`/api/crawl/due-bundles` 폴링) | 없음 |
| 자동 크롤 on/off | ✅ `crawl_auto_enabled` | 폰용 토글 API 1개 |
| 지금 한 바퀴 | ✅ `start_new_lap` | 폰용 POST 1개 |
| 진행률·남은 건수 | △ 바퀴 기록·대기 목록 존재 | 폰용 **요약 조회 API 1개** |
| "PC 연결됨" | ❌ 서버가 모름 | **신규** — 확장이 `/api/crawl/due-bundles` 를 부를 때 `CrawlWorker.last_heartbeat_at` 를 갱신. **확장 수정 불필요**(서버가 기록만 하면 됨) |

**온라인 판정**: `crawl_queue.HEARTBEAT_ONLINE_SEC`(90초) 재사용.

**진행률의 정의**: "이번 바퀴에서 처리한 대상 수 ÷ 이번 바퀴 전체 대상 수".
구현 중 이 값을 정확히 낼 수 없다고 판명되면 **퍼센트를 지어내지 않는다** — 대신
"남은 N건"만 표시하고 퍼센트 막대는 빼며, 사장님께 그 사실을 보고한다.

**⚠️ 못 박아 둘 한계**
- PC 크롬이 꺼져 있으면 폰에서 아무리 눌러도 크롤은 돌지 않는다. **폰으로 PC를 켤 방법은 없다.**
- 그래서 ③에서 버튼을 **비활성**으로 만든다. 눌리는데 아무 일도 안 일어나는 것이 가장 나쁘다.
- 크롤 자체는 로컬 PC 원칙을 유지한다 — 서버는 "할 일"만 알려준다. 서버측 크롤로 되돌리지 않는다.


### 🔴 2026-08-04 정정 — 확장을 1줄 고친다 (사장님 확정 A)

구현 중 실측으로 §4.4 의 전제 2가지가 **틀린 것**으로 드러났다.

| 적어뒀던 것 | 실제 (`extension/moum-crawler/background.js` 실측) |
|---|---|
| 확장이 `due-bundles` 를 **1~2초마다** 폴링 | **1분에 한 번**(`chrome.alarms`, `periodInMinutes: 1`). 1.5초로 도는 건 확장이 아니라 PC **자동화 화면**(`automation/index.html:1161`) |
| `/api/crawl/queue` 도 확장이 폴링 | **화면만** 부른다(`automation/index.html:754`). 여길 신호로 쓰면 확장이 꺼져 있어도 "PC 연결됨"이 된다 |
| 확장 수정 **불필요** | **틀렸다.** 확장의 크롤 폴링 알람은 화면의 실행/정지 버튼이 만든다(`:643`·`:1159`). **크롤이 멈춰 있으면 확장은 서버를 아예 안 부른다** → 폰에서 시작시킬 방법이 없고, 폰엔 "PC 꺼짐"이 뜬다. 폰 리모컨의 존재 이유가 바로 그 순간이므로 치명적 |

**확정(사장님, 2026-08-04): A안 — 확장을 1줄 고친다.**

- `background.js` 모듈 로드 시점에 크롤 폴링 알람을 **항상** 만든다.
  서버의 `crawl_auto_enabled` 게이트가 이미 이중 안전장치라(꺼져 있으면 빈 목록) **동작은 바뀌지 않는다** — 확장 주석에도 그렇게 적혀 있다.
- 확장 버전을 올린다(`manifest.json` + `background.js` 의 `MOUM_EXT_VERSION` — 둘이 어긋난 전례가 있다).
- **사장님이 PC 에서 확장 새로고침 1회** 필요. 이건 배포로 자동 해결되지 않는다.

**따라오는 수정**

- 생존 신호는 **`/api/crawl/due-bundles` 한 곳만** 기록한다(`/api/crawl/queue` 는 화면이라 제외).
- 온라인 판정 창 **90초 → 180초**. 확장 주기가 1분이라 90초는 여유가 30초뿐이고, MV3 알람은 절전 시 지연돼 🟢⚪ 깜빡임이 난다.
- 확장을 새로고침하기 전까지는 크롤이 멈춰 있으면 "PC 꺼져 있음"으로 보인다 — 이는 오표시가 아니라 **아직 확인 못 함**이 맞다(프로젝트 3대 원칙 1번).

### 4.5 설치 안내

- **아이폰**: 사파리로 접속 → 공유 → "홈 화면에 추가". **크롬으로는 안 된다.**
  iOS 는 설치 배너를 자동으로 띄우지 못하므로 **앱 안에 그림이 있는 안내 화면**을 만든다
  (팀원이 늘어도 그 주소만 주면 된다).
- **안드로이드**: 크롬이 설치 배너를 자동으로 띄운다. 설정이 이미 갖춰져 있어
  **이미 되는 상태일 가능성이 크다** → 실제 폰으로 확인만 한다.
- 두 기기 모두 **실제 폰에서 설치까지 해봐야** 완료로 친다(브라우저 개발자도구 시뮬레이션은 증거로 인정하지 않는다).

### 4.6 로그인 유지

- 폰 로그인은 `remember` 를 **항상 켠 상태**로, 유지 기간 **90일**.
- 로그아웃 버튼은 "전체" 맨 아래.
- 폰 분실 시 PC 에서 비밀번호를 바꾸면 세션이 끊긴다.

### 4.7 오프라인 정책 — 돈 관련 캐시 금지 (**A안**)

현재 `static/sw.js` 는 HTML/API 를 `Network First` + **오프라인 시 캐시 폴백**으로 처리한다.
폰은 지하철·엘리베이터·지하 창고에서 수시로 끊기므로, 이대로 두면
**어제 매입가·재고가 티 없이 화면에 뜬다.**

**결정**: 돈 관련 데이터는 캐시로 대신 보여주지 않는다.

| 대상 | 정책 |
|---|---|
| 앱 껍데기 (아이콘 · CSS · 글꼴 · 메뉴 뼈대) | 캐시 O — 앱이 빨리 뜨게 |
| **가격 · 재고 · 주문 · 정산 · 마진** | **캐시 X** — 끊기면 "연결이 안 됩니다 / 다시 시도" 표시 |

- 프로젝트 규칙 1번(**가격·재고 오류 = 금전 손실**)의 직접 적용이다.
- 감수하는 것: 인터넷이 없는 지하 창고에서는 숫자를 볼 수 없다.
- 캐시 버전(`CACHE_VERSION`)을 올려 기존에 깔린 낡은 캐시를 무효화한다.

## 5. 검증 방법

**"화면에서 보이는 것"이 기준이다.** 코드가 맞다는 것으로 완료를 주장하지 않는다.

1. **실제 폰 2대**(아이폰 · 안드로이드)로 `mou-m.com` 접속 → 홈화면에 설치 → 아이콘으로 실행
2. 주소창 없이 뜨는지, 하단 탭이 나오는지, 안전영역(노치·홈바)에 안 가리는지
3. "전체"에서 **169개 항목이 다 나오는지** — `sidebar_layout.json` 항목 수와 대조
4. PC 전용 화면 하나를 열어 → 앱 안에서 열리는지 · 뒤로가기·탭·안내 띠가 나오는지
5. 크롤 리모컨:
   - PC 크롬 켠 상태 → 🟢 연결됨 표시, "한 바퀴 돌리기" 눌러 **실제로 크롤이 시작되는지**
   - PC 크롬 끈 상태 → ⚪ 꺼짐 표시 + **버튼이 비활성인지**
6. 오프라인: 폰 비행기모드 → 가격·재고 화면에서 **낡은 숫자가 아니라 "연결 안 됨"이 뜨는지**
7. 로그인 유지: 앱 껐다 켜도 다시 안 묻는지
