# 재고 정합성 조사 — 「크롤링 검사」 탭 신설 (설계)

> **연관 정본**: [docs/크롤링-가이드.md](../../크롤링-가이드.md) (데이터 흐름·소싱처별 로직 단일 진실 원천)

## 1. 목적 (Why)

재고 정합성 검사는 **에러가 굉장히 많고, 매우 자주** 반복 실행하는 작업이다. 지금까지는 매번
프롬프트를 순차로 손으로 쳐서 Claude Code와 소통해 왔다(르무통 65URL, 롯데온 SOUT 둔갑,
스스 999둔갑 등). 이 반복 노동을 **시스템화**한다 — 웹앱 카드 한 번 클릭 → 완성된 프롬프트
복사 → Claude Code에 붙여넣기 → 5단계 조사가 정해진 프로토콜로 실행되게 한다.

## 2. 산출물 구조 (What)

**핵심 메커니즘 = 프롬프트 복사형 (전체 인라인)**

| 산출물 | 위치 | 역할 |
|---|---|---|
| ① 카드 「크롤링 검사」 | 소싱처 가이드 상단 (4번째 카드, 기존 3개와 동일 스타일) | 진입점 |
| ② 페이지 `/sourcing-guide/crawl-check` | 2탭: **재고 정합성 검사** / 가격 정합성 검사 | 이번 구현 = 재고 탭. 가격 탭은 자리만(placeholder) |
| ③ 재고 탭 본문 | 완성된 **전체 프롬프트**(5단계·OK/NG 기준·유형)를 통째로 인라인 표시 + [복사] 버튼 | 사용자는 대상 소싱처·URL만 확인 후 복사 → Claude Code에 붙여넣기 |

> **결정**: 프로토콜을 별도 스킬 파일로 빼지 않고 웹앱 탭 프롬프트에 **전체 인라인**한다.
> 복사본은 이 탭 하나뿐 — 프로토콜 수정 시 이 템플릿만 고친다.

## 3. 조사 5단계 프로토콜 (프롬프트 본문)

붙여넣은 프롬프트를 받은 Claude Code가 실행하는 순서:

1. **크롤한다** — 대상 소싱처의 매트릭스 등록 URL 전체를 크롤(로컬 크롬 확장/Playwright)해
   최신 재고를 프로그램 DB에 반영한다.
2. **실브라우저 URL 전체 재고 엑셀 조사** — 각 등록 URL을 실브라우저로 직접 열어
   **색 × 사이즈별 실제 재고(상태 + 가능하면 수량)** 를 읽어 엑셀로 정리한다.
   (기준 = 실브라우저 상품 URL. 추정·폴백 금지.)
3. **비교** — 크롤 결과값(= 매트릭스 보기에 저장된 데이터)과 2의 엑셀을 **셀(색×사이즈) 단위로 1:1 대조**한다.
4. **정합성 판정 + 유형 분류** — 각 셀을 아래 기준으로 OK/NG 판정하고, NG는 이중 태그를 단다.
5. **OK/NG별 유형 구분·집계** — 소싱처별로 유형별 개수를 집계하고, 조치 리스트를 귀책별로 분리 출력한다.

## 4. OK/NG 판정 기준 + 유형 (핵심)

**대조 단위 = 색 × 사이즈 셀 1칸.** 실브라우저 재고 vs 프로그램 저장값(매트릭스 보기) 비교.

- **OK** = 재고 상태(있음/품절) 일치. 수량까지 긁는 소싱처는 수량도 일치(±허용오차)해야 OK.
- **NG** = 불일치. **이중 태그**(귀책 + 증상)를 단다.

### 4-1. 귀책 축 (먼저 판정 — 누가 고치나)

진단법: **그 URL을 실브라우저로 직접 열어, 매트릭스의 그 색·사이즈와 실제로 같은 상품인지 확인.**

| 귀책 | 판정 | 조치 주체 |
|---|---|---|
| **U (URL측 문제)** | 등록 URL이 실제 상품과 불일치 — 대체상품·다른상품·404·만료 | **사용자가 URL 정정** |
| **P (프로그램측 문제)** | URL은 그 상품이 맞는데 프로그램 저장 재고값이 틀림 | **Claude가 코드 수정** |

### 4-2. 증상 유형 (귀책과 무관하게 부착)

| 코드 | 이름 | 정의 | 위험 | 대표 사례 |
|---|---|---|---|---|
| **A** | 품절둔갑 | 실=품절, 프로그램=있음 | ★최고 (없는 걸 팔아 발주 불가·금전손실) | 롯데온 SOUT '있음' 저장 |
| **B** | 거짓품절 | 실=있음, 프로그램=품절/차단 | 판매기회 손실 | 무신사 빈색 매칭버그 |
| **C** | 999·센티넬둔갑 | 프로그램=센티넬, 실=실수량 존재 | 저장누락 | 스스·르무통 저장누락 |
| **D** | 미수집·확인불가 둔갑 | 크롤 매칭실패인데 '있음' 표기 | 3대원칙 위반(확인불가여야) | 현대H몰 색상모음전 |
| **E** | 수량불일치 | 상태는 맞으나 수량 상이 | 한정수량 오판 | SSF 한정수량 N개 |

### 4-3. OK 유형 (2종)

- **OK-1 완전일치**: 상태 + 수량 모두 일치
- **OK-2 상태일치**: boolean만 긁는 소싱처(수량 미제공)라 상태만 일치 — 정상 OK

### 4-4. 태그 예시

- `롯데온 / 블랙 / 100 → NG · 귀책=U · 증상=A` = URL이 대체상품을 가리켜 품절이 있음으로 둔갑 → **사용자가 URL 교체**
- `스스 / 아이보리 / L → NG · 귀책=P · 증상=C` = URL은 맞는데 저장 누락 → **Claude가 저장 파이프라인 수정**

## 5. 결과 출력 형식

소싱처별로:
- **집계표**: OK-1 / OK-2 / NG(귀책 U) / NG(귀책 P), 증상 A~E별 개수
- **조치 리스트 2분리**:
  - **URL 정정 리스트 (귀책 U)**: URL·색·사이즈·실값·프로그램값·왜 URL 문제인지 → 사용자 액션
  - **코드 수정 리스트 (귀책 P)**: 셀·증상·의심 코드 파일:라인 → Claude 액션
- **엑셀 산출물**: 색×사이즈 전수 대조표 (기존 검증 세션 엑셀 형식 준용)

## 6. UI (카드 + 탭)

- 카드 「크롤링 검사」: 기존 3개 카드(소싱처 추가·업데이트 / 데이터·코드 지도 / 크롤러 설치)와
  **동일 스타일**의 4번째 카드. 아이콘 = 검사/체크 계열.

- 재고 탭 본문: 프로토콜 전체 프롬프트 카드 + [복사] 버튼 + 간단한 사용법 3줄.
- **디자인 변경 = `/design-mockup` 게이트 선행 의무** (CLAUDE.md). 카드·탭·프롬프트 카드 레이아웃은
