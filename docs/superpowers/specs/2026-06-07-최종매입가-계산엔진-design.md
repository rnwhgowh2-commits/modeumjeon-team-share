# 최종 매입가 계산 엔진 — 설계 (Design Spec)

> 2026-06-07. 소싱처 크롤링 가이드 ③ 혜택 규칙(선반영/차감/적립/결제/캐시백 + 세트 제약)을 실제 **최종 매입가** 산출로 연결.
> 관계: [[2026-06-06-소싱처-크롤링-가이드-design.md]](③ 혜택 모델), 기존 `compute_breakdown`(api_benefits.py) 확장.
> 상태: **검토 대기** (사용자 확정 후 plan→구현).

---

## 1. 배경 / 조사 결과

- 이미 핵심 엔진 존재: **`compute_breakdown()`** (`webapp/routes/api_benefits.py`) — 소싱처 판매가 → 혜택 누적 차감 → `final_price`(실매입가). 매트릭스 셀·최저 소싱처 선정에 직접 사용(blast radius 큼).
- 혜택 데이터: `SourceBenefitTemplate`(사이트 기본) + `OptionBenefitOverride`(옵션별) + `SourceProduct.dynamic_benefits_json`(크롤 동적값). 카테고리 = 정액/정률/결제/캐시백/기타.
- 이미 구현됨: **결제 택1 pick-best**, 무신사머니/카드혜택가 fallback 상호배타.
- 별개: `compute_market_price`(unified.py) = 원가→마켓 판매가(업로드가). 본 작업과 무관.

→ **새 엔진 금지. 기존 `compute_breakdown` 을 확장**해 가격 일관성 유지.

## 2. 목표 / 비목표

**목표:**
- 가이드 ③ 혜택 5종(선반영/차감/적립/결제/캐시백)을 반영한 **최종 매입가** 산출.
- **세트 제약**(상호배타) 반영 + **경로별 최저가 자동 선택**.
- 가이드 ④ 검증 영수증·매트릭스 셀이 같은 결과를 쓰도록 단일 함수 경유.

**사용자 확정(2026-06-07):**
- Q1(a) 혜택 **값(%·원)은 크롤값**(`dynamic_benefits_json`) 사용. 없으면 0 취급.
- Q2(c) **공통 계산 모듈**(가이드·매트릭스 공용) + **모음전(옵션)별 혜택 추가/삭제/수정**(소싱처 베이스 위 override) 지원.
- Q3 경로 최저가 + **소싱처 선택**: 동일 옵션에 여러 소싱처 URL → **재고 있는 소싱처 중 최저 매입가** 선택.

**비목표(이번 X):**
- 혜택 율/금액 자동 크롤 로직 신규 작성(기존 크롤이 채운 값을 읽기만).
- 가이드 ③에서 혜택 값(%·원) 직접 편집 UI(다음 단계 — 값은 크롤·override 경유).

## 3. 계산 모델 (핵심)

입력: `BASE`(소싱처 표면 노출가=크롤가), 혜택 목록 `[{name, apply, value_type(%|원), value, tags}]`.

```
잔액 = BASE                       # 🔵 선반영은 이미 BASE에 포함 → 계산서 제외(표시만)
잔액 -= Σ 정액차감(원)            # 🔴 deduct, amount (원 단위)
# ── 모든 정률(%)은 직전 잔액(=베이스금액)에 순차 곱셈 차감 ──
best = min over 유효경로 P:
    p잔액 = 잔액
    for r in [정률차감%, 적립%, 결제%(P), 캐시백%(P 허용시)]:   # 🔴🟢🟣🟠 전부 순차
        p잔액 = p잔액 − p잔액 × r        # = p잔액 × (1−r), 직전 잔액 기준
    → p잔액
최종 매입가 = best
```

- **확정(2026-06-07)**: 모든 정률 혜택(선할인/쿠폰%·적립·결제·캐시백)은 **순차 누적 차감** — 각 %가 **직전 잔액(베이스금액)에 적용**되어 잔액이 갱신됨. 즉 `잔액 × Π(1 − 각 %)`. (병렬 합산 ❌)
- **예시**: `10,000 → −10% → 9,000 → −10% → 8,100` (= 10,000 × 0.9 × 0.9).
- **적립**도 실질 비용 인하로 같은 순차 곱셈에 포함(표시엔 '적립' 표기).
- 정액(원) 차감은 곱셈 전에 먼저 적용. 순서: 정액 → 정률(순차).
- ※ 이 순차 누적 방식은 **기존 `compute_breakdown` 동작과 동일** → M1 회귀 테스트가 그대로 성립.

## 4. 세트 제약 모델 (상호배타) — 핵심 신규

각 혜택에 **태그** 부여(데이터 모델에 추가):
- `pay_method`: `affiliate_card`(제휴카드 L.PAY·SSG.PAY) | `naver_pay`(네이버페이) | `other_pay`
- `channel`: `naver_via`(네이버 쇼핑 경유 — 제휴쿠폰 등) | `normal`
- `is_cashback`: bool

**제약 규칙(사용자 확정):**
1. 결제수단 택1: `affiliate_card` ⟷ `naver_pay` 동시 불가 (기존 결제 택1 확장).
2. `channel=naver_via` ⟹ `is_cashback` 혜택 비활성(캐시백 불가).

**경로(P) = (결제수단 선택, 유입경로 선택)** 의 유효 조합:
| 경로 | 결제 | 캐시백 | 네이버경유 쿠폰 |
|---|---|---|---|
| A 제휴카드·일반 | 제휴카드 | ✅ | ✗ |
| B 네이버페이·일반 | 네이버페이 | ✅ | ✗ |
| C 네이버경유 | (해당 결제) | ✗ | ✅ |
| D 무결제 | 없음 | ✅ | ✗ |

→ 각 경로의 최종 매입가 계산 후 **최저가 경로 채택**(`best`). 결과에 "선택된 경로" 표기.

## 5. 데이터 모델 변경

`SourceBenefitTemplate` / `OptionBenefitOverride` 에 컬럼 추가(멱등 ALTER, Alembic 없음 — shared/db.py 마이그레이션 리스트):
- `apply_mode VARCHAR(16)` — preapplied|deduct|accrue|payment|cashback (가이드 ③와 동일 enum). 기존 `category`(정액/정률/결제/캐시백/기타)와 매핑: 정액·정률→deduct, 결제→payment, 캐시백→cashback, +신규 preapplied/accrue.
- `pay_method VARCHAR(16)` nullable — affiliate_card|naver_pay|other_pay (payment 혜택만).
- `channel VARCHAR(16)` nullable — naver_via|normal.

> 마이그레이션 후 기존 행은 `category`→`apply_mode` 로 1회 백필(정액/정률=deduct 등). 신규 분류(선반영·적립)는 소싱처별로 수동/가이드 동기화.

## 6. 구현 위치 (단일 진실원천)

- `compute_breakdown()` 확장(또는 내부에서 호출하는 순수 함수 `compute_final_price(base, benefits) -> {final, path, steps}` 추출).
- **순수 함수로 분리**해 유닛 테스트 가능하게(기존은 DB·요청 결합). 시그니처:
  ```python
  def compute_final_price(base:int, benefits:list[dict]) -> dict:
      # benefits: [{name, apply_mode, value_type, value, pay_method, channel, is_cashback, enabled}]
      # returns {"final_price":int, "path":"A|B|C|D", "steps":[...], "applied":[...], "excluded":[...]}
  ```
- 기존 `compute_breakdown` 은 이 순수 함수를 호출하도록 리팩터(결과 동일 보장 — 회귀 테스트로 고정).
- 가이드 ④ 검증·매트릭스 셀 모두 이 결과 사용(중복 0).

## 7. 가이드와의 연결

- 가이드 ③ = **규칙 정의(진실원천)**: apply_mode·tags·status. 값(%·원)은 기존 혜택 테이블/크롤값.
- "③ 규칙 ↔ SourceBenefitTemplate 동기화" = 별도 작업(이번엔 모델만 일치시키고 수동/스크립트 백필).
- 가이드 ④ 영수증: `compute_final_price` 결과로 BASE→차감→경로(결제·캐시백)→적립→최종 표시 + "선택 경로" 뱃지.

## 8. 무결성 / 리스크

- **blast radius**: compute_breakdown 변경 = 전 매트릭스 가격. → **회귀 테스트 필수**(리팩터 전후 동일 final_price 스냅샷 비교) 후에만 머지.
- 값 없는 혜택(value=0/None) → 차감 0(무시), 오류 X.
- 잘못된 enum/tag → 검증 거부, 기존 값 보존.
- 음수 매입가 방지(사니티 가드 `pricing_policy.sanity_check` 재사용).

## 9. 테스트

- 순수 함수 유닛: 선반영 제외 / 정액·정률 순차차감 / 경로 4종 최저가 선택 / 세트제약(네이버경유→캐시백off, 제휴카드↔네이버페이 택1) / 적립 차감 / value 누락.
- 회귀: 기존 compute_breakdown 출력 = 리팩터 후 출력 동일(샘플 SKU 다수).
- 실검증: 가이드 ④에서 무신사·SSG 샘플 URL 검증 → 경로·최종가 표시 확인.

## 10. 마일스톤

- **M1**: 순수 함수 `compute_final_price` + 유닛/회귀 테스트 + compute_breakdown 리팩터(동작 동일).
- **M2**: 데이터 모델 3컬럼 + 백필 + 세트제약/경로선택 활성.
- **M3**: 가이드 ④ 영수증에 경로·최종가 연결. ③ 규칙↔혜택테이블 동기화.

## 11. 레이어 구조 (사용자 확정 Q2·Q3 반영)

혜택 적용 = **3계층** (아래로 갈수록 우선):
1. **소싱처 베이스** = 가이드 ③ 규칙 ↔ `SourceBenefitTemplate` (사이트 공통 혜택·태그).
2. **모음전(옵션)별 override** = `OptionBenefitOverride` (canonical_sku 단위) — 모음전 상품마다 혜택 **추가/삭제/수정**. UI에서 편집(다음 단계). 엔진은 base+override 머지(기존 compute_breakdown 이 이미 머지).
3. **크롤 동적값** = `dynamic_benefits_json` — 등급적립·머니·기프트포인트 등 상품 크롤 시점 실값 주입.

→ `compute_final_price(base, merged_benefits)` 는 위 3계층을 머지한 혜택 목록을 받음(순수 함수).

### 소싱처 선택 (Q3) — 엔진 위 레이어
- 한 옵션(canonical_sku)에 소싱처 N개 URL 가능. 각 소싱처별 `compute_final_price` → 매입가 N개.
- **선택 = 재고 있는 소싱처 중 최저 매입가** (기존 `lowestSrcPerOpt` + 재고 시맨틱 [[project_stock_matching_semantics]] 재사용).
- 재고 판정·센티넬(999 등) 기존 규칙 그대로. 본 엔진은 "소싱처별 매입가"만 정확히 내고, 선택은 기존 레이어가 수행.

### 흐름 요약
```
[가이드 ③ 규칙=SourceBenefitTemplate] + [모음전별 OptionBenefitOverride] + [크롤 dynamic_benefits_json]
        │ merge (compute_breakdown)
        ▼
 compute_final_price(소싱처 BASE, merged) → 소싱처별 최종 매입가 (+선택 경로)
        │  옵션의 소싱처 N개 각각
        ▼
 재고 있는 소싱처 중 최저 매입가 = 옵션의 채택 매입가 (기존 lowestSrcPerOpt)
        ▼
 매트릭스 셀 / 가이드 ④ 영수증 표시
```
