## 1. 목적 (Why)

재고 정합성 검사와 짝이 되는 **가격** 검사. 소싱처 크롤이 저장한 가격이 실제 상품 URL의 가격과
맞는지 반복 검사하는데, 가격은 재고보다 층이 많아(표면노출가−혜택=최종매입가) 에러가 더 잦다.
재고 탭과 똑같이 **프롬프트 복사형**으로 시스템화한다.

## 2. 산출물 구조 (What)

**이미 만들어진 「크롤링 검사」 팝업의 두 번째 탭(현재 「준비 중」 placeholder)을 채운다.**

- 위치: `/sourcing-guide/crawl-check` 팝업 → 「💰 가격 정합성 검사」 세그먼트
- 형태: 재고 탭과 **동일한 시각 구조** — 사용법 3줄 + 「📋 복사할 프롬프트」 라벨 박스(꽉 채움) + 복사 버튼 2개(우상단·하단 풀폭)
- 내용: 아래 가격 프로토콜 전체 프롬프트를 인라인
- 서버 로직·DB 변경 **없음** (정적 프롬프트 표시. 머니 경로 무영향)

## 3. 조사 프로토콜 (프롬프트 본문)

1. **크롤** — 대상 소싱처 매트릭스 등록 URL 전체 로컬 크롤 → 최신 가격·혜택 DB 반영
2. **실브라우저 엑셀 조사** — 각 URL을 실브라우저로 열어 **3층**을 읽어 엑셀로 정리:
   ① 표면노출가 ② 적용 가능 혜택(선반영/후반영/결제택1/캐시백)의 항목·금액 ③ 최종매입가(혜택 적용 계산)
3. **대조** — 크롤 결과값(매트릭스 셀=표면가+최종매입가, 계산식 영수증=혜택 내역)과 2의 엑셀을 셀 단위 1:1 대조
4. **OK/NG 판정 + 이중 태그**
5. **집계·출력** — 소싱처별 유형별 개수 + 조치 리스트(U/P 분리) + 전수 대조 엑셀

## 4. OK/NG 판정 기준 + 유형

**대조 단위 = 색×사이즈 셀 1칸.** 각 셀 3층을 실브라우저 URL과 대조.

- **OK** = 3층(표면가·혜택 항목/금액·최종매입가) 모두 일치. (혜택 미정의 소싱처=스스·르무통공홈은 표면가=최종가 일치면 OK)
- **NG** = 어느 층이든 불일치. **이중 태그**(귀책 + 증상).

### 4-1. 귀책 축 (재고와 동일)

| 귀책 | 판정 | 조치 |
|---|---|---|
| **U (URL측)** | 등록 URL이 실제 상품과 불일치(대체상품·다른상품·404·만료) | 사용자가 URL 정정 |
| **P (프로그램측)** | URL은 맞는데 저장 가격·혜택·계산값이 틀림 | Claude가 코드 수정 |

### 4-2. 증상 유형 (3층 × 위험도 순)

| 코드 | 층 | 이름 | 정의 | 위험 | 사례 |
|---|---|---|---|---|---|
| **A** | 표면 | 표면가 오류 | 실브라우저 표면가 ≠ 프로그램 표면가(오긁음·1원둔갑·stale) | 직접 금전 | P1·P17 |
| **B** | 최종 | 언더프라이싱 | 프로그램 최종가 < 실제(없는/과다 혜택 적용) | ★최고 (싸게 보고 발주=손해) | P20·P9 |
| **C** | 최종 | 폴백가 둔갑 | 크롤·매칭 실패인데 대표가(평균·최저·95000) 표시 | ★최고 (가짜 가격) | P23 |
| **D** | 혜택 | 혜택 누락 | 실제 받는 혜택이 프로그램에 안 뜸 → 매입가 과대표시 | 기회손실 (더 싼데 안 삼) | P3·P8·P19 |
| **E** | 최종 | 셀≠계산식 | 표면·혜택 맞는데 셀 큰숫자 ≠ 계산식 영수증(단일 진실 원천 위반) | 표시 모순 | P4 |

### 4-3. OK 유형 (2종)

- **OK-1 완전일치**: 3층 모두 일치
- **OK-2 표면가일치**: 혜택 미정의 소싱처(표면가=최종가) — 표면가만 일치하면 OK

### 4-4. 태그 예시

- `무신사 / 블랙 / 100 → NG · 귀책=P · 증상=A` = 회원가를 표면가로 오긁음 → 크롤러 표면가 파싱 수정
- `SSG / 아이보리 / L → NG · 귀책=P · 증상=D` = SSG MONEY 적립이 라이브크롤로 미저장 → 혜택 배선(`_SITE_BY_SRC`) 수정

## 5. 가격 특유 함정 (프롬프트에 명시)

- **완전한 B (다중 URL)**: 한 소싱처에 URL 여러 개면 셀은 **최저 최종매입가 후보**를 고름. stale 후보면 유령가=언더프라이싱(B). 셀·계산식은 **같은 후보**(source_product_id) 써야 함(E).
- **라이브 확장크롤(`save_crawl_result`)은 혜택 미저장**(price/stock만) — 무신사·롯데온 혜택 안 뜨면 여기(D 주 배선원인). SSG/SSF는 navGrab→parse의 `_save_navgrab_dynamic_benefits`가 저장(P3 해소).
- **폴백가 금지(§4 철칙)**: 매칭·크롤 실패 시 대표가(평균·최저·95000) 폴백 절대 금지 → "가격 없음 + 크롤 실패" 표면화(C).

## 7. 구현 범위 (파일)

- **Modify** `webapp/templates/sourcing_guide/crawl_check.html` — 「가격 패널」 placeholder를 재고 패널과 동일 구조(사용법 3줄 + 라벨 박스 + 복사 버튼 2개)로 교체, 가격 프롬프트 전문 인라인. 복사 JS를 두 패널이 공유하도록 일반화(패널별 프롬프트 박스 id 부여).
- **Modify** `tests/sourcing/test_crawl_check_tab.py` — 가격 프롬프트 핵심 문자열 검증 추가(예: "언더프라이싱", "표면노출가", "혜택 누락", "셀≠계산식").
- 라우트·카드 변경 없음(이미 존재).

## 8. 범위 밖 (YAGNI)

- 전송층(판매처로 나가는 가격) 검사 — 정합성 검사는 크롤 vs 실브라우저까지. 전송은 드라이런(별개).
- 결과 DB 저장·대시보드 (프롬프트 복사만).
