## 2. 개념·번호 규칙 [확정]

### 개념은 셋

| 개념 | 뜻 | 표시번호 | 속 열쇠 |
|---|---|---|---|
| **개별 옵션** | 색상 × 사이즈 한 줄 | `U20260801-000003-01` | `canonical_sku` (`SKU-XXXXXXXX`) |
| **매트릭스 옵션** | 옵션들의 묶음(축 구성) | 원본 `U…` / 파생 `P…` | `matrix_options.id` |
| **모음전 상품** | 마켓에 파는 단위 | `M…` | `models.model_code` |

화면에서는 위 세 말만 쓴다. 「모델」·「모상품」·「묶음」 같은 옛 표현은 화면에서 없앤다.

### 규칙 1~9

1. **옵션의 주인은 원본 매트릭스 하나뿐이다.** 상품이 아니다. 파생(`P…`)은 주인이 아니라 「골라 담은 목록」이다.
2. **상품은 매트릭스의 옵션을 참조한다.** 복제하지 않는다. 한 매트릭스에서 상품을 여러 개 만들 수 있다.
3. **소싱처 URL·축·사입 정보는 원본에서만 고친다.** 고치면 그 옵션을 쓰는 **모든 상품에 즉시 반영**된다.
4. **어느 소싱처에서 살지는 사람이 안 정한다.** 재고 있는 소싱처 중 **최종매입가 최저**. 🔴 표면가로 고르면 틀린다(실측: 메이트 라이트블루 240 — 표면가 최저 롯데온 116,840 vs 최종매입가 최저 르무통 107,700).
5. **`M…` 은 판매 단위로 만들어진 것.** 매트릭스만 있으면 `M…` 이 없다. 실제 판매 중인지는 별도 상태로 본다.
6. **우리 옵션 1 : 소싱처 옵션 N.**
7. **사입은 번호가 아니라 옵션의 상태다.** 사입품번을 따로 만들지 않는다.
8. **번호 발급은 `shared/display_no.py` 한 곳에서만.** 옵션 열쇠(`canonical_sku`)는 바꾸지 않는다 — 252파일 1,715곳이 쓴다.
9. **전 소싱처 품절 + 사입 0 → 그 옵션 재고만 0.** 상품은 안 내린다. 한 상품의 옵션이 전부 품절되면 알림.

### 규칙 10~12 — 중복 금지 [확정]

10. **만드는 격자는 하나, 보는 격자는 하나.** 색상×사이즈 격자가 두 곳에 생기지 않게 한다.
    · 만들기 = 「옵션 생성(직접)」 화면 · 보기 = 「상품관리 > 모음전 옵션관리」
11. **소싱처 주소 저장소를 하나로 합친다.** 지금 `OptionSourceUrl`(구)과 `bundle_source_urls`(신) 두 곳으로 갈려 있고, 예전에 한쪽만 읽어 **원가가 가짜 95,000원으로 튄 사고**가 있었다(`lemouton/uploader/preview.py:107` 주석). 옵션 주인을 옮기는 그 작업에서 **하나로 합친다.** 안 합치면 셋이 된다.
12. **같은 기능의 입구는 하나.** 모음전 상세의 「옵션 조합 생성 및 수정」 버튼은 없애고 새 화면 링크로 바꾼다. 별도 재고 매핑 화면(`/bundles/<code>/inventory-mapping`)도 없애고 모달의 「📋 재고관리 매핑」 탭 하나만 남긴다.

## 5. 하위탭 ① 모음전 옵션 생성 (직접)

### 5.1 화면 = 지금 창을 그대로 편 것 [확정 E1]

정본 = `webapp/static/option_url_modal.js` (3,377줄). **다시 만들지 않는다.** 모달을 화면(라우트)으로 승격만 한다.

```
┌ 옵션 매트릭스 (왼쪽·파랑) ──┐  →  ┌ 소싱처 URL 매핑 (오른쪽·초록) ─┐
│ ① 축 생성 ② 옵션명           │ 적용 │ 📍 소싱처 URL 매핑 / 📋 재고관리 매핑 │
│ ③ 자동 생성 ④ OFF 클릭       │      │ 소싱처 탭 8개 (가로 스크롤)          │
│ 1축(가로) 💡추천: 색상        │      │ URL 카드 — 라벨 · 타입 · 주소 ·      │
│ 2축(세로) 💡추천: 사이즈      │      │   📌 13/102 · ▸매핑 · 📋복사 · ✕삭제 │
│ ＋ 축 추가 (최대 3축)         │      │ ▸매핑 펼치면 옵션 격자로 찍기        │
│ 조합 매트릭스 102/126         │      │ ＋ 새 현대H몰 URL 추가               │
└──────────────────────────┘      └──────────────────────────────┘
```

지금 창이 이미 하는 것 (그대로 씀):
- 축 최대 3개, 이름 자유 (추천: 색상 · 사이즈 · 모델) → 노션의 「2/3축 쪼개기」가 이미 됨
- 조합 매트릭스 ON/OFF, 헤더 클릭 = 줄 전체 토글, 드래그 = 순서 변경
- **주소 하나 = 여러 옵션.** 주소를 등록하고 「이 주소가 어느 옵션들을 덮는가」를 격자로 찍음
  (실측: `HMALL_색상모음전` 주소 하나가 **97/102 옵션**을 덮음)
- 주소 타입 3종 — 단품 / 색상모음전 / 모델모음전 (크롤 로그 구분용)
- 크롤 실패 주소는 빨강 카드 + 「❌ 크롤 실패 (응답 오류) — 이 URL 의 옵션 13건은 가격/재고를 못 받았어요.」
- 「📋 재고관리 매핑」 탭 = **노션 STEP 2-2 「사입」의 자리** (새로 만들 것 없음)

### 5.2 새로 만들 것 5가지 (기획의도 대비 모자란 것)

| # | 무엇 | 왜 |
|---|---|---|
| 1 | **매트릭스 옵션명 칸 + `U…` 번호** | 노션 STEP 1 = 「원본 매트릭스 옵션번호, 옵션 매트릭스명」. 지금 창은 모음전에 매달려 열려서 이름을 안 받음 |
| 2 | **옵션마다 표시번호 `U…-01`** | 노션 = 「옵션별 개별 옵션번호/옵션명 생성」. 지금은 `SKU-` 만 뒤에서 생기고 화면에 안 보임 |
| 3 | **합친 옵션명** — 예 `메이트 블랙 265` | 노션 = 「2/3축 쪼개져도 하나의 옵션번호」. 규칙 = **매트릭스 옵션명 + 축 값들을 축 순서대로 공백으로 이어 붙임**. `메이트`(매트릭스명) + `블랙`(1축) + `265`(2축) → `메이트 블랙 265`. 3축이면 값이 하나 더 붙는다 |
| 4 | **모음전 없이 열리는 입구** | 규칙 1 — 옵션의 주인이 매트릭스가 되므로 |
| 5 | **화면에 SKU 숨기기** | 표시번호만 보이게. SKU 는 속 열쇠라 화면에 두면 번호가 둘로 보인다 |

### 5.3 안 만드는 것 [확정]

- **소싱처별 색상·사이즈 이름 자동 매칭** — 노션에 「시안 제시 필요」로 적힌 항목. 자동으로 잇다 틀리면 엉뚱한 색상의 가격·재고를 가져오므로, 지금처럼 격자에서 손으로 찍는다.

## 6. 하위탭 ② 모음전 옵션 생성 (내마켓 불러오기)

## 9-2. ✅ §4 「모음전 상세 4조각 분리」 + 규칙 12 (2026-08-02)

### 어떻게 나눴나 — **자르지 않고 고른다**

🔴 `_matrix_v3.html` 은 **6,000줄짜리 `<script>` 한 덩어리**가 옵션 트리·매입가 격자·
크롤 카드를 **한꺼번에** 그린다. 조각을 잘라 다른 템플릿으로 옮기면 서로를 못 찾아
죽는다. 그래서 **DOM 은 그대로 다 싣고 `data-piece` 로 보여줄 조각만 고른다**
(이 화면이 이미 쓰던 탭 전환과 같은 방식).

- 렌더러 한 벌 = `webapp/routes/bundles.py:_render_bundle_detail(code, piece=, active=)`
- 조각 스위치 = `edit.html` 의 `BUNDLE_PIECE` + `.piece-off { display:none !important }`
- 🔴 `!important` 필수 — 이 화면 JS 가 `sm-side-h` 등에 **인라인 display 를 직접 찍는다.**
  없으면 크롤이 끝나는 순간 감춰둔 조각이 되살아난다.
- 배정표의 단일 진실 원천 = `tests/test_bundle_detail_split.py:ASSIGNMENT`

### 입구 4개

| URL | 메뉴 | 무엇이 보이나 |
|---|---|---|
| `/bundles/<code>` | 📦 모음전 상품관리 | 헤더·기본 정보 + **나머지 조각으로 가는 문 4장** |
| `/policies/product/<code>` | 🔧 상품 가공 | 가격 템플릿 · 사올 때 · 팔 때 · 마켓 등록·업로드 · 고급 축 구성 |
| `/automation/product/<code>` | ⚙️ 자동화 | 전체 크롤 · 소싱처 진행 카드 · 최저가 1위 · **실행 이력** |
| `/matrix/product/<code>` | 📦 모음전 옵션관리 | 옵션 트리 · 옵션별 실제 매입가 격자 · 브랜드 지정 · 선택 크롤 |
| `/bundles/<code>/all` | (되돌아볼 자리) | 나누기 전 화면 그대로 — 지우지 않는다 |

목적지 메뉴에서 상품을 고를 길도 냈다: 🔧 은 `상품 정책 적용` 표의 「가격 보기 →」,
⚙️ 는 자동화 화면의 「상품 하나만」 찾기 칸, 📦 은 매트릭스 카드 밑 링크.

### 설계서 §4 에서 **바뀐 판단** 4가지

1. **「기본 정보」는 📥 옵션생성으로 안 옮겼다.** 모음전 코드·카테고리·노출명은
   **상품** 정보지 옵션 정보가 아니다. 옵션 만드는 화면에 상품 설정을 끼워 넣으면
   그 화면의 뜻이 흐려진다 → 📦 모음전 상품관리에 남긴다.
2. **「선택 크롤」은 ⚙️ 자동화가 아니라 📦 옵션관리에 뒀다.** 고를 격자가 거기 있다.
   자동화로 보내면 **고를 대상이 없어 못 쓰는 단추**가 된다. ⚙️ 는 전체 크롤 담당.
3. **헤더는 조각마다 「이름만」 남겼다.** 가격 추이 차트·복제·삭제는 `home` 전용.
   같은 차트를 네 화면에서 또 그리는 것은 중복이고, 「가격」 화면의 삭제 단추는
   잘못 누를 자리만 늘린다.
4. **「실행 이력」은 없어진 게 아니라 못 열던 것이었다.** 탭이 3개로 줄며
   `sec-runs` 가 인라인 `display:none` 으로 남아 **아무 데서도 안 열렸다.**
   ⚙️ 자동화 조각이 그 자리를 되찾았다.

### 규칙 12 — 옵션 고치는 입구를 하나로

모음전 상세의 「＋ 옵션 조합 생성 및 수정」이 모달을 또 띄우던 것을
`/optgen/box/<code>` 링크로 바꿨다. `toss.js` 의 `step-design` 처리기는 **지우지 않는다**
— 지금 부르는 화면은 없지만 `option_url_modal.js` 가 그 이름에 붙어 있다.

### 곁다리로 고친 것
`/api/policies/bundles` 가 **번호·브랜드로만** 찾았다. 사장님은 「메이트」로 찾는다
→ 이름(`model_name_display`)도 찾도록 넓혔다. 🔧 상품 정책 적용 화면도 같이 좋아진다.

## 14. 모델 모음전 — **열려 있다.** 막이는 전송에 (2026-08-13 사장님 확정)

### 한때 만들기를 막았다가 되돌린 이유

감사 후속으로 모델 모음전 프리셋을 「준비 중」으로 막았었다. **막는 자리가 틀렸다.**

사장님 지적 — 「옵션·상품 만들 때 축은 1·2·3축 가능하고, 마켓별 축 설정은 **상품 가공**에서
하는 것 아니냐」. 맞다. 노션에도 「마켓별 옵션 1/2/3축 구성 정책」은 **상품 가공 > 정책 생성**
항목으로 적혀 있다. 만들기 탭이 정할 일이 아니다.

### 실측 — 만들기 단계는 온전하다

3축(모델·색상·사이즈)으로 옵션을 만들어 확인한 결과:

| 확인 | 결과 |
|---|---|
| 축 값 3개가 다 남나 | ✅ `["메이트","블랙","250"]` |
| SKU 가 서로 다른가 | ✅ |
| 옵션명이 서로 다른가 | ✅ `메이트 블랙 250` / `스위트 블랙 250` |
| 모델명이 축에서 나오나 | ✅ |

**겹치는 건 마켓 전송뿐이다.** 마켓 옵션 이름을 `색상 + 사이즈` 두 칸으로만 만들기 때문에
(`formatter/esm.py:60`·`coupang.py:44`·`lotteon.py:59`), 모델이 달라도 둘 다 「블랙 250」이 된다.

### 그래서 막이는 전송에 있다

`lemouton/formatter/pipeline.py` — 한 상품 안에서 마켓 옵션 이름이 겹치면
**그 옵션만 전송 보류**하고 사유를 남긴다(`option_name_collision`).
재고 확인 불가 때와 같은 처방이다 — 틀린 값을 보내느니 보류하고 이유를 말한다.

시험 = `tests/test_formatter_axis_collision.py`

- 1축 `['모델']` → 마켓 이름 「메이트」 — 겹치지 않는다(막이 안 걸림)
- 2축 `['모델','색상']` → 「블랙 메이트」 — 겹치지 않는다. 다만 모델명이 **사이즈 칸**에 들어가
  마켓에서 칸 이름이 어긋난다(값은 유일하므로 주문 매칭은 된다)
- 3축 → 「블랙 250」이 겹친다 → **보류**

### 이 막이를 푸는 조건 — **스마트스토어는 풀렸다 (2026-08-13)**

#### 마켓이 3축을 받나 → **받는다** (문서 근거 확보)

판매처 지도 전수정독으로 확인. 근거 서열 2(마켓 개발자센터 원문), 문서 버전 2.85.0:

> `optionCombinations` — **「최대 등록 가능한 옵션 개수는 조합형은 3개, 지점형은 4개입니다.」**
> 축 이름 칸도 있다 — `optionCombinationGroupNames.optionGroupName1~3`

🔴 **[2026-08-13 정정] 「표준형 함정」은 없었다 — 내가 만든 추론이다.**

한때 여기에 「카테고리가 표준형을 필수로 요구하면 3축 조합형은 못 쓴다」고 적고,
`GET /v1/options/standard-options` 판정 게이트를 지으려 했다. **접었다.** 근거 셋:

1. 지도 `optionInfo`(부모) 원문에 **표준형이라는 말이 아예 없다** —
   「단독형 옵션, 조합형 옵션, 직접 입력형 옵션 중 최소 한 개는 입력해야 합니다.」
2. 저장소가 **이미 결론냈다** — `docs/superpowers/plans/2026-07-17-대량등록-Phase1A.md:903`
   > ✅ 표준형 vs 조합형 확인 완료 … `optionInfo` 가 「최소 한 개」라고 명시 —
   > **표준형은 강제가 아니다. 조합형으로 진행이 맞다.**
3. `optionSetRequired` 는 최상위가 아니라 **표준형 그룹 안** 필드다
   (`standardOptionCategoryGroups[]` 안, `groupName` 과 `standardOptionAttributes` 사이).
   「이 카테고리가 표준형을 강제하나」를 묻는 칸이 **아니다.**

표준형과 조합형이 **함께** 못 쓰이는 것은 사실이다. 그러나 **카테고리가 표준형을
강제한다고 말하는 칸은 지도에 없다.** 없는 제약을 근거로 게이트를 지으면,
지금 잘 올라가는 카테고리 등록까지 멈춘다.

🔴 **쿠팡은 아직 아니다** — `items` 최대 200개·`attributes` 반복 가능이지만
**attributes 개수 상한은 확인불가**(문서 링크 403)이고, 원문에 경고가 있다:
「2024년 10월 10일부터 자유 구매옵션 구성을 할 경우 노출에 제한이 됩니다」.
그래서 쿠팡은 **2갈래 그대로** 두고, 모델이 겹치면 막는다.

#### 진짜 막이는 마켓이 아니라 **우리 칸이 없던 것**이었다

코드가 사유를 그대로 적어 두고 있었다 —
「옵션에 모델명을 담는 칸이 없습니다(옵션은 색상·사이즈·재고·추가금·SKU 만 담습니다)」.
칸을 만들었다. 새 저장 칸이 아니라 **그때그때 만드는 값**이다(같은 사실을 두 곳에 저장하면 갈린다).

| 자리 | 무엇을 했나 |
|---|---|
| `policy/to_payload.py` `_options_json` | 옵션 행에 `model` 칸 — 값은 `matrix/option_name.model_name_of` |
| `registration/options.py` `_normalize` | 중복 검사 키 = **이번 전송이 실제로 내보내는 이름 조합** |
| `registration/options.py` `build_smartstore_options` | `axis='three'` 를 받는다 → `모델명 · 색상 · 사이즈` |
| `registration/process_apply.py` `option_axis` | `NO_MODEL_AXIS` 강등 제거 |
| `webapp/routes/api.py` 미리보기 | `opt_dicts` 에 `model_name` |

🔴 **여기서 하마터면 사고 날 뻔한 자리** — `_normalize` 는 스스·쿠팡이 **같이 쓰는** 정규화기다.
중복 키를 무조건 (모델,색상,사이즈)로 넓혔더니 쿠팡으로 `블랙-260` 두 줄이 **에러 없이** 나갔다(실측).
불변식은 「모델 칸이 있느냐」가 아니라 **「이번 전송이 모델을 이름에 싣느냐」**다.
안 싣는 전송에서 모델만 다른 옵션이 오면 **막고, 3갈래로 바꾸라고 말한다.**
