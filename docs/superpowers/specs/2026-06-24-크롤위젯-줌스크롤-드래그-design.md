# 크롤 위젯 — 확대/축소·스크롤·폭조절 입력 재정의 (설계)

> **계층**: 프로젝트 스펙 (단일 기능)
> **대상 파일**: `프로그램/_시스템/webapp/static/crawl_log.js` (단일), 배포 시 `templates/base.html` 캐시버스터
> **작성일**: 2026-06-24
> **상태**: 사용자 확정 — 구현 플랜 대기

---

## 1. 배경 / 문제

크롤 진행 위젯(`#mcl-panel`)의 마우스 입력(폭조절·스크롤·확대축소)이 한 휠 핸들러에 뒤엉켜 있어 다음 문제가 있다.

- **휠로 폭이 바뀜**: 위젯 위에서 그냥 휠을 굴리면 폭이 변한다(`onPanelWheel` → `preventDefault` 후 width 변경). 의도치 않은 오작동.
- **내부 세로 스크롤이 막힘**: 패널 전체에 휠 리스너가 `e.preventDefault()`로 걸려 있어, 이미 `overflow-y:auto`인 내부 패널들(모음전 목록·소싱처 카드·로그표)의 마우스 휠 세로 스크롤이 전부 죽어 있다.
- **확대/축소 수단 없음**: `transform:scale(1.5)` 고정. `ctrl+휠`은 위젯이 안 가로채서 브라우저 페이지 전체가 줌된다.

## 2. 목표 (사용자 요구사항)

1. **좌우(폭) 조절 = 마우스 드래그 전용.** 휠로는 폭이 바뀌지 않는다.
2. **확대/축소 = 위젯 위에서 `Ctrl+휠` ↑↓.** 위젯만 커지고/작아지고, 브라우저 페이지는 줌되지 않는다.
3. **상/하 스크롤 = 그냥 휠 ↑↓.** 마우스 밑 패널이 세로 스크롤된다. 대상 영역 3종:
   - `#mcl-rail` — 좌측 모음전 목록
   - `#mcl-cards-wrap` — 소싱처 카드 **전체 목록**(여러 소싱처 카드가 세로로 쌓인 바깥 컨테이너)
   - `.mcl-card-logs` — 한 소싱처 카드 **안의** URL 로그 기록표(소싱처마다 독립)

## 3. 사용자 확정 결정

| 항목 | 결정 |
|---|---|
| 줌 범위 | **1.0× ~ 2.0×** |
| 줌 단계 | **0.25× / 한 휠 노치** |
| 줌 기본값 | **1.5×** (현재 보이는 크기 유지) |
| 줌 리셋 제스처 | **없음** |
| 중첩 스크롤(로그표 위) | **브라우저 기본** — 로그표 끝까지 스크롤하면 바깥 카드 목록으로 이어서 스크롤(체이닝 유지, `overscroll-behavior` 미설정) |

## 4. 행동별 화면 반응 (확정 사양)

| # | 행동 | 마우스 위치 | 결과 |
|---|---|---|---|
| 1 | 왼쪽 모서리 핸들 드래그 | `#mcl-grip` | 폭 넓어짐/좁아짐 (유일한 폭조절 수단) |
| 2 | 그냥 휠 ↑↓ | 위젯 빈 곳·헤더 | 변화 없음 |
| 3 | 그냥 휠 ↑↓ | `#mcl-rail`(모음전 목록) | 목록 세로 스크롤 |
| 4 | 그냥 휠 ↑↓ | `#mcl-cards-wrap`(카드 전체) | 소싱처 카드 목록 세로 스크롤 |
| 5 | 그냥 휠 ↑↓ | `.mcl-card-logs`(소싱처 로그표) | 그 소싱처 로그표 세로 스크롤, 끝나면 바깥 목록으로 체이닝 |
| 6 | Ctrl+휠 ↑ | 위젯 아무 곳 | 위젯만 확대 (+0.25, 상한 2.0×) |
| 7 | Ctrl+휠 ↓ | 위젯 아무 곳 | 위젯만 축소 (−0.25, 하한 1.0×) |
| 8 | Ctrl+휠 | 위젯 바깥 | 브라우저 페이지 줌 (그대로) |
| 9 | 줌 변경 후 | — | 위젯 높이는 항상 화면 세로 꽉 채움, 글자·카드만 스케일, 오른쪽 가장자리 고정 |

## 5. 설계

### 5.1 scale 고정 상수 → 동적 변수 + CSS 변수

scale이 여러 곳에 1.5로 박혀 있어 한 곳만 바꾸면 어긋난다. CSS 커스텀 프로퍼티 `--mcl-scale` 로 단일화한다.

- `#mcl-panel` CSS:
  - `transform:scale(1.5)` → `transform:scale(var(--mcl-scale, 1.5))`
  - `height:calc(100vh / 1.5)` → `height:calc(100vh / var(--mcl-scale, 1.5))` (높이가 scale에 묶여 줌해도 화면 세로 100% 유지)
  - `transform-origin:top right` 유지 (오른쪽 가장자리 고정)
- `#mcl-panel.mcl-hidden` 의 `transform:scale(1.5) translateX(100%)` → `transform:scale(var(--mcl-scale,1.5)) translateX(100%)`
- 패널 생성 시 `--mcl-scale` 초기값 1.5 설정.
- JS 모듈 변수 `panelScale = 1.5` 도입. 기존 고정 상수 `DOCK_SCALE = 1.5` 의 **모든 참조를 `panelScale` 로 교체** (`onGripDown` 드래그 좌표 변환, `clampPanelW`, 등). 줌 상태에서 드래그/클램프 계산이 어긋나지 않게.

### 5.2 `applyZoom(next)` 신설

```
function applyZoom(next):
    next = clamp(next, 1.0, 2.0)
    next = round(next / 0.25) * 0.25      # 0.25 격자에 스냅
    if next == panelScale: return
    panelScale = next
    panel.style.setProperty('--mcl-scale', String(next))
    applyDock()                            # 화면상 폭 변동 → 본문 밀어내기 폭 재계산
```

### 5.3 `onPanelWheel` 재정의 (핵심)

```
function onPanelWheel(e):
    panel = #mcl-panel
    if !panel or panel.hidden: return
    if e.ctrlKey or e.metaKey:             # 확대/축소
        e.preventDefault()                 # 브라우저 페이지 줌 차단
        step = (e.deltaY < 0) ? +0.25 : -0.25
        applyZoom(panelScale + step)
        return
    # 그냥 휠 → 아무것도 안 함(preventDefault 제거) → 내부 네이티브 세로 스크롤 복원
```

- **휠→폭 변경 로직 완전 제거** (요구 1).
- 그냥 휠 경로에서 `preventDefault` 를 하지 않으므로 `#mcl-rail`·`#mcl-cards-wrap`·`.mcl-card-logs` 의 네이티브 세로 스크롤이 자동 복원됨 (요구 3). **추가 스크롤 코드 불필요.**
- 리스너는 `{ passive: false }` 유지 (ctrl 경로에서 `preventDefault` 필요).

### 5.4 폭 드래그 — 유지

`onGripDown`(`#mcl-grip` mousedown 드래그)은 동작 변경 없음. 내부 `DOCK_SCALE` 참조만 `panelScale` 로 교체.

## 6. 데이터 흐름

- `Ctrl+휠` → `onPanelWheel` → `applyZoom(panelScale±0.25)` → `--mcl-scale` 갱신(+ 높이 자동) → `applyDock()`(본문 max-width 재계산).
- `그냥 휠` → 브라우저 네이티브 → 마우스 밑 스크롤 박스(rail/cards/logs)가 세로 스크롤.
- `핸들 드래그` → `onGripDown` → 폭(미변환 px) 변경 → `applyDock()`.

## 7. 영향 범위 / 비목표

- **영향 없음**: 크롤 이벤트 처리(`handleCrawlLog`), 레일/상세/헤더 렌더, 최소화 카드, 도킹 로직 자체(폭 계산만 `panelScale` 사용), 일시중지/중지 버튼.
- **비목표(YAGNI)**: 줌 리셋 제스처, 줌 퍼센트 표시 UI, 줌값 영속(localStorage), 터치/핀치 줌, 최소화 레일(`#mcl-rail-min`) 줌.

## 8. 검증 (라이브 실브라우저 — mou-m.com 크롤 위젯)

> 로컬 `file://` 프리뷰는 CSS 충돌을 못 잡으므로 라이브 실검증 필수(프로젝트 기록).

1. 핸들 드래그로 폭이 변한다. **그냥 휠로는 폭이 안 변한다.**
2. 위젯 위 `Ctrl+휠`로 위젯만 1.0×~2.0×, 0.25 단계로 줌된다. **브라우저 페이지는 줌되지 않는다.** 상·하한에서 멈춘다.
3. `#mcl-rail`(모음전 목록) 위 휠 → 목록 세로 스크롤.
4. `#mcl-cards-wrap`(카드 전체) 위 휠 → 소싱처 카드 목록 세로 스크롤.
5. `.mcl-card-logs`(소싱처 로그표) 위 휠 → 그 로그표 세로 스크롤, 끝나면 바깥 목록으로 체이닝.
6. 모든 줌 배율(1.0/1.25/1.5/1.75/2.0)에서 위젯 높이가 화면 세로를 꽉 채우고 오른쪽 가장자리에 고정.
7. 줌 변경 후에도 핸들 드래그 폭조절·도킹(본문 밀어내기)이 어긋나지 않는다.
