## 1. 배경 / 문제

소싱처 크롤 시 재고를 잘못 잡는 사고가 반복된다. 현재 확인된 곳은 **무신사·롯데온 단품**(다른 소싱처는 현재 양호하나 같은 구조적 위험 보유).

**근본 원인 = 센티넬 `999`의 의미 과부하.** 재고는 정수 한 칸(`current_stock`/`last_stock`)에 저장되고 `999`(또는 `None`)가 "있음"을 뜻하는데, 이 "있음"이 서로 다른 두 상황을 뭉뚱그린다:

| 실제 상황 | 현재 저장 | 현재 화면 | 결과 |
|---|---|---|---|
| 소싱처가 "재고 충분(수량 표식 없음)"을 **명시적으로** 확인 | `999` | 있음 ✅ | 정상 |
| 크롤러가 재고 신호를 **못 읽음**(API 키 불일치·파싱 실패·대체상품 모호·호출 실패) | `999`/`None` | 있음 ❌ | **품절·한정이 "있음" 둔갑 = 금전 손실** |

구체 증거:
- **롯데온**: 품절 사이즈(아이보리 265/275/280)가 매트릭스에 "4개/있음" — 대체상품 가드가 숫자형 URL에서 무력화(별도 수정 완료, [[project_lotteon_substitute_guard_numeric_url]]). DOM 폴백도 `else 999`라 가짜 충분 가능.
- **무신사**(확장 추출기): 재고 API를 `productVariantId` 기준으로 받아 `invMap[it.no]`로 조회 → 키 불일치 시 `inv={}` → `remainQuantity==null` → **999 둔갑**. "마지막 N개"류 한정 표기를 별도로 안 읽음.
- **가이드 ↔ 실제 불일치**: `docs/크롤링-가이드.md` §1 재고편이 "실코드"로 **서버 크롤러**(`musinsa.py:492`, `ssg.py:608`, `lotteon.py`)를 가리키지만, 라이브 무신사·롯데온(및 스스·SSF·SSG)은 **크롬 확장 추출기**로 돈다(딴 코드). 가이드가 검증·신뢰의 기준인데 라이브 경로를 안 가리킴.

## 2. 목표 / 비목표

**목표**
- "확실히 있음일 때만 초록불, 못 읽으면 솔직하게 경고"를 **전 소싱처 공통 규칙**으로 만든다.
- 무신사·롯데온의 현재 둔갑 버그를 이 공통 규칙으로 해소.
- 가이드를 라이브 경로 기준으로 정정하고 새 상태를 반영.

**비목표(YAGNI)**
- 스스·SSF·SSG·르무통의 동작 변경(현재 양호 — "못 읽음" 경로만 공통 규칙에 편입, 정상 경로는 그대로).
- DB 스키마 신규 컬럼 추가(센티넬로 해결).
- 가격·혜택 로직 변경(재고에 한정).

## 3. 핵심 설계 결정 (사용자 확정)

1. **충분 vs 불명 분리** — `999`(충분, 명시적 in-stock)와 `불명`(못 읽음)을 별개 상태로 분리.
2. **불명의 취급** — 화면엔 **⚠️확인필요**로 표시하고, **수량은 0 취급**(품절처럼 주문·업로드·최저가 후보에서 제외). 단 라벨은 "품절"과 구분.
3. **기본값 역전** — 지금은 "애매하면 999". 앞으로는 **"애매하면 불명"**. `999`는 소싱처별 명시 신호를 증명해야만 부여.
4. **구현 방식 = 센티넬 1개 추가**(방법 ①). `current_stock`/`last_stock` 정수 칸에 **`불명 = -1`** 추가. 표시·계산·업로드는 종착지 `_resolve_stock` 한 곳에서 자동 파생.

## 4. 재고 상태 모델 (단일 진실 원천)

크롤된 옵션 재고 = 다음 중 하나:

| 값 | 상태 | 의미 | 화면 라벨 | 판매후보 |
|---|---|---|---|---|
| `0` | 품절 | 소싱처 명시 품절 신호 | 품절 | 제외 |
| `1..898` | 한정/실수량 | 수량이 수치로 드러남 | `N개` | 포함 |
| `999`(≥900) | 충분 | 소싱처가 "판매중 + 수량표식 없음" **명시 확인** | 있음 | 포함 |
| **`-1`** | **불명(신규)** | 크롤은 됐으나 **신뢰할 재고 신호를 못 읽음** | **⚠️확인필요** | **제외(0 취급)** |
| `None` | 미크롤 | 이번 런에서 아직/하드리셋 직후 안 긁음 | 미크롤 | (해당 없음) |

**불명(-1) vs 미크롤(None) 구분 필수.** None은 "안 긁음", -1은 "긁었는데 못 읽음". 종착지에서 다르게 표기.

## 5. 소싱처별 "999 받을 자격" 규칙 (추출기에 심음)

핵심: 각 추출기는 **명시적 in-stock 신호가 있을 때만 999**, 신호를 못 읽으면 `-1`(불명), 명시적 품절이면 `0`, 수치 있으면 실수량.

- **무신사(확장 `musinsaExtractor`)**
  - 재고 API(`prioritized-inventories`) 실패(`invOk=false`) → 해당 상품 전 옵션 `-1`(불명). *(현재 null→999/재고있음 둔갑 제거)*
  - API 성공 + 옵션 매칭 성공 + `outOfStock=true` → `0`.
  - 매칭 성공 + 수량 있음 → 실수량. **"마지막 N개·잔여 N개" 표기도 파싱**해 한정 반영(API에 수량 없을 때).
  - 매칭 성공 + 품절 아님 + 수량 표식 없음 → `999`.
  - **옵션 매칭 실패**(`invMap[it.no]` 미스 = 키 불일치) → `-1`(불명). *(현재 999 둔갑의 직접 원인)* — 매칭 키(`it.no` ↔ `productVariantId`)가 실제로 맞는지 라이브 확인 후, 안 맞으면 올바른 조인 키로 교정.
- **롯데온(확장 `lotteonExtractor`)**
  - API 매핑: `SALE && stkQty>0` → 실수량 / 비SALE·대체상품(spdNo 다름) → `0` / 키 없음 → 제외(미존재).
  - DOM 폴백: 명시 품절 → `0` / "N개 남음·마지막 N개" → 실수량 / **명시 in-stock 확인 가능할 때만 999, 아니면 `-1`(불명)**. *(현재 `else 999` → 불명으로)*
  - 대체상품 가드 숫자형 URL 무력화는 수정 완료([[project_lotteon_substitute_guard_numeric_url]]).
- **SSF·SSG·스스·르무통(현재 양호)**: 정상 경로(실수량/명시품절/명시충분) 유지. **"파싱/호출 실패·옵션 매핑 실패" 경로만 999/조용한skip → `-1`(불명)** 으로 통일. 동작 회귀 없도록 정상 케이스는 불변.

## 6. 서버 변경 (origin/main = 라이브)

- **`_resolve_stock`** (`webapp/routes/api_pricing.py:142`)
  - `-1` 분기 추가 → `(0, '⚠️확인필요', True)` (수량 0·판매제외·라벨 구분). `stock_out=True`로 최저가/업로드 자동 제외.
  - `None` 분기 재검토 — "미크롤"은 매트릭스가 status/last_fetched로 이미 구분하므로 `_resolve_stock(None)`이 "재고있음"으로 새지 않도록 정합성 확인(필요 시 미크롤 전용 라벨로).
- **`_persist_option_stocks`** (`api_pricing.py:143`) — `-1`은 정수라 그대로 영속됨(품절 0과 동일하게 "반드시 기록"). 단 **불명이 멀쩡한 옛값을 덮어 깜빡이지 않도록**, 불명 판정은 추출기 재시도(§7) 후에만 내림.
- **`save_crawl_result`** (`api_pricing.py:1011`, `_persist_option_stocks` 호출부) — 확장 `options[].stock`의 `-1`을 그대로 통과(현 로직이 int 통과라 OK), 검증만.
- **상품레벨 `last_stock`** — 옵션 전부 불명이면 상품 요약도 불명 신호 반영(매트릭스 상품 카드 정합).

## 7. 일시 실패 방어 (flaky → 불명 깜빡임 방지)

- 추출기는 즉시 불명 처리 금지. 재고 API/파싱을 **2~3회 재시도(백오프)** 후에도 못 읽을 때만 `-1`.
- 무신사는 이미 `goodsPrice` 3회 재시도 패턴 보유 — 재고 API에도 동일 적용.
- 재시도해도 불명이면 불명을 **영속**(옛값 유지로 가짜 재고 끌어쓰기 금지 — §원칙 ①·②).

## 8. 표시 / 계산 / 업로드 (자동 파생)

`_resolve_stock` 한 곳 수정으로 아래가 자동 반영:
- **매트릭스 셀**: ⚠️확인필요(노랑/경고색, 품절과 구분).
- **최저가(★)·`_pick_cheapest_buyable`**: `stock_out=True`라 후보 제외.
- **업로드 게이트**: 재고 0 취급이라 판매중단/제외.
- **매트릭스 보기 > 로그**: 불명도 한 상태로 표기.

## 10. 검증 (라이브 필수)

- 무신사·롯데온 **실제 상품**으로 크롤 후 **매트릭스 vs 실제 페이지** 대조: 품절=품절, 한정=N개, 못 읽은 옵션=⚠️확인필요로 뜨는지.
- 확장 수정은 **리로드+재크롤** 후에만 라이브 반영(데스크톱 로드 사본 + 사용자 reload).
- 회귀 테스트: 롯데온 가드 테스트(`scripts/test_lotteon_substitute_guard.js`) 패턴으로 무신사 매칭·불명 분기도 순수함수 테스트 추가.

## 12. 리스크

- **불명이 멀쩡한 재고를 덮어 판매 누락** → §7 재시도로 완화. 잔존 시 ⚠️가 사람에게 보여 복구 가능(사용자 선택 = 안전 우선).
- **무신사 매칭 키 가설 미확정** — `it.no ↔ productVariantId` 실제 관계를 라이브로 먼저 확인(못 하면 불명이 과다 발생). 검증 단계에서 확정.
- **확장 2버전 분열**(main 0.4.4 / 데스크톱 0.6.x) — 데스크톱 사본을 단일 라이브로 취급.
