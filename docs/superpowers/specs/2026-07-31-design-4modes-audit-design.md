# 디자인 4타입 — 이름 변경·드롭버튼·전수 가독성 감사 (설계)

작성 2026-07-31 · 사장님 승인 완료 · 작업방 `C:\dev\_wt_dsaudit` (origin/main 기준)

---

## 1. 배경

디자인 4모드가 PR#563 으로 들어갔고, 이후 3차에 걸쳐 어두운 화면 대비를 고쳤다.
그런데 그 측정이 **`/orders` 한 화면에서만** 이뤄졌다. 화면은 약 90개, 템플릿은 163개다.
나머지 화면은 아무도 안 재봤고, 사장님이 실제로 다음을 발견했다.

- 검정A·B 타입인데 흰 카드 디자인이 그대로 남은 곳 (예: 마진계산기)
- 검정 배경에 검정 글씨가 겹쳐 안 보이는 곳
- 넓은 표에서 **화면 틀 자체가 좌우로 밀리는** 현상 (예: 주문관리)

## 2. 목표

1. 4타입 이름을 사장님이 쓰는 말로 바꾼다.
2. 타입 전환을 드롭버튼 하나로 통일하고 화면 최우측 최상단에 고정한다.
3. 위 3가지 결함을 **눈이 아니라 기계로** 전 화면에서 찾아 고친다.
4. 「기존 타입」은 한 픽셀도 안 바뀐다 — 안전망이 훼손되면 되돌릴 길이 사라진다.

기준은 애플 코리아 실측값(`docs/디자인-규칙.md`, 정본). 대비 합격선 4.5.

## 3. 하지 않는 것 (YAGNI)

- 새 디자인 타입 추가
- 내부 값(`current`/`mono`/`layer`/`light`) 변경 — 사람마다 저장된 취향이 날아간다
- 디자인 규칙 자체의 재정의 — 이미 정본이 있다
- 감사와 무관한 리팩터링

## 4. 설계

### 4.1 이름 변경 — 단일 원천 한 곳

`webapp/design_mode.py` 의 `MODES` 딕셔너리가 표시명의 유일한 출처다.
사이드바·상단탭·내 계정 세 화면이 모두 이 값을 읽어 그린다.

| 내부 값 (불변) | 지금 표시명 | 바뀔 표시명 |
|---|---|---|
| `current` | 현재 | **기존 타입** |
| `mono` | 검정 한 판 | **검정A 타입** |
| `layer` | 검정 3단 | **검정B 타입** |
| `light` | 밝은 카드 | **화이트 타입** |

설명 문구도 새 이름에 맞춰 다듬는다. `tests/design/test_design_mode.py` 가 표시명을
문자열로 검사하므로 함께 갱신한다.

### 4.2 드롭버튼 — 공용 부품 1개, 오른쪽 위 붙박이

새 파일 `webapp/templates/partials/design_mode_menu.html`.

- **자리**: `position: fixed`, 화면 오른쪽 위. 4타입 어디서든 같은 자리, 스크롤해도 따라온다.
- **평소**: 현재 타입 이름만 보이는 작은 버튼.
- **누르면**: 4줄 목록이 아래로 펼쳐진다. 줄마다 이름 + 설명 한 줄. 현재 것에 체크 표시.
- **동작**: 지금과 같은 `POST auth.set_design_mode`. JS 는 여닫기만 담당하고,
  JS 가 죽어도 목록이 `<details>` 로 열려 선택은 가능해야 한다(전환은 폼 제출).

**안전망 규칙 — 이 부품만은 디자인 토큰을 쓰지 않는다.**
토큰이 망가져 화면이 안 보이게 됐을 때 「기존 타입」으로 돌아올 유일한 통로다.
색·크기를 전부 고정 hex 로 박아, tokens.css 가 어떻게 되든 항상 읽힌다.
(지난번에도 `--ink` 가 다크에서 밝은 값이 되는 바람에 되돌리기 버튼 자체가 안 보인 사고가 있었다.)

교체 대상 3곳:
- `partials/sidebar.html` 의 `.sb-designmode` 블록 → 삭제하고 공용 부품 사용
- `partials/topnav.html` 의 `.tn-dm` 블록 → 삭제하고 공용 부품 사용
- `auth/me.html` 의 라디오 목록 → 공용 부품 사용

부품 자체는 `base.html` 에서 한 번만 포함하고, 세 곳의 중복 마크업을 걷어낸다.
(같은 것을 세 번 적으면 다음에 또 갈라진다.)

### 4.3 가로 넘침 — 원인 확정

`webapp/static/toss.css:247`

```
.main { flex: 1; padding: 40px clamp(16px, 2vw, 44px); }
```

`min-width: 0` 이 없다. flex 자식의 기본 최소폭은 `auto` = **내용물 폭**이라,
넓은 표가 `.main` 을 밀어 넓힌다 → `.app` 이 커진다 → 문서 전체가 가로로 밀린다.
그래서 사이드바까지 딸려 움직인다.

`webapp/static/topnav.css:171` 의 상단탭 경로에는 `min-width: 0` 이 이미 있다.
그래서 타입마다 증상이 다르게 나타났다.

**고침 2겹**

1. 바깥 틀이 폭을 붙잡는다 — `.main { min-width: 0 }`, `.app { max-width: 100% }`,
   그리고 문서 가로 넘침 자체를 차단.
2. 안쪽 상자가 스크롤을 갖는다 — 넘치는 표를 감싼 상자에 `overflow-x: auto` 가
   실제로 붙어 동작하는지 **실측으로** 확인. 주문관리 `#tablewrap` 은 선언은 있는데
   1번이 없어 무력화돼 있었다.

회귀 방지: 감사기가 「문서 폭 > 창 폭」을 항상 검사하므로, 다시 생기면 잡힌다.

### 4.4 실브라우저 자동 감사기

`프로그램/_시스템/scripts/design_audit_live.py` (저장소에 남긴다 — 재실행 가능해야 한다).

**돌리는 방식**: 화면 목록 × 타입 4종을 순회하며 각 페이지에서 측정 JS 를 실행한다.
화면 목록은 Flask `app.url_map` 에서 인자 없는 GET 라우트를 뽑아 만든다(약 90개).

**한 페이지에서 재는 것**

| 측정 | 잡히는 결함 | 판정 |
|---|---|---|
| 글자색 ↔ 실제 겹친 배경색 대비 | c. 검정 글씨 안 보임 / d. 흐린 글자 | < 4.5 미달 |
| 배경 밝기 vs 타입 | a. 검정 타입에 흰 카드 잔재 | 어두운 타입인데 밝기 높음 |
| `documentElement.scrollWidth > clientWidth` | b. 화면 통째로 밀림 | 초과하면 실패 |
| font-size / font-weight / 여백 / 둥글기 | d. 애플 규칙 이탈 | 정본 허용값 밖 |

**정확도 핵심 — 배경은 역산해야 한다.**
배경이 반투명이면 요소의 `background-color` 만 읽어선 안 된다. 조상 쪽으로 올라가며
알파를 합성해 **눈에 실제로 보이는 색**을 구한다. 지난 실측에서 이걸 안 하면 대비가
16.9 인데 1.09 로 잘못 나오는 것을 확인했다.

**출력**: `_design_audit/<타입>.json` (원자료) + 사람이 읽는 요약(화면별 결함 수·최악 사례).

## 5. 안전 장치

- 작업방은 `origin/main` 기준 워크트리. 로컬 가지는 낡아 파일이 아예 없었다.
- 색 고침은 전부 `var(--토큰, 원래색)` 예비값 방식 — 「기존 타입」에는 토큰이 없으므로
  원래색으로 떨어져 무손실.
- **무손실 증명**: 감사기로 「기존 타입」 전 화면을 작업 전/후 측정해 차이 0 을 확인한다.
  주장이 아니라 측정으로 증명한다.
- 테스트는 이 저장소 특성상 전체 실패 개수가 널뛴다(공유 SQLite 오염). 판정은
  **실패 파일 목록을 작업 전 워크트리에서 같은 파일만 돌려 대조**한다.
- `margin_embed.html` 은 스윕 도구 대상에서 제외.
