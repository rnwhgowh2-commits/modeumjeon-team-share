## 1. 목적 (Why)

사무실 까대기 발송 워크플로에서 사람이 놓치는 3가지를 프로그램이 잡아준다.

1. **중복 송장** — 이미 송장번호가 입력된 주문건을 며칠 뒤 실수로 다시 뽑는 것.
2. **배송흐름 미발생** — 송장은 입력했지만(현지배송완료로 필터 변경) 실제로는 소싱처 품절·지연으로 배송흐름이 안 뜨는 주문. 전수검수를 안 하므로 놓치기 쉬움.
3. **배송방식 구분** — 각 주문이 "까대기(사무실 경유 재포장)"인지 "직배(소싱처 직접배송)"인지 한눈에 관리.

### 현장 워크플로 (배경)
- 주문 수집·관리 원장은 외부 프로그램 **더망고 솔루션**. 우리 프로그램은 그 위에 얹는 **검사·보조 도구**.
- 흐름: (1) 더망고가 마켓 주문 수집 → (2) 소싱처에서 까대기 주문을 사무실로 → (3) 상품 도착·까대기 → (4) 취소/교환 제외한 2~3일 전 주문건 기준 송장 미리 출력 → (5) 송장번호 입력 → (6) 더망고에서 구분자 변경(해외현지배송중 → 현지배송완료; 중복출력 방지) → (7) 포장.
- "구분자(해외현지배송중·현지배송완료 등)"는 배송 단계를 나누는 라벨일 뿐 의미는 무관하며 **언제든 명칭이 바뀔 수 있다.**

## 2. 범위 (Scope)

**포함**
- 더망고 주문내역 엑셀(.xls) 업로드·파싱·DB 누적 저장
- 구분자(더망고주문상태) 매핑 설정: 기본셋팅 제공 + 편집 가능
- 검사 2종: (a) 중복송장여부, (b) 배송흐름 미발생
- 배송방식 열(까대기/직배/미지정): L매핑 자동 + 업로드 일괄지정 + 행별 수기 드롭
- 주문내역 안 신규 하위탭 "배송검사"

**제외 (YAGNI)**
- 택배사 송장추적 API 직접 연동(스윗트래커 등) — 배송흐름은 마켓 API 주문상태로 판단
- 송장 자동 전송/출력 — 본 기능은 "검사"만. 실제 송장전송은 기존 별도 기능
- 마진 계산 — 별도 마진계산기 스펙 소관

## 3. 접근 방식 결정

| 방식 | 내용 | 채택 |
|---|---|---|
| **A. 엑셀 업로드=원장, DB 누적** | 업로드 시 DB upsert. 배송방식·수기수정 저장. 날짜 가로지른 중복탐지 가능. API는 보강. | ✅ **채택** |
| B. 마켓 API 실시간 중심 | 엑셀 보조. 계정 순차조회 느림, 크로스데이 누적 중복탐지 약함. | ❌ |
| C. 무저장(그 자리 계산) | 수기지정이 새로고침 시 소멸, 전날 대비 중복탐지 불가. | ❌ |

**크로스데이 누적이 필수** — "전날 뽑은 송장을 다시 뽑는가"를 잡으려면 업로드 이력을 DB에 남겨야 하므로 방식 A.

## 4. 데이터 원천: 더망고 엑셀 실측 (2026-07-11 샘플 425행)

**중요**: `.xls` 확장자지만 실체는 **HTML을 위장한 파일 + 동반 폴더**(`{이름}.files/sheet001.htm`에 실제 표). 껍데기 .xls는 프레임셋. 파서는 openpyxl→xlrd 실패, **BeautifulSoup(html) 경로 필수**. 인코딩 utf-8, 셀 안에 `\r\n  ` 개행 다수.

- L에는 "현지배송완료" 리터럴이 없고 "국내배송중/배송완료"가 있다. 구분자 명칭은 가변 → **설정으로 분리**한다(하드코딩 금지).
- N의 "까대기"는 425건 중 4건 자유입력뿐 → 배송방식 자동판정의 1차 기준으로 부적합. 배송방식은 L매핑을 기본으로 한다.

## 6. 배송방식 판정 (우선순위)

```
delivery_method =
  1) 수기 지정값        (delivery_method_source='수기')  ← 최우선, 재업로드로도 안 덮임
  2) 업로드 일괄지정값  (이번 업로드에 "전부 까대기/직배" 선택 시)
  3) L매핑 default_method (MangoStatusMap)                ← 자동 기본
  4) 미지정
```

- (c) 행별 수기 드롭다운: 까대기 ↔ 직배 ↔ 미지정. 변경 시 즉시 저장 + source='수기'.
- (e) 업로드 일괄지정: 업로드 화면에서 "이 파일 전부 [까대기|직배|자동판정]" 선택. source='일괄'(또는 자동판정 선택 시 source='자동').

## 7. 검사 로직 2종

### (a) 중복송장여부
- **정의**: 동일 주문(`mango_uid` P, 보조로 `market_order_no` C)이 **이미 `invoice_no`(K)를 가진 상태**로 존재하는데, 새 업로드/현재 목록에서 다시 송장출력 대상으로 잡히는 경우.
- **판정**:
  - 같은 `mango_uid`가 서로 다른 송장번호로 2회 이상 관측 → **중복(강)**.
  - `invoice_no`가 이미 채워진 주문이 "송장 미출력 대상 필터(예: 해외현지배송중)"에 다시 나타남 → **중복 의심(약)**.
- **출력**: 배송검사 탭에 "중복송장" 배지 + 목록. 왜 중복인지(같은 고유번호/기존 송장번호 K) 근거 표시.
- 엑셀만으로 100% 판정 가능(주소·API 불필요).

### (b) 배송흐름 미발생
- **정의**: 구분자가 `is_flow_check_target=True`(배송완료류 = 송장 넣고 현지배송완료로 넘긴 단계)인데, 실제 배송흐름이 안 뜨는 주문.
- **판정 신호**:
  - `market_status`(M)가 `송장전송실패` → 강한 신호.
  - `invoice_no`(K) 있음 + L이 배송완료류인데 M이 진척 없음(특이사항없음 등 정지) → 의심.
  - (선택 보강) 마켓 API 주문상태 조회로 배송단계 확인 — 기본은 엑셀 M열로 판단, API는 후속 옵션.
- **출력**: "배송흐름 없음/실패" 목록 → 소싱처 확인·CS 대응 대상.

## 8. 화면 (UI) — 신규 하위탭 "배송검사"

`/orders?tab=` 에 `delivery-check`(라벨 "배송검사") 추가. 구성 요소:
1. **더망고 업로드 영역** — 파일 선택 + 일괄 배송방식 지정 + 업로드.
2. **구분자 매핑 설정** — L값 ↔ 의미·배송방식·flow대상 편집 표.
3. **주문 목록 표** — 마켓·수령인·상품·송장번호·구분자(L)·마켓상태(M)·**배송방식(드롭)** + 검사 배지(중복송장/배송흐름없음).
4. **검사 요약** — 중복 N건 / 배송흐름 없음 N건 필터 토글.

> **디자인 게이트 완료 (2026-07-11)** — 각 5안 시안(바탕화면 「모음전 시안_배송검사탭 v1.html」) 후 사용자 확정:
> 1. 배송방식 열 → **토글 칩** (까대기 ↔ 직배, 미지정=회색 양쪽)
> 2. 더망고 업로드 → **카드형 드롭존** (끌어놓기 + 일괄방식 세그먼트 + 업로드)
> 3. 구분자 매핑 설정 → **설정 모달** (표 위 ⚙ 버튼 → 팝업 편집)
> 4. 업로드 시 일괄 지정 → **라디오 3택 카드** (자동판정/전부 까대기/전부 직배, 기본=자동판정, 수기값 보존 안내)
> 5. 검사결과 → **요약카드 + 필터 + 통합표** (중복송장·배송흐름없음·정상 건수 카드 → 클릭 필터, 근거 열)
> - **공통 색규칙**: 정상=초록(success) · 중복송장=빨강(danger) · 배송흐름없음=노랑(warning) · 까대기=주황계열 · 직배=파랑(primary)

## 9. 파서 설계 (더망고 .xls)

```
def parse_mango_xls(file_or_bytes) -> list[dict]:
    # 1) 프레임셋 .xls면 동반 폴더 {name}.files/sheet001.htm 사용
    #    업로드는 단일 파일이므로: 업로드된 파일이 sheet001.htm(실표)인지,
    #    프레임셋 껍데기인지 감지. 껍데기면 사용자에게 "실제 표 파일 필요" 안내.
    # 2) utf-8 디코드 → BeautifulSoup(html.parser)
    # 3) tr 순회, td>=16인 행 수집. 첫 행=헤더 검증(마켓주문일자…더망고주문고유번호)
    # 4) 셀 내 \r\n\s+ 정규화. 컬럼 인덱스 고정(A~P) + 헤더명 이중검증
    # 5) dict per row → MangoOrder upsert
```

**업로드 방식 결정 필요(시안/구현 시)**: 사용자가 브라우저로 올리는 파일이 껍데기 .xls면 표 데이터가 동반 폴더에 있어 단일 업로드로 안 잡힘. → **권장: 사용자에게 "sheet001.htm 또는 폴더 zip" 업로드 안내**, 또는 껍데기 감지 시 명확한 오류 메시지. (거짓 성공 금지 — 정합성 원칙)
