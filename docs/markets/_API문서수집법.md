# 판매처 API 문서 수집법 — 접수 경로 × 신뢰도 매트릭스 · 전체 탭 계층 · 플레이북

> **계층**: 프로젝트 문서 (도메인 지식 SOT)
> **책임**: 판매처(오픈마켓) 공식 API 문서를 「데이터 코드 지도」에 접수할 때, 마켓별로 **어느 경로를 어떤 순서로 시도해야 가장 잘 뚫리는지** + **문서 포털의 전체 탭 계층(상위탭 > 가로 하위탭 > …)**을 실측·분류
> **최종 렌더 목적지**: 인앱 `판매처관리 › 데이터코드지도 › API문서수집법` 탭 (본 문서 = 그 데이터 원본)
> **원칙**: 날조 금지 · 실측만 "가능" · robots·약관 준수 · 인증 URL 노출 금지 · 첨부에만 있으면 위치만 기록(값 창작 금지)
> **최종 실측일**: 2026-07-17 — **6대 마켓 전부 공식 접수 완료(611 apis)**. 신규 경로 **I(로그인 콘솔 스니펫)** + **A-2(신규 정적 이관본)** 실증 반영.

---

## 1. 왜 필요한가

- 마켓 공식 API 문서를 「데이터 코드 지도」에 접수해두면 새 기능 만들 때 F12 반복 노가다 없이 지도만 보고 구현한다.
- 마켓마다 문서 접근 경로가 **전부 다르다**. 실측 결과 6개 마켓이 **6가지 다른 경로**로 뚫렸다.
- 마켓이 수십 개로 늘면 **"어느 경로를, 어떤 순서로"**를 미리 알아야 빠르고 빠짐이 없다. → §6 플레이북이 이 문서의 핵심.

### 💡 이번 실측이 뒤집은 통념 2가지 (가장 중요)
1. **"SPA라 차단 = 끝"이 아니다.** 마켓이 문서를 **신규 정적 사이트로 이관**해뒀을 수 있다.
   → 스마트스토어: 옛 `/ko`(Angular SPA·정책차단) ❌ 이지만 **신규 `/docs`(Docusaurus 정적) ✅ 전량 관통**. 같은 도메인, 경로만 다름.
2. **"로그인 게이트 = 사람이 다 복붙"이 아니다.** 사용자가 **로그인한 탭 콘솔에 스니펫 1회**만 붙여넣으면 전 페이지가 자동 수집된다.
   → 11번가: 붙여넣기 1회 → 26페이지 크롤 → 구조화 스펙(jsonData) → 파일 다운로드 → Claude가 읽어 25 API 접수.

## 3. 접수 경로 도구상자 (A ~ I)

| 코드 | 방법 | 특징·기법 | 한계 |
|---|---|---|---|
| **A** | `fetch` MCP (`mcp__fetch__fetch`) | ★C의 안전차단을 우회. **SSR 사이트 관통**. `raw=true`로 HTML/href 열거, `start_index` 이어읽기, 기본 markdown은 표·본문 깔끔 | robots `Disallow` 차단 · **클라이언트렌더 SPA(`<app-root>`만)는 빈 껍데기** · 프롬프트 인자 없음(내용만 반환) |
| **A-2** | ★**신규 정적 이관본 탐색** (A의 하위기법) | **옛 포털이 SPA·차단이어도 신규 문서가 정적 사이트일 수 있다.** 판별=`fetch raw`에 `Docusaurus`/`Redoc`/`Mintlify` generator meta·정적 마크업. **열쇠 = `<docs루트>/sitemap.xml`로 전 페이지 열거** | Docusaurus+OpenAPI 플러그인은 **오퍼레이션 본문이 클라이언트 렌더(스켈레톤)** → 필드는 **구조체(`/schemas/`) 페이지**(서버렌더 완전)에서 확보 |
| **B** | `WebFetch` 툴 | A와 **다른 구현** — A가 robots에 막혀도 B는 통과할 때가 있음(11st 실측). 프롬프트로 요약·추출 가능 | 일부 도메인 자체 차단(apicenter) · 인증 페이지 실패 |
| **C** | `claude-in-chrome` (사용자 실제 크롬) | SPA도 navigate+JS/DOM 추출로 구동. 로그인 세션 활용. 네트워크 XHR 관찰(E 겸용) | **일부 도메인 안전정책 차단**(쿠팡·스스·11번가·네이버) — **로그인해도 안 풀림**(차단=도메인 정책) · 탭ID 세션중 변동 |
| **D** | 우리 어댑터 코드 + `docs/markets/*.yaml` | **라이브 왕복검증된 엔드포인트 = 신뢰도 최상 ①** | "우리가 쓰는 API"만(전체 카탈로그 아님) |
| **E** | SPA 백엔드 JSON API 발견 | SPA가 부르는 문서 데이터 JSON 직격(번들 분석·네트워크 패턴) | 데이터가 번들에 baked면 없음 · 안전차단 도메인은 XHR 관찰 불가 · **실측 3마켓 모두 실패** |
| **F** | 기계판독 스펙·공식 저장소 | OpenAPI/Swagger JSON, sitemap, 공식 GitHub(Wiki·docs·릴리즈노트) | 배포 안 했으면 없음 · ⚠️`naver/naver-openapi-guide` swagger=**Clova/검색(커머스 아님)** 혼동주의 · commerce-api repo=지원공간(스펙 없음) |
| **G** | 사용자 복붙 | 최후 수단 | 사람 반복노동 → **I로 대체하라** |
| **H** | 공식 블로그/외부 도메인 | ★마켓이 공식문서를 **별도 블로그/도메인**에 두는 경우(ESM=Tistory `etapi.gmarket.com`). SSR이라 A로 관통·`/category`로 글 열거 | 공지가 API문서와 섞임 → **`[METHOD]`+URL 유무로 선별** |
| **I** | ★**로그인 세션 콘솔 스니펫** (신규) | **로그인 게이트 + A·C 전부 막힘일 때의 정답.** 사용자가 로그인한 탭 콘솔에 **1회 붙여넣기** → 같은출처 `fetch(credentials:'include')`로 전 페이지 크롤 → 구조 추출 → **Blob 파일 다운로드** → Claude가 다운로드 폴더를 `Read` | 사용자 1회 개입 필요 · **인코딩 함정**(§3-1) · 페이지 구조 사전파악 권장 |

### 3-1. 경로 I 표준 절차 (11번가 실증 · 재사용 템플릿)

1. **구조 사전 파악**: 가능하면 `B(WebFetch)`로 비로그인 페이지를 먼저 열어 **프레임 유무·메뉴 링크 패턴**(예: `?categoryNo=N`)·필드가 표인지 목록인지 확인 → 스니펫을 그 구조에 맞춘다.
2. **스니펫 설계 원칙**
   - **같은출처 fetch + `credentials:'include'`** (사용자 세션 쿠키 사용, 우리는 쿠키를 만지지 않음)
   - **링크 자동 발견 후 BFS 크롤**(사용자가 페이지마다 클릭할 필요 0)
   - ⚠️ **인코딩**: 옛 한국 사이트는 **EUC-KR**. `response.text()`는 UTF-8로 디코딩해 **한글이 U+FFFD로 깨지고 복구 불가**. → **반드시 `arrayBuffer()` + `new TextDecoder('euc-kr').decode(buf)`**. (11번가 1차 실패 원인 = 이것 하나)
   - **구조화 데이터 우선**: 페이지가 `var jsonData = {...}` 같은 **스펙 객체**를 품고 있으면 표 파싱 말고 **브레이스 워크로 통째 추출**(가장 정확). 없으면 표(cell 배열)+본문 텍스트 통째로.
   - **출력 = 채팅 붙여넣기 ❌ / Blob 파일 다운로드 ✅** (용량 제한 없음, Claude가 `C:\Users\<user>\Downloads\*.json`을 직접 Read)
   - **자가진단 로그**: `console.log(페이지수 + 제목목록)` → 사용자가 숫자만 불러주면 성공/보완을 즉시 판단
3. **파싱은 Claude가 파일에서** (사용자는 재작업 0). 구조화 JSON이면 **결정론적 파서**(서브에이전트 불필요).
4. **실패 시 안전망**: ① 숫자 이상 → 스니펫만 고쳐 재붙여넣기(수초) ② 최후 → 브라우저 `Save all as HAR` / `웹페이지 전체 저장`.

## 5. 마켓별 전체 탭 계층 (실측)

> 표기: `상위탭` → `하위탭(가로)` → `상세 탭`. 각 마켓 문서 포털을 실제로 열어 확인.

### 쿠팡 — A(fetch) 완전 ✅ · 108 접수
- 문서: `https://developers.coupang.com/ko/api` (Next.js SSR).
- **상위탭**: 홈 · 시작하기 · **API 문서** · FAQ · 공지사항 · 지원(wing) · Travel API(별도 포털).
- **API문서 > 11 패밀리 > 100 엔드포인트**: 상품(22)·카테고리(6)·브랜드(3)·배송/주문(12)·반품(7)·교환(4)·프로모션쿠폰(21)·물류(8)·고객문의(6)·정산(2)·RocketGrowth(9).
- **엔드포인트 상세 탭**: 요약·상세·경로·요청·응답·오류 → **②**.
- **시작하기 > 18 가이드**(별도 접수 8): HMAC 서명(`CEA algorithm=HmacSHA256`, msg=datetime+method+path+query, `yyMMddTHHmmssZ`) · **ID모델**(sellerProductId/productId/vendorItemId/externalVendorSku) · Key발급(유효 180일) · 필수옵션 조건(MANDATORY/groupNumber/exposed).
- ⚠️ VOC 사유코드 = XLSX 첨부(인라인 없음) → 첨부 위치만 기록(값 창작 금지).

### 롯데온 — C(실크롬) 완전 ✅ · 115 접수(109 상세)
- 문서: `https://api.lotteon.com/apiService/` (Nuxt SPA). A/B 빈껍데기, C는 정상(안전차단 아님).
- **좌측 13 카테고리**: 시작하기·거래처·상품속성·상품·판촉·주문·클레임·고객센터·배송·정산·공통·전시·스마트픽.
- **상세 탭**: 요청·응답·사유코드 + API 변경이력 → **②**.
- 접근법: `?apiNo=N&menuIdx=4` 이동 → **1초 대기** → 테이블 JS 추출(**1 API/1 콜**; 다중배치는 SPA 렌더 전 추출로 실패).
- ⚠️ 판촉 6개 = **사이트 자체가 렌더 안 함**(죽은 페이지) → 인덱스만.

### 옥션·G마켓(ESM) — A + H(공식 블로그) 완전 ✅ · 각 117 접수
- 문서: `https://etapi.gmarket.com/` = **Tistory 공식 블로그**. SSR → A 관통.
- **상단 메뉴**: 공지 · API가이드 · 상품 · 주문|배송 · 클레임 · 정산조회 · CS · 서비스 · 스타배송 · Q&A → **23 리프 카테고리 · API 글 117**.
- **글 상세**: Description(`[METHOD] sa2.esmplus.com/...`) · Request표 · Response(JSON Success/Fail) · 사유코드 → **②**.
- **선별 규칙(H)**: `[METHOD]`+URL 있으면 API, 없으면 공지 → 제외 (198글 중 117이 API).
- 인증 = JWT(HS256), `ssi="A:{판매자ID}"`(옥션)/`"G:{...}"`(G마켓). **옥션·G마켓 공통 API** → 1회 추출 후 양 마켓 복제(fnKey 공유).
- ⚠️ 실시간 가격/재고(`/86`·`/87`·`/84`)는 **판매자 호스팅 콜백**(조회 API 아님) → st=off 정직표기.

### 스마트스토어(네이버 커머스) — ★**A-2(신규 정적 이관본)** 완전 ✅ · 129 접수
- ❌ **옛 포털** `apicenter.commerce.naver.com/ko` = Angular SPA + **도메인 안전차단**(fetch=껍데기, WebFetch·인앱브라우저·실크롬 전부 차단). E(번들 JSON) 실패.
- ✅ **신규 포털** `apicenter.commerce.naver.com/docs/commerce-api/current` = **Docusaurus v3.7 정적사이트** → **fetch 완전 관통**(사용자 개입 0).
- **열쇠**: `/docs/sitemap.xml` → 현재버전(2.82.0) **171 페이지** 열거. (버전 드롭다운: current=2.82.0, 2.81.0 …)
- **상위탭**: 소개 · **커머스API** · 변경이력(GitHub Discussions) · 솔루션 가이드.
- **좌측 카테고리**: 인증(OAuth2) · N배송(sku) · 문의 · 상품 · 정산 · 주문 · 클레임 … → **오퍼레이션 115 + 공용 구조체 14 + 랜딩 42**.
- **페이지 2종 (★중요)**
  - **구조체 `/schemas/*`** = **서버렌더 완전** → 필드명·타입·required·`Possible values:[...]`·예시JSON **전량 확보** ②
  - **오퍼레이션** = method·path·설명·응답/에러코드는 서버렌더 ✅, **요청/응답 본문은 openapi-explorer 위젯이 클라이언트 렌더(스켈레톤)** ❌ → 본문 필드는 **구조체 참조**로 보완
- ⚠️ F 헛다리 주의: `naver/naver-openapi-guide` swagger = **Clova/Papago/검색**(커머스 아님) · `commerce-api-naver/commerce-api` = 지원공간(Discussions·Wiki, 스펙 파일 없음) · wikidocs 가이드북 = 403.

### 11번가 — ★**I(로그인 콘솔 스니펫)** ✅ · 25 접수
- ❌ `openapi.11st.co.kr` robots `Disallow: /` → A 금지(우회 안 함). C 안전차단. **B(WebFetch)는 사이트 열림** → 구조 파악엔 사용(공개=일반 Open API만, **셀러 API 상세는 로그인 게이트**).
