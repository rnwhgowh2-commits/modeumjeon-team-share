# 대량등록 ↔ samba-wave 연동

모음전의 대량등록(소싱처 수집) 기능을 앞으로 samba-wave(별도 시스템)로 대체한다.
두 시스템은 독립적으로 운영하되, 판매처 계정만 공유한다.

## Language

**대량등록**:
모음전에서 소싱처를 크롤링해 상품을 모아 오는 기존 기능(`/bulk?tab=collect`). samba-wave 도입 후 이 자리를 대체한다.
_Avoid_: 일괄등록, bulk

**samba-wave**:
사용자가 다른 사업(리셀 — 이베이·크림·스니커덩크 등)에 쓰던 별도의 상품수집·판매관리 플랫폼. FastAPI+Next.js, 원저작자(`sbk0674-web`)의 저장소를 fork. 모음전과 별도로 배포·운영한다.
_Avoid_: 대량등록과 같은 뜻으로 섞어 쓰지 않는다 (기능명이 아니라 시스템명)

**판매처(Market)**:
상품을 파는 쪽 채널 — 쿠팡·11번가·옥션·G마켓 등. samba-wave 의 `market_type`.

**소싱처(Source)**:
상품을 사입/수집해 오는 쪽 사이트 — 무신사·롯데온·SSG 등. 대량등록/samba-wave collector 가 긁어오는 대상.
_Avoid_: 판매처와 혼동 금지 — 방향이 반대다 (소싱처=사입, 판매처=판매)

**판매처 계정(Market Seller Account)**:
특정 판매처에 대한 로그인/API 자격증명(키·시크릿·OAuth 토큰) 한 벌. 두 시스템이 공유하는 유일한 데이터. samba-wave 의 `samba_market_account` 스키마가 표준이 되고, 모음전은 자체 방식(플랫폼별 파일 캐시 — `shared/platforms/*/token_store.py`)을 이 표준에 맞춰간다.
_Avoid_: 셀러 계정, API 키(더 좁은 뜻)

## Relationships

- **모음전**과 **samba-wave**는 서로 독립적으로 배포·운영되는 별개 시스템이다 (다른 스택, 다른 배포 대상)
- 단, 둘은 같은 **판매처 계정** 집합을 공유한다 — samba-wave 의 스키마가 기준(source of truth)이고 모음전이 따라간다
- **판매처 계정**은 하나의 **판매처**에 속한다 (market_type 당 다중 계정 가능, `is_default` 로 우선순위)
- **대량등록**(모음전 기존 기능)은 samba-wave 도입 후 대체 대상. 유사 기능(수집·소싱 로직)은 향후 "효율적인 방법 비교" 후 통합을 검토하되, 지금은 통합하지 않는다

## Example dialogue

> **Dev:** "대량등록 탭을 없애고 samba-wave 화면으로 연결하면, 로그인도 같이 합쳐야 하나요?"
> **사장님:** "아니, 완전 독립적으로 생각하면 돼. 로그인 말고 판매처 계정만 공유할 거야 — 그것도 samba-wave 형식을 모음전이 따라가는 거지, 반대가 아니야."
> **Dev:** "지금 소싱처 7곳 긁어오는 대량등록이랑, samba-wave collector 랑 겹치는 부분은요?"
> **사장님:** "겹치는 거 많은 거 알아. 그래도 지금은 그냥 둘 다 따로 두고, 나중에 뭐가 더 효율적인지 비교해서 합칠 거야."

## Flagged ambiguities

- "판매처 계정 공유"가 (a) 두 시스템이 같은 DB 테이블을 직접 보는 것인지, (b) samba-wave 가 API 로 내주고 모음전이 읽어오는 것인지 — STEP 2b 매핑 단계에서 결정
- "대체"의 범위 — 모음전 사이드바의 "대량등록" 항목을 지우고 samba-wave 화면(별도 주소)으로 안내만 하는 것인지, 모음전 화면 틀 안에 samba-wave 화면을 끼워넣는(iframe 등) 것인지 — STEP 2b 에서 결정
