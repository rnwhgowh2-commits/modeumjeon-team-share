# 본질 기능 대조 규격 · 전수 재검토

> 사장님 지시(2026-08-06): *"결국에 본질 '기능'이 뭔지 따져가며 비교하는 게 중요하고, 이에 대한 보고서까지 면밀한 검토가 필요하다."*
> 이 문서는 **비교 방법 자체**를 규격화하고, 지금까지 내린 판정을 **전수 재검토**한 결과다.

---

## 1. 왜 「기능 이름」으로 비교하면 반드시 틀리는가

지금까지의 대조는 화면·기능 **이름**으로 짝을 지었다. 그래서 세 가지 오류가 섞였다.

| 오류 유형 | 뜻 | 실제로 발생한 사례 |
|---|---|---|
| **① 거짓 동률** | 이름이 같아 「둘 다 있음」으로 셌지만 **푸는 문제가 다르다** | 「마진율」 — 더망고는 *표면가*에 얹고, 우리는 *최종매입가*에 얹는다. 같은 칸이 아니다 |
| **② 놓친 중복** | 이름이 달라 「우리에겐 없음」으로 셌지만 **이미 같은 문제를 풀고 있다** | 「금지어」·「KC인증」 — 우리 가공정책 13항목에 **이미 있다**(`process_policy.py:36-52`) |
| **③ 없는 문제 베끼기** | 저쪽엔 문제가 있지만 **우리에겐 그 문제가 없다** | 관부가세·통관·환율·배송대행지 — 우리는 국내 소싱이라 문제 자체가 없다 |

⇒ **비교의 단위는 기능이 아니라 「기능이 푸는 문제(Job)」여야 한다.**

---

## 2. 대조 규격 (앞으로 모든 항목은 이 6칸을 채운다)

```
① Job          이 기능이 푸는 문제 한 줄. 도구가 아니라 문제로 쓴다.
                 ✗ "배송비를 설정한다"        ✓ "검색 노출가를 낮춰 클릭을 얻는다"
② 우리에게 그 Job 이 있는가   있음 / 없음 / 크기가 다름
③ 더망고 해법  실측 근거(화면·URL·문구)와 함께
④ 우리 해법    **실코드 근거(파일:줄) 또는 ❌**. 기억으로 쓰지 않는다
⑤ 동일성       같음 / 부분겹침 / 다름  ← ①②를 근거로
⑥ 판정         🟢🔵🔴🟡 + 한 줄 근거
```

### 판정 4분류를 **Job 기준으로 재정의**
기존 정의는 "좋아 보이나"였다. 그건 취향이다. Job 기준으로 다시 못박는다.

| | 이름 | **정확한 정의** |
|---|---|---|
| 🟢 | **따라할 것** | Job 이 우리에게 **있고**, 우리 해법이 **없거나 열등**하다 |
| 🔵 | **우리가 이미 우위** | **같은 Job** 인데 우리 해법이 **우월**하다 (다른 Job 이면 우위가 아니라 무관) |
| 🔴 | **버릴 것** | **Job 자체가 우리에게 없다.** 해법이 나빠서가 아니다 |
| 🟡 | **사장님 판단** | Job 은 있는데 해법에 **가치판단·리스크**가 걸린다 (법·정책·전략) |

🔴 **가장 흔한 실수 = 「해법이 위험한 것」을 🔴(버릴 것)에 넣는 것.** 그건 🟡이다.
Job 이 있으면 언젠가 다른 해법으로 풀어야 한다. 🔴에 넣으면 **문제가 있다는 사실 자체가 지워진다.**

## 3. 전수 재검토 — 기존 판정이 뒤집힌 것

### 🔄 오분류 ①: 「마켓별 금지어」 — 🟢 따라할 것 → 🔵/🟢 분리

| | |
|---|---|
| **Job** | 마켓이 거부할 상품을 **등록 전에** 걸러 실패·계정 위험을 막는다 |
| 우리 Job | **있음** |
| 더망고 해법 | 수집 시 **마켓별 금지어 템플릿 7종**(스스60·롯데온61·옥션62·전체63·G마켓84·11번가85·쿠팡86) 중 택1. 상품명/상품설명 검사 |
| **우리 해법** | ✅ **있다** — 가공정책 13항목의 `banned_words`(`process_policy.py:48`). 🎯 **말 단위 판정**(`process_apply.py:56` — *"맨 포함검사면 수집 금지어 'Men' 이 'Mentoring' 에 걸린다"*). 수집/업로드 두 시점 모두 |
| **동일성** | 부분겹침 |
| **판정** | 🔵 **판정 로직은 우리가 우위**(단순 포함 vs 말 단위) / 🟢 **「마켓별 템플릿」 축만 채택** |

> **기존 판정이 틀렸다.** 「우리에게 없음」이 아니라 「있는데 마켓별로 안 쪼개져 있음」이었다.

### 🔄 오분류 ②: 「KC인증」 — 🟢 따라할 것 → **🔵 우리가 우위**

| | |
|---|---|
| **Job** | 인증 없는 상품 판매로 인한 **형사 처벌**(3년 이하 징역·3천만원 이하 벌금)을 막는다 |
| 더망고 해법 | 마켓정책에서 **유형만 택1** — KC인증 있음 / 없음 / 구매대행 안전기준 준수 / 안전관리대상 아님. **인증번호는 다루지 않는다** |
| **우리 해법** | ✅ `process_rule_schema.py:234` — `safety_target`(안전기준준수 대상) + **`collect_kc_no`(KC 인증번호 수집, 기본 ON)**. 주석: *"소싱처에서 KC 인증번호를 가져올 수 있으면 **반드시 수집·저장**합니다."* |
| **동일성** | 같은 Job |
| **판정** | 🔵 **우리가 우위** — 더망고는 「인증이 있다고 신고」, 우리는 「**인증번호를 실제로 확보**」. 소명 요구 시 갈린다 |
| 남은 것 | 🟢 **법적 경고 문구 노출**만 채택 (더망고는 화면에 형량을 적어 실수를 막는다) |

> **두 번 연속 같은 실수를 했다** — 우리 코드를 안 보고 「없다」고 단정. §6 규칙(실코드 근거 필수)이 이래서 필요하다.

### 🔄 오분류 ③: 「옵션저장안함(단품화)」 — 🔴 버릴 것 → 🟡 사장님 판단

| | |
|---|---|
| **Job** | 옵션이 **마켓 상한을 넘을 때** 등록 자체가 막히는 것을 피한다 |
| 우리 Job | **있음** — 더망고 「마켓별 세부설정」에 **「전송 옵션개수」** 상한이 따로 있는 것이 증거. 마켓 상한은 실재한다 |
| 더망고 해법 | 옵션을 통째로 버리고 단품 저장 |
| 우리 해법 | ❌ (상품명 상한은 `market_limits.py` 에 있으나 **옵션 개수 상한은 없다**) |
| **판정** | 🟡 — 해법(단품화)은 우리에게 위험하다(옵션별 재고 = 오버셀 방어선). **그러나 Job 은 살아 있다.** 우리 해법은 「단품화」가 아니라 **「옵션 우선순위 잘라 보내기 + 잘린 개수 표면화」**여야 한다 |

> 🔴에 넣었으면 **마켓 옵션 상한이라는 문제가 통째로 사라질 뻔했다.**

### 🔄 오분류 ④: 「연속 품절 일괄삭제」 — 🟢 따라할 것 → 🟢(동기 정정)

| | |
|---|---|
| 내가 적었던 동기 | "저장 한도 20만이 병목이라" |
| **진짜 Job** | ① 죽은 상품이 **크롤 큐를 먹어** 살아있는 상품의 가격·품절 반영이 늦어진다 ② 마켓에 품절 상품이 쌓여 **스토어 품질 점수**가 내려간다 |
| 우리 Job | **있음** (한도는 없지만 ①②는 그대로) |
| 우리 해법 | 부분 — 크롤 계수 `no_change_streak` 로 **덜 돌 수는** 있으나(`crawl_schedule.py`) **치우지는 않는다** |
| **판정** | 🟢 유지. **단 우선순위는 낮지 않다** — 한도가 없다고 문제가 없는 게 아니다 |

### 🔄 오분류 ⑤: 「카테고리 사전 59,048건」 — 🔵 우위 → 🔵(단서 붙임)

`MarketCategory`(`models.py:167`)에 **국내/해외 구분 컬럼이 없다.** 11번가·롯데ON 은 두 벌이 다르다.
⇒ **양(59,048건)의 우위는 사실이나, 정확성은 미검증.** 「우위」 주장에 단서를 단다. 검증 전까지 **판정 = 확인불가**.

### 🔄 오분류 ⑥: 「정책 상속」 — 재정의

내가 「우리는 평면, 더망고는 상속」이라 했는데 **구조가 다른 것이지 우열이 아니었다.**

| | 더망고 | 우리 |
|---|---|---|
| 겹침 허용 | **허용** — 4단 우선순위로 해소 | **금지** — `PolicyConflict`: *"한 구성을 두 정책에 붙이려 할 때"*(`process_policy.py:62`) |
| Job | 예외를 **적은 비용**으로 표현 | 정책 귀속을 **모호하지 않게** |
| 대가 | 「이 상품에 왜 이 값이?」 추적이 어려움 | 예외 하나마다 정책 하나 → 폭발 |

**⇒ 이건 설계 철학의 트레이드오프다.** 더망고는 138개 폭발을 **부분 오버라이드 8항목**으로 겨우 누르고 있고, 우리는 충돌 금지로 **모호함**을 막았지만 예외 표현 수단이 없다.
**판정 🟢 조건부**: 상속을 도입하되 **「이 값이 어느 층에서 왔는지」를 화면에 반드시 표시**한다(우리 fx영수증 철학 그대로). 그 표시가 없으면 도입하지 않는 편이 낫다.

### 🔴 버릴 것 — *Job 자체가 우리에게 없다*
해외 구매대행 전용. **국내 소싱에는 문제가 존재하지 않는다.**

## 5. 아직 「확인불가」인 것 — 우위/열위를 말하면 안 되는 항목

프로젝트 규칙(판정 3값: 일치 / 불일치 / **확인불가**)에 따라 **모른다고 적는다.**

| 항목 | 왜 모르나 | 확인 방법 |
|---|---|---|
| **11번가·롯데ON 카테고리 국내/해외** | `MarketCategory` 에 구분 컬럼 없음. 수집기는 한 벌만 가져옴 | 마켓 등록 API 원문 대조 · 실제 수집된 코드 표본 확인 |
| 우리 가공정책 수 (더망고 138 대비) | 미조사 | 라이브 DB `process_policies` count |
| **마켓별 옵션 개수 상한** | `market_limits.py` 는 **상품명 길이만** 다룬다. 옵션 개수 상한은 코드에 흔적 없음 | `marketplace_api_map.json` 등록 API 정독 |
| 마켓 접속통계 API 제공 여부 | 미조사 | 마켓 API 지도 정독 |
| 우리 `frame` 상세 템플릿에 **변수 치환·조건부 블록**이 있는가 | `mode="frame"` 선택지는 있으나 렌더러 미조사 | `process_apply.py` 의 detail 처리부 정독 |

### ✅ 해소된 확인불가 — 우리 상세페이지 가공 (`process_rule_schema.py:208`)
| 필드 | 뜻 |
|---|---|
| `mode` | **recombine**(이미지 재조합) / **original**(원본 통째) / **frame**(프레임 템플릿) |
| `top_images` / `bottom_images` | 상단·하단 삽입 이미지 |
| `common_notice` | 하단 공통안내 자동 (기본 ON) |
| **`hide_source_logo`** | **소싱처 로고 가리기** (기본 ON) |
> 주석: *"브랜드마다 후크 이미지를 다르게 걸 수 있습니다."*

**판정 재조정**:
- 「상세페이지 템플릿」 Job — 우리도 `frame` 모드로 갖고 있다. **🟢 → 부분 채택**: 없는 것은 **① 변수 치환(`{goods_brand}` 류) ② 조건부 블록(`[GOODS_SPEC]`)** 뿐이다.
- 🔵 **`hide_source_logo`(소싱처 로고 가리기)는 더망고에 없다** — 더망고는 워터마크를 *얹는* 기능만 있고 원본 로고를 *지우는* 기능이 없다. **우리 우위 항목 추가.**
