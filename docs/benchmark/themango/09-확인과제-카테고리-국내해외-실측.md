> 🔴 결론이 애초 가설과 **다르다.** 롯데온은 「구분 컬럼이 없다」가 문제가 아니었다.

## 0. 한 줄 결론

| 마켓 | 애초 가설 | **실측 결론** |
|---|---|---|
| **11번가** | 국내/해외 트리가 다른데 한 벌만 수집 | 🟢 **한 트리 + 카테고리별 플래그** 구조. 우리가 쓰는 게 맞다. 단 플래그를 **버리고 있다** |
| **롯데온** | 국내/해외 트리가 다른데 한 벌만 수집 | 🔴 **더 심각.** 등록에 **카테고리를 아예 안 보낸다.** 「본보기 상품」을 복사한다 — 그 본보기가 해외직구면 **전량이 해외직구로 나간다** |

**공통 희소식** — 두 마켓 다 구분 단서가 `market_categories.raw_json` 에 **이미 저장돼 있다.**
**재수집이 필요 없다.** 컬럼 하나 뽑아 쓰면 된다.

## 1. 우리 그릇에 구분 컬럼이 없는 것은 사실

`lemouton/registration/models.py:166~195` `MarketCategory`

```
market · code · name · full_path · parent_code · depth · is_leaf
extra_code(ESM 짝코드 전용) · raw_json · harvested_at · removed_at · child_count
```

→ **국내/해외를 가릴 컬럼이 없다.** 유니크 키도 `(market, code)` 뿐이라
같은 코드가 국내·해외에 각각 있으면 **한쪽이 다른 쪽을 덮어쓴다.**

단 `raw_json` (`:180`) 에 **마켓 응답 원문 조각을 통째로 보관**하고 있다("버리지 않는다").
`save_snapshot` 이 `raw_json=row.get('raw')` 로 실제 저장한다 — `category_harvest.py:436`.
**→ 구분값은 이미 우리 DB 안에 있다. 꺼내 쓰기만 하면 된다.**

## 2. 11번가 — 🟢 한 트리 + 플래그. 우리가 쓰는 게 맞다

### 수집하는 것
`GET http://api.11st.co.kr/rest/cateservice/category` — **「전체 카테고리 조회」**
(`webapp/data/marketplace_api_map.json` · 파서 `category_harvest.py:51 parse_eleven11`)

응답 한 블록의 필수 필드 (마켓 문서 원문):

| 필드 | 뜻 | 우리가 |
|---|---|---|
| `dispNo` / `dispNm` | 카테고리 번호·이름 | **씀** |
| `parentDispNo` / `depth` / `leafYn` | 트리 구조 | **씀** |
| **`gblDlvYn`** | **전세계배송가능여부** (Y/N) | 🔴 **버림** (raw_json 에만) |
| **`engDispYn`** | **영문11번가 노출여부** (Y/N) | 🔴 **버림** (raw_json 에만) |

### 판정
11번가는 **국내 트리와 해외 트리를 따로 주지 않는다.** 트리는 하나이고,
카테고리마다 **「이건 해외로도 나갈 수 있다」를 플래그로** 붙여 준다.

우리 등록은 `dispCtgrNo` **한 칸**만 보낸다 — `lemouton/policy/required.py:161`,
전문 조립은 `shared/platforms/eleven11/products.py:263`.
→ **국내 셀러 등록 API 에 국내 트리 코드를 보내고 있다. 맞다.**

더망고 화면의 *"11번가는 해외/국내카테고리가 다릅니다"* 는 **해외직구(구매대행) 전용
등록 흐름**을 가리키는 말로 보인다. 우리는 국내 소싱·국내 배송이라 해당 없음.

### 🟡 남는 일 (작음)
`gblDlvYn` 을 `MarketCategory` 에 컬럼 하나로 승격.
버려서 당장 사고 나는 값은 아니지만, **「이 카테고리 해외로 나가나?」를 화면에서
못 보는 상태**다. `raw_json` 에 있으니 **재수집 없이** 백필 가능.

## 3. 롯데온 — 🔴 애초 가설보다 심각. 카테고리를 안 보낸다

### ① 등록 API 가 요구하는 카테고리는 **3칸**
`lemouton/policy/required.py:199~200` (마켓 등록 API 원문 요약, 별표 = 필수)

```
scatNo*   표준카테고리번호
dcatLst*  전시카테고리
lfDcatNo* leaf 전시카테고리
```

### ② 우리가 수집하는 건 그 중 **1칸뿐**
`webapp/routes/bulk/categories.py:229` → `job=cheetahStandardCategory`
= **표준카테고리만.**

**전시카테고리(`cheetahDisplayCategory`)는 API 지도에 적혀만 있고
코드에서 한 번도 호출하지 않는다** — 전 `*.py` 를 뒤져 호출 0건.

### ③ 🔴 그런데 국내/해외 구분자는 **전시카테고리 쪽에 산다**
표준카테고리 응답 안의 `disp_list[]` 에 이 둘이 짝으로 들어 있다
(`marketplace_api_map.json:505,510`):

```
disp_list[].disp_cat_id    전시카테고리ID
disp_list[].mall_dvs_cd    몰구분코드   ← 이게 국내/해외를 가른다
```

실물 확인 — 라이브 롯데온 상품 덤프에 값이 찍혀 있다:
`scripts/_lotteon_pbf_dump/lemouton_base.json:21` · `:1258`

```
"mallDvsCd": "LTON"          ← 롯데온 일반(국내)
"dispCatId": "FC17000000"    (+ dispCatId0~2 계층)
```

`harvest_lotteon` 은 `disp_list` 를 **쓰지 않지만 통째로 raw_json 에 저장**한다
(`category_harvest.py:388` `'raw': _json.dumps(c, ...)`).
**→ `mall_dvs_cd` 는 이미 우리 DB 안에 있다.**

### ④ 🔴🔴 진짜 위험은 다른 데 있었다 — 「본보기 상품 복사」

`lemouton/registration/compile_more.py:148~163` `compile_lotteon`

```
category_code = 본보기 기존 상품번호(spdNo)   ← 카테고리 번호가 아니다
```
```
같은 계정·비슷한 카테고리의 판매중 상품번호를 넣어야
카테고리·고시·배송·출하지 값이 그대로 통한다
(등록 body = 그 상품 detail 스키마 — 2026-07-21 실측)
```

즉 롯데온 등록은 **카테고리를 우리가 고르지 않는다.**
본보기 상품 하나(`LO...`)를 지정하면 **그 상품의 카테고리·고시·배송·출하지가 통째로 상속**된다.

**대량등록에 이걸 그대로 쓰면:**

| 위험 | 결과 |
|---|---|
| 🔴 본보기가 **해외직구 상품**이면 | 그 필터로 나가는 **수천 건 전부**가 해외직구로 등록. 마켓에서 변경 불가 → **삭제 후 재등록만이 복구** |
| 🔴 본보기 하나 = 카테고리 하나 | 검색필터 한 개가 여러 카테고리 상품을 물어오는데 **전부 같은 카테고리로** 나간다 |
| 🔴 본보기가 **판매중지·삭제**되면 | 그 필터의 등록이 통째로 죽는다. 조용히 |
| 🔴 `MarketCategory(market='lotteon')` 수집분은 | 등록에 **쓰이지도 않는다** (맵핑·제안 화면용) |

**애초 가설(「구분 컬럼이 없다」)은 절반만 맞았다.**
컬럼이 없는 것도 사실이지만, 롯데온은 **컬럼을 채워도 그 값이 등록에 안 실린다.**

## 4. 🟢 그래서 설계에 넣을 것 — 4가지

| # | 할 일 | 왜 | 비용 |
|---|---|---|---|
| **1** | `MarketCategory` 에 **`mall_scope`** 컬럼 추가 (`domestic`/`overseas`/`unknown`) + `raw_json` 에서 **백필** | 재수집 불필요. 11번가 `gblDlvYn`, 롯데온 `disp_list[].mall_dvs_cd` 로 채움 | 작음 |
| **2** | 🔴 **롯데온 본보기 상품 preflight** — 등록 직전 본보기 `spdNo` 를 조회해 ① 아직 **판매중**인가 ② `mallDvsCd` 가 **국내(LTON)** 인가 ③ 그 카테고리가 상품과 맞나. **하나라도 아니면 전송 중단** | 🔴 수천 건이 한 번에 잘못 나가는 유일한 통로를 막는다 | **중간 — 최우선** |
| **3** | 롯데온 **전시카테고리 수집**(`cheetahDisplayCategory`) 추가 → 장기적으로 본보기 복사에서 **직접 지정**으로 | 본보기 방식은 대량등록과 구조적으로 안 맞는다 | 큼 — 2차 |
| **4** | 카테고리 유니크 키를 **`(market, code)` → `(market, mall_scope, code)`** 로 검토 | 같은 코드가 국내·해외에 있으면 지금은 덮어쓴다 | 작음 |

**지금 당장 필요한 건 #2 하나다.** #1·#4 는 값싸고, #3 은 2차.

## 5. 재수집 없이 확인하는 법 (사장님 승인 불필요, 읽기만)

DB 에 이미 있는 값을 세는 것뿐이다.

```sql
-- 롯데온: 표준카테고리 raw 안에 몰구분코드가 실제로 들어 있나
SELECT COUNT(*) FILTER (WHERE raw_json LIKE '%mall_dvs_cd%') AS 구분값있음,
       COUNT(*) AS 전체
FROM market_categories WHERE market='lotteon';

-- 11번가: 전세계배송 플래그 분포
SELECT COUNT(*) FILTER (WHERE raw_json LIKE '%<gblDlvYn>Y</gblDlvYn>%') AS 해외가능,
       COUNT(*) FILTER (WHERE raw_json LIKE '%<gblDlvYn>N</gblDlvYn>%') AS 국내만,
       COUNT(*) AS 전체
FROM market_categories WHERE market='eleven11';
```
