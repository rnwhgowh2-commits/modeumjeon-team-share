## 🔴 정정 (9번째) — 매뉴얼의 치환 규칙 설명이 실화면과 다르다

매뉴얼(`119`)을 근거로 *"위에서부터 순차 적용, **중복 조건이면 제일 아래 것이 승리**"* 라고 적었다.
**실화면에는 그런 규칙이 없다.** 대신 **치환 방식을 사용자가 고른다.**

| 방식 | 화면 설명 원문 |
|---|---|
| **순차치환** | *"정의한 문자열 **순서대로** 치환합니다."* |
| **동시치환** | *"정의한 문자열을 **동시에 한번만** 치환합니다. 겹치는 문자열이 있는 경우에는 **가장 긴 문자열에 대해서만** 치환됩니다."*<br>예: `RED → 레드`, `PREDATER → 프레데터` 일 때 **`PREDATER` 에 대해서만** 치환 |

⇒ **동시치환 = longest-match-wins.** 이건 매뉴얼에 없던 핵심 개념이다.
⇒ 🎯 **우리 `process_apply.py:56` 의 「말 단위 판정」(`'Men' ⊂ 'Mentoring'` 방지)과 같은 문제를 다르게 푼 것.**
   - 우리: **단어 경계**로 푼다
   - 더망고: **가장 긴 것 우선** + **`온전한 단어` 체크박스**(아래) 로 둘 다 제공

## ★ 블록 1 — 상품명 치환 정책

| 항목 | 내용 |
|---|---|
| **치환방식** | `순차치환` / `동시치환` |
| **치환 템플릿** | `템플릿 사용 안함 / 직접 작성` ↔ **`한글치환템플릿`** + `[템플릿 관리]`<br>*"템플릿을 사용하시면 선택한 템플릿에 설정된 치환조건으로만 적용됩니다"* |
| **치환조건 추가** | `[원본] → [대상]` + ☐`대소문자 구분안함` + `[+ 상품명 치환조건추가하기]`<br>*"추가되는 치환조건은 리스트 마지막 순서에 추가됩니다"* |
| **치환조건 리스트** | 행마다 `▲` `▼`(순서 이동) · `삭제` · ☐`대소문자 구분안함` ☐**`온전한 단어`** ☐**`정규식`** |
| **엑셀** | 🎯 `[상품명치환 엑셀업로드]` `[상품명치환 엑셀다운로드]` **`[상품명치환 오류체크]`** |

### 🎯🎯 세 체크박스가 결정적이다
| 체크박스 | 뜻 | 우리 대응 |
|---|---|---|
| `대소문자 구분안함` | case-insensitive | ❌ |
| **`온전한 단어`** | **whole-word 매칭** | 🔵 우리 금지어는 말 단위 고정(`process_apply.py:56`) — 하지만 **치환에는 없다** |
| **`정규식`** | **정규표현식 지원** | ❌ |

⇒ 🟢 **채택**: 치환 규칙마다 **①대소문자 ②온전한단어 ③정규식** 세 스위치.
우리는 「말 단위」를 **고정 정책**으로 박아뒀는데, 더망고는 **규칙마다 고를 수 있게** 했다. 실무에선 부분 일치가 필요한 경우도 있다.

### 🎯 엑셀 업로드/다운로드 + **오류체크**
치환 규칙이 수백 개가 되면 화면에서 한 줄씩 못 고친다. **엑셀로 내려받아 고치고 다시 올린다.**
그리고 **`오류체크`** 버튼이 따로 있다 — 올리기 전에 규칙 충돌·잘못된 정규식을 잡는다.
🟢 **채택 확정.** 사장님 상품명 필터링에 이미 수백 단어가 들어 있는 걸 봤다. 화면 편집만으로는 감당 안 된다.

## ★ 블록 2 — 상품명 조합 정책

**조립 블록 6종 + 자유 텍스트**
`상품명` · `모델명` · `브랜드명` · `해외사이트명` · `상품번호` · `해외상품번호` · `[+ 텍스트추가]`
→ `* 상품명 조합 조건` 에 순서대로 쌓고 `삭제` 가능

### 🎯 브랜드명 중복 처리 (매뉴얼에 없던 것)
> *"상품명에 브랜드명이 포함되어 있는 경우 브랜드명을"*
> ◉ `{상품명} 위치에만 표기` / ○ `{브랜드명} 위치에만 표기` / ○ `둘다 표기`

⇒ **「나이키 나이키 에어맥스」 같은 중복을 막는다.** 🟢 채택.

### 유의사항 (화면 원문)
1. 작성한 조건으로 변경된 상품명이 마켓에 전송
2. **아무 조건도 입력하지 않으면 수집된 원문 상품명으로 전송** (안전한 기본값)
3. **상품명은 필수로 선택**
4. *"마켓의 경우 상품명을 글자수로 제한(보통 **50바이트**)하는 경우가 있기 때문에 **가장 긴 문자열인 상품명을 가장 마지막에** 조합하기를 추천"*
5. 모델명·브랜드명이 없는 상품은 **빈값**

⇒ 4번은 🔵 우리가 더 낫다 — `market_limits.py` 가 **마켓별 실측 상한**을 갖고 있고(coupang 100·eleven11 100), **확인 못 한 마켓엔 상한을 적용하지 않는다.** 더망고는 "보통 50바이트"라고 **추측**한다.

## ★ 블록 3 — 🆕 상품명 중복단어 필터링 (매뉴얼에 없음)

☐ `중복단어를 필터링 합니다`
> 1. 상품명에서 **띄어쓰기 기준**으로 중복되는 단어를 **1개만 남기고** 제거
> 2. 🎯 **"중복단어 필터링은 조합·치환 등 변경이 모두 완료된 상품명에 적용됩니다"**
> 3. **대소문자를 구분합니다** (대소문자가 다르면 필터링 안 됨)

⇒ 2번이 중요하다. **실행 순서가 또 한 번 명문화**됐다.

### 🎯 이제 상품명 가공 순서가 완전히 드러났다
```
원문 상품명
 → 번역            (번역 정책)
 → 치환            (순차 or 동시·longest-match)
 → 조합            (블록 6종 + 텍스트)
 → 중복단어 제거
 → 필터링(단어 삭제) (환경설정 > 상품명 필터링)
 → 랜덤키워드 부착   (수집 시 설정)
 = 마켓 전송 상품명
```
🟢 **이 파이프라인 순서 자체를 채택.** 우리 `process_apply` 는 이만큼 단계가 나뉘어 있지 않다.

⇒ 🎯 **우리 `'Men' ⊂ 'Mentoring'` 사고([[project_category_suggest_partial_match_fix]] 계열)와 정확히 같은 함정**을 저쪽도 겪었고, **기본값을 안전한 쪽(모든 문자열 일치)으로 두고 화면에 경고를 적었다.**
🟢 **채택**: 옵션명 치환은 **기본이 완전일치**여야 한다. 사이즈 `M`·`S`·`L` 은 한 글자라 부분일치가 재앙이다.
