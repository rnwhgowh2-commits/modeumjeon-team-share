# ★★★ 확인 과제 해소 ① — **전송 옵션개수 상한이 있고, 사장님은 10개로 쓰신다**

> **`전송 옵션개수  [10] 개`**
> *"마켓에 전송되는 옵션개수를 설정할 수 있습니다."*
> *"**옵션명을 오름차순으로 정렬한 후, 입력한 개수보다 옵션이 많은 상품은 입력한 옵션개수까지만** 마켓에 전송됩니다."*
> *"개수를 입력하지 않으면 모든 옵션이 전송됩니다."*

## 이것이 §07 의 🟡「옵션 상한 대응」 Job 을 확정한다
- **G1 ✅ 강하게 통과** — 값 `10` 이 실제로 들어 있다. 사장님은 **옵션이 21개·37개인 상품도 마켓엔 10개만** 보내고 계신다
- 앞서 상품 목록에서 본 `[옵션개수:21]` `[옵션개수:37]` 이 왜 표시되는지도 설명된다 — **잘릴 수 있으니 미리 보여주는 것**

## 🔴 다만 **자르는 기준이 위험하다**
「옵션명 **오름차순** 정렬 후 앞에서 10개」
⇒ 사이즈가 `S · M · L · XL · 2XL` 이면 가나다/알파벳 순으로 잘린다. **잘 팔리는 사이즈가 뒤에 있으면 그게 잘린다.**
⇒ 재고가 많은 옵션, 매출이 나는 옵션이 잘려도 아무도 모른다.

### 판정 🟡 **형태 바꿔 채택**
| | |
|---|---|
| Job | 마켓 옵션 상한을 넘겨 등록이 통째로 실패하는 것을 막는다 |
| 더망고 해법 | 옵션명 오름차순 앞 N개 |
| **우리 방식** | ① **자를 순서를 고를 수 있게** (재고 많은 순 / 매출 순 / 옵션명 순)<br>② **잘린 개수와 잘린 옵션을 화면에 표면화** — 조용히 버리지 않는다<br>③ 상한은 **마켓별 실측값**으로 (`market_limits.py` 에 옵션 상한 칸 추가) |

# ★★★ 확인 과제 해소 ② — **정산예정금액 계산식 + `(계산됨)` 꼬리표**

> **`정산예정금액 = 결제금액 × [ 계산식 입력 ]`**
> *"정산예정금액을 제공하지 않는 마켓의 정산예정금액을 **임의의 계산식**으로 보여줄 수 있습니다."*
> *"주문관리 메뉴에서 확인할 수 있고, 계산식으로 계산된 정산예정금액 뒤에 **`(계산됨)`** 이라는 문구가 추가되어 보여집니다."*
> *"**정산(예정)금액을 마켓에서 수집한 경우, 본 수식은 적용되지 않습니다.**"*
> 입력 가능: 괄호 · 숫자 · `*` `+` `-` · 예시 `( 20000 - 1000 ) * 0.88`

## 🎯 여기서 배울 것은 계산식이 아니라 **`(계산됨)` 꼬리표**다
- **마켓이 실제로 준 값** 과 **우리가 추정한 값** 을 화면에서 구분한다
- 그리고 **실측값이 있으면 추정을 쓰지 않는다** (우선순위가 명확)

⇒ 🔵 우리 원칙([[feedback_no_fallback_price_on_match_fail]] · 판정 3값 「일치/불일치/**확인불가**」)과 **정확히 같은 철학**이다.
⇒ 🟢 **채택**: 우리 정산예정금액 탭에 **「마켓 제공」 / 「계산됨」 배지**를 붙인다. 지금은 둘이 섞여 있어 구분이 안 된다.
⇒ 🔵 우리가 나은 점: 우리는 마켓별 수수료율을 **실측**해 두었다(스스6·쿠팡11.55·롯데온18·11번가11→체크시8·옥션지마켓15). 더망고는 사용자가 손으로 넣는다.

# ★★ 새로 발견 — **동일 상품명 마켓등록 제한** (중복 등록 방어)

> ✅ **`동일 상품명 마켓등록 제한`** (체크됨)
> *"같은 상품명으로 마켓에 이미 등록되었을 경우 마켓상품등록을 제한합니다."*

- **G1 ✅ 체크돼 있다** — 사장님이 실제로 켜두셨다
- 🎯 **§06 이관 제약의 「중복 등록 방어」와 직결.** 이관 후 우리가 같은 상품을 다시 올리면 마켓 중복 = 계정 위험
- 🟡 **형태 바꿔 채택** — 상품명은 약한 열쇠다(치환·조합으로 바뀐다). 우리는 **`(소싱처URL, 마켓, 계정)`** 으로 막는다. 상품명 비교는 **보조 경고**로만

# ★ 금지어가 **4군데**에 있고 전부 동시 적용된다

> *"금지어는 총 **4군데**에 설정이 가능하며, 설정된 금지어는 **동시에 적용**됩니다."*
> ① `환경설정 - 상품수집관련 설정` ② `환경설정 - 마켓 관리정보 설정` ③ `환경설정 - 수집사이트별 세부설정` ④ `상품데이터 수집시(검색필터별)`

여기 마켓 설정에서 고른 것: **`옵션 금지어`** + `[금지어 템플릿 관리]`

⇒ 🔴 **이건 따라하지 않는다.** 금지어가 4곳에 흩어져 동시 적용되면 **「왜 이 상품이 안 들어왔지?」를 아무도 못 푼다.**
게다가 §08 에서 본 것처럼 **필터링과 금지어가 서로를 무력화**한다.
⇒ 🟡 우리는 **한 곳(가공정책 `banned_words`)에 모으고, 적용 범위(전체/소싱처/필터/마켓)를 그 안에서 태그로 구분**한다. 판정 결과에 **어느 규칙에 걸렸는지**를 반드시 남긴다.

# ★ 단일상품등록설정 — 옥션·지마켓의 실제 제약 대응

두 체크 **모두 ON**:
| 체크 | 내용 |
|---|---|
| ✅ **옵션조합이 1개인 상품을 옵션등록 없이 단일상품으로 등록** | *예: 색상 블랙 / 사이즈 XL 인 상품도 조합은 「블랙+XL」 1개이므로 단일상품으로 등록* |
| ✅ **단일상품등록시 옵션내용을 상품명 뒤에 포함** | *예: `나이키 조던 운동화` + 옵션 `블랙` → `나이키 조던 운동화 블랙`*<br>⚠️ *"옵션내용을 포함할 경우 마켓에서 허용하는 **상품명 길이를 초과하면 옵션내용은 전송되지 않을 수 있습니다**"* |

**왜 필요한가 (화면 설명)**
> *"**옥션2.0은 일부 카테고리에 대해 상품등록시 옵션등록을 제한**하고 있습니다."*
> *"옵션조합이 2개 이상인 상품은 옵션등록이 가능한 **유사 카테고리로 변경하여** 전송하시면 됩니다."*
> 확인처: 공지 *"지마켓 주문옵션 등록방식 수정 공지"* 하단 카테고리 리스트

⇒ 🔴🔴 **이건 우리가 몰랐던 마켓 제약이다.** 옥션·지마켓의 **일부 카테고리는 옵션 등록 자체가 막혀 있다.**
⇒ 🟢 **채택 — 단 「단품화」가 아니라 「제약 인지」로.**
   - **G1 ✅** 둘 다 켜져 있다
   - 우리 preflight 에 **「이 카테고리는 옵션 등록 불가」 검사**를 넣는다
   - 조합이 1개뿐인 상품은 단일상품으로 보내도 **정보 손실이 없다**(옵션이 하나니까) — 이건 §07 에서 🔴로 뒀던 「옵션저장안함(단품화)」과 **전혀 다른 것**이다. 그건 옵션 여러 개를 버리는 것, 이건 옵션 1개를 평평하게 만드는 것
   - **정정**: §07 🔴 「단품화」 항목에 이 구분을 명시할 것

# 마켓분산등록 설정 — ⚪ **보류 유지** (G1 탈락 확인)

화면: `1. [-- 마켓 아이디 선택 --] [등록가능 상품수] [삭제] [우선순위▲▼]` + `[+마켓 아이디 추가하기]`
**→ 사장님 미설정 (빈 행 1개)**

설명 요지:
- 1상품을 1마켓에만 등록해 **등록 가능 수량을 최대로** 이용
- **우선순위에 따라 등록되며, 등록가능 상품수에 도달하면 다음 우선순위 마켓으로**
- **마켓 신규 등록시에만 적용.** 이미 등록된 상품의 업데이트는 정상 진행
- 예: 옥션 3,000 / 지마켓 5,000 / 11번가 1,000 으로 설정하면 A 상품은 셋 중 **1곳에만**, 분산등록 미설정인 쿠팡엔 **그대로 등록**

⇒ **G1 ❌ · G3** — 이건 **마켓 등록 한도가 병목일 때만** 의미가 있다. 사장님은 아직 한도에 안 닿으셨다.
⇒ ⚪ **보류 유지.** 다만 개념은 기록 — 나중에 한도에 부딪히면 여기서 꺼낸다.

## 🔴 G1 결정적 탈락
**크레딧이 `5,000` 그대로다.** 매뉴얼(`211`)에 *"모든 회원이 처음 AI 기능을 이용할 때 5,000 크레딧이 제공됩니다"* 라고 돼 있다.
⇒ **사장님은 AI 기능을 한 번도 안 쓰셨다.** API Key 도 둘 다 비어 있다.

## 🔴 게다가 G5 위험이 크다 — AI 카테고리 자동매핑의 근거가 너무 얕다
> *"AI 마켓카테고리 자동 매핑은 각 상품 그룹(카테고리/검색필터)에 포함되어 있는 **한 개의 상품정보를 기반**으로 마켓 카테고리를 추천하여 매핑합니다."*

⇒ **검색필터 하나에 상품 3,000개가 들어 있는데, 그중 1개만 보고 전체를 매핑한다.**
「나이키」 필터에는 신발·의류·가방이 다 섞여 있다. **틀린 카테고리로 통째 나간다.**
그리고 🔴 **틀린 카테고리로 등록되면 마켓에서 변경 불가 — 삭제 후 재등록만이 복구**다(매뉴얼 `110`).

⇒ **⚪ 보류 + 우리 방침 재확인.** 사장님이 확정하신 **「자동확정 금지, 제안까지만」**이 옳다는 것이 이 화면으로 증명됐다.
우리 `category_suggest.py`·`category_map.py`(제안/확정/재확정 하이브리드)를 그대로 유지한다.
