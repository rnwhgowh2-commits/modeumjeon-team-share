## ★★★ 1. 마켓 아이디 그룹핑 — **정책명 138개의 수수께끼가 풀렸다**

> *"마켓아이디를 그룹하여 관리할 수 있습니다."* + `[마켓아이디 그룹 추가]` `[설정저장]`

### 실측 그룹 5개 = **사장님의 스토어 브랜드**
| 그룹 | 묶인 마켓 아이디 | 배송대행지 |
|---|---|---|
| **사무실 까대기** | 스마트스토어 **2개** · 쿠팡 **2개** | -- 설정안함 -- |
| **브랜드위시** | 11번가 · G마켓2.0 · 롯데ON · 스마트스토어 · 옥션2.0 · 쿠팡 (**6마켓 한 벌**) | 배송대행지 |
| **브랜드박스** | 11번가 · G마켓2.0 · 롯데ON · 스마트스토어 · 옥션2.0 · 쿠팡 (**6마켓 한 벌**) | 배송대행지 |
| **브랜드타임** | 11번가 · G마켓2.0 · 롯데ON · 쿠팡 … | 배송대행지 |
| **브랜드바이** | 11번가 · 스마트스토어 (2개만) | 배송대행지 |

각 행: `마켓명 [계정수] [계정ID…]` · 그룹마다 `[수정] [삭제]`

### 🎯 이것이 정책 이름의 마지막 조각이다
```
무_아르마니(타임+박스)        → 브랜드타임 + 브랜드박스 그룹에 올림
무_락포트_(위시+바이+타임)    → 브랜드위시 + 브랜드바이 + 브랜드타임
ssg_아레나_3개월(박스+마켓)   → 브랜드박스 + 브랜드마켓
아디다스-웨이 -저마진배송비    → 브랜드웨이
```
⇒ **정책 축이 4차원이라 했는데 사실은 이 4번째 축이 「계정」이 아니라 「스토어 브랜드 그룹」이었다.**
`rnwhgowh1` = 브랜드박스, `rnwhgowh2` = 브랜드위시, `rnwhgowh3` = 브랜드타임, `rnwhgowh4` = 브랜드바이 로 계정이 그룹에 **일관되게 배정**돼 있다.

### 우리 대응 (6칸)
| 칸 | 내용 |
|---|---|
| **Job** | 여러 스토어(브랜드)를 운영할 때, 스토어 하나 = 마켓 계정 여러 개를 **한 덩어리로** 다룬다 |
| 우리 Job | **있음** — 사장님은 실제로 스토어를 5개 굴리고 계신다 |
| 더망고 해법 | 마켓 아이디 그룹 + 그룹별 배송대행지 |
| **우리 해법** | ✅ `MarketAccount`(마켓 계정 단위) 있음 / ❌ **「계정 그룹 = 스토어 브랜드」 계층 없음** |
| **동일성** | 같은 Job |
| **판정** | 🟢 **채택 — 우선순위 높음.** 이게 없으면 정책이 계정 수만큼 곱해진다(더망고 138개가 그 증거) |

## ★★ 2. 상품수집관련 설정 — 사장님 실운영 값

### 🎯 재고 수량 설정 — **재고를 10개로 일괄 고정**
> "모든 상품의 옵션 재고 및 상품 재고 수량을 **`10`** 개로 일괄 변경합니다." + ☐`품절상품 포함`
> - 재고수량을 입력하지 않으면 변경되지 않습니다
> - **재고수량을 0개(품절)로는 변경할 수 없습니다**
> - '품절상품 포함' 선택 시 재고 0인 상품의 재고도 변경됩니다
> - ⚠️ **`[수집사이트 세부설정]-[재고수량설정]` 이 있는 경우 본 설정보다 우선적용됩니다**

🔴 **실제 재고가 950개·1,524개·2,130개인 상품들이 마켓엔 10개로 나간다.**
이유는 명백하다 — **소싱처 재고를 그대로 올리면 오버셀 위험 + 재고를 남에게 알려주는 셈**이다.

⇒ **판정**: 🟢 **채택.** 우리에게 이 개념이 없다.
[[feedback_stock_999_not_a_bug]] 에 「재고 999 = 정상」이 있지만 그건 **소싱처가 999를 준다**는 뜻이지, **우리가 마켓에 올릴 값을 정하는 규칙**이 아니다. **둘은 다른 문제다.**
⚠️ 단 우리 P0 게이트(품절 즉시 반영)와 **충돌하지 않게** 설계해야 한다 — 상한 캡이지 하한이 아니다. **0은 0으로 보낸다.**

### 🎯 상품가격 단위 설정
`10원 단위 절삭 (ex, 9,999원 → 9,900원)`
⇒ 🔵 우리도 있다 — 최종매입가 **백원 버림**(`_FINAL_FLOOR_UNIT=100`). 다만 우리는 **매입가**에, 더망고는 **판매가**에 건다. 🟢 **판매가 절삭 단위 설정 채택.**

### 🔴🔴 「필터링」과 「금지어」는 다른 것 — 그리고 서로를 무력화한다
| | 뜻 | 어디서 |
|---|---|---|
| **금지어** | 그 단어가 있으면 **상품을 아예 안 받는다**(수집·전송 차단) | `[상품수집관련 설정]` |
| **필터링** | 그 단어를 **문자열에서 지운다**(상품은 받는다) | `[상품관리관련 설정]` |

> 🔴 **"필터링 단어와 금지어가 동일하면, 상품명이 먼저 필터링 되기 때문에 금지어는 동작하지 않습니다."**
> (상세페이지 단어 필터링에도 같은 경고 반복)

⇒ **두 규칙의 실행 순서가 충돌한다.** 지워버린 뒤에 검사하니 걸릴 게 없다.
🟢 **채택하되 반드시 개선**: 우리는 **금지어 검사를 필터링보다 먼저** 돌리거나, 최소한 **같은 단어가 양쪽에 있으면 화면에서 경고**한다.

### 필터링 4종 (실측)
| 종류 | 내용 |
|---|---|
| **상품명 필터링** | 상품명에서 단어 일괄 삭제. `;` 또는 엔터 구분. **사장님이 실제로 수백 개 등록해 두심** — 광고 문구(`5천원 즉시 할인`), 브랜드+상품 조합(`[닥스 모자]`, `언더아머모자`), 마케팅 수식어(`아이코닉한 트레포일으로…`) |
| **옵션명 필터링** | `[수집 사이트 세부설정]-[옵션명 제한 설정]` 에서 **소싱처별** |
| **상세페이지 단어 필터링** | 상세 본문에서 단어 삭제 |
| **상세페이지 이미지 필터링** | 🎯 **이미지 URL 로 삭제**. 예시가 쿠팡 CDN — `https://thumbnail7.coupangcdn.com/…/image1.jpg` |

🎯 **상세페이지 이미지 필터링**은 우리 `hide_source_logo`(소싱처 로고 가리기)와 같은 Job이다.
- 우리: **불리언 스위치** (로고 가리기 ON/OFF)
- 더망고: **URL 목록** (이 이미지들을 지워라)
⇒ 🟡 **둘 다 필요.** 스위치는 편하고, URL 목록은 정확하다.

### 🎯 상품보기 설정 — **필터 축 30개+**
`판매이력 있는/없는` · `상품명 수정/미수정` · `옵션명 수정/미수정` · `옵션 있는/없는` · `옵션저장안함/옵션모두저장` · `이미지 변경/미변경` · `상품영상 등록/미등록` · `번역완료/미완료` · `이미지 번역완료/미완료` · `상품메모 있는/없는` · `검색태그 등록/미등록` · `국제운송료 미…` · `단일상품만/제외` · `상품설명 수정/미수정` · `상세페이지직접 수정/미수정` · `브랜드 미수집` · `카테고리 미수정/수집` · **`수집제한 완료/미완료`** · `복사된 상품 보기/제외` · `대표옵션저장상품` …

⇒ **「아직 손 안 댄 상품」을 찾는 도구다.** 16.8만 건을 운영하면 *"번역 안 된 게 몇 개지?"* *"카테고리 미수집이 몇 개지?"* 가 곧 할 일 목록이 된다.
🟢 **채택** — 다만 30개 체크박스를 그대로 베끼지 않는다. 우리는 **「할 일」 관점의 묶음**(예: 「마켓에 못 올라가는 이유별」)으로 묶는다.

### 상품명 수정 설정
개별 수정 시 입력란에 `정책적용된 상품명` 을 자동으로 채워넣음
> *"정책적용된 상품명이란, 번역이 완료된 상품명에 상품명 정책, 상품명 필터링 정책이 적용된 상품명을 의미합니다."*

🎯 **적용 순서를 문장으로 못박아 뒀다**: `원문 → 번역 → 상품명 정책(치환·조합) → 필터링`. 🟢 **이 순서 자체를 채택.**
