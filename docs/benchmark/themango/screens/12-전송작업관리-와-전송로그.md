### 🎯 반복되는 패턴 하나
```
전송마켓: <마켓 1개>

```
= **"이 검색필터의 상품 중, 이 마켓에 아직 안 올라간 것만, 이 마켓에 보낸다"**

14:49~14:51 **3분 사이에 6건 연속** — 필터를 하나씩 바꿔가며 돌리고 계신다.

### 🔴 이것이 내 앞선 판정을 바로잡는다
§05(마켓전송 화면)에서 *"더망고는 전량 푸시가 기본이라 위험 / 165,911건이 한 번에 나갈 수 있다"* 고 적었다.
**화면 기본값은 그렇지만, 실제 운영은 정반대다.** 사장님은 **「필터 1개 × 마켓 1개 × 미등록만」**으로 아주 좁게 조준해 돌리신다.

⇒ 🎯 **대량등록 운영의 실제 단위는 「전량」이 아니라 「필터 × 마켓 × 등록여부」다.**
우리 `send` 탭 설계도 이 단위를 1급으로 삼아야 한다.

# ② 전송 로그 조회 (`admin_logview2.php`)

> *"**상품번호 기준**으로 수집/업데이트 + 마켓 등록/업데이트 로그를 **함께** 확인합니다. **(최대 7일 보관)**"*

### 검색 조건
| 항목 | 값 |
|---|---|
| **로그종류** | `사이트 수집/업데이트 로그` / `마켓 전송 로그` |
| 기간 | ~ |
| **상품번호** · **마켓상품번호** | 🎯 둘 다로 찾을 수 있다 |
| **상태** | `전체` / **`성공 (S)`** / **`실패 (F)`** |
| 검색어 | + `[초기화]` `[조회]` |

### 결과 섹션 2개
`상품 수집/업데이트 로그` · `마켓 등록/업데이트 로그`

### 🎯 핵심 값어치
**한 상품의 「소싱처에서 긁은 기록」과 「마켓에 보낸 기록」을 한 화면에서 나란히 본다.**
사장님이 *"이 상품이 왜 마켓에 안 올라갔지?"* 라고 물을 때, **긁기에서 실패했는지 보내기에서 실패했는지**를 가른다.

### 🎯 이관 관점의 부수 소득
**마켓상품번호로도 검색된다** = 더망고 내부에 **마켓상품번호 ↔ 더망고 상품번호 짝이 존재**한다는 확증.
⇒ §06 이관 통로 판정 보강: 화면에서 **1건씩은 역추적이 가능**하다. (다만 16.8만 건 일괄 추출은 여전히 불가)

### 🔴 한계 — **최대 7일 보관**
7일 지나면 사라진다. 문제가 늦게 발견되면 원인을 못 찾는다.

### 게이트 판정
| 게이트 | 결과 |
|---|---|
| G1 | ❓ 사용 흔적 불명 (로그는 문제 생겼을 때만 본다) |
| **G2 대체** | 우리는 `AuditLog`(범용 변경 이력) · `CrawlDelta` · `PriceSnapshot` · 업로드 게이트 `reason_code` 가 **이미 있다**. 없는 건 **한 상품 기준으로 모아 보는 화면** |
| G4 | 문제 추적이 안 되면 사장님이 물을 때 답을 못 한다. 값어치 있음 |
| G5 | 위험 없음 |

**판정 🟡 형태 바꿔 채택**
- 새 로그 테이블을 만들지 않는다 (**G2** — 이미 있는 것을 모아 보여주면 된다)
- **「상품 1건의 전체 이력」 화면**을 만든다: 크롤 → 게이트 판정 → 전송 → 결과
- 🔵 **보관 기간은 우리가 길게 간다** — 7일은 너무 짧다. 우리 `CrawlDelta`·`AuditLog` 는 이미 계속 쌓인다
- 🔵 우리가 더 나은 점: 우리는 **「왜 안 보냈는지」(P2 스킵·역마진 가드·일일 상한)까지 `reason_code` 로 남긴다.** 더망고 로그엔 성공/실패만 있다

### 게이트 판정 ⚪ **보류**
- **G1 ❌** — Pro 전용 기능인데 **한 건도 안 쓰신다**
