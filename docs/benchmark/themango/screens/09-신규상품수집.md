| **SSG (검색)** | `/search.ssg?query=<검색어>&shpp=department&repBrandId=<ID>\|<ID>…` | 🎯 **`repBrandId` 를 파이프로 여러 개**. `shpp=department` = 백화점관 한정 |
| **SSG (셀러홈)** | `/sellerhome/<셀러ID>/search/seller.ssg?query=<검색어>` | 🎯 **셀러 단위 수집** (`149766`) |

⇒ `gf=A` (무신사), `shpp=department` (SSG) 같은 **고정 파라미터**가 있다 — 어댑터에 상수로 박을 것.

## 🔴🔴 정정 (8번째, 이번 세션 최대) — 「유지율」이 아니라 「휴지통」

앞선 보고에서 이 컬럼을 저해상도 스크린샷으로 `저장상품/유지율` 로 읽고
**"유지율 3.9% — 긁은 것의 78~100%가 죽는다"** 는 결론을 냈다.

**실제 헤더는 `저장상품/휴지통` 이다.** 두 화면 모두 `get_page_text` 로 확인했다.

| | 틀린 해석 | **실제** |
|---|---|---|
| 무신사 언더아머 1,106 / 43 | 43개만 생존 (3.9%) | **43개만 휴지통 → 생존 96.1%** |
| 무신사 타미진스 1,736 / 0 | 전멸 | **0개 삭제 → 100% 생존** |
| SSG 언더아머 3,120 / 704 | 22% 생존 | **77.4% 생존** |

⇒ **수집한 상품은 대부분 살아 있다.** 결론이 정반대였다.
⇒ 저장 한도 20만이 병목인 이유도 달라진다 — **죽어 쌓이는 게 아니라 계속 새로 긁어서 차는 것**이다.

### ★ 이 사고의 규율
🔴 **스크린샷 OCR 로 숫자·컬럼명을 읽고 결론 내지 말 것.** 반드시 `get_page_text` 로 재확인.
판독 오류 하나가 **「대량등록은 대부분 죽는 사업」**이라는 틀린 세계관을 만들었고 메모리에까지 저장됐다.

## 🎯 대신 진짜 지표가 드러났다 — **필터별 누적매출금액**

| 관찰 | 뜻 |
|---|---|
| 필터 12개 중 **매출 난 것은 3개** (나이키×2, 룰루레몬) | **긁는다고 팔리지 않는다** |
| 룰루레몬 2,127개 → 548,560원 | 상품당 258원 |
| 나이키 무신사 1,491개 → 207,060원 / SSG 2,307개 → 221,500원 | 같은 브랜드도 소싱처마다 다름 |
| 정렬 `매출금액순` · 필터 `매출이 발생한 필터만 보기` · 검색 `매출발생 여부` | **더망고도 이걸 핵심 지표로 본다** (세 곳에 배치) |

⇒ 🟢 **채택 확정**: 우리에게 **「검색조건 단위 매출」 축이 없다.**
**「몇 개 긁었나」가 아니라 「이 검색어가 얼마를 벌었나」**가 대량등록의 성적표다.
이 숫자가 있어야 **어떤 필터를 더 자주 돌리고 어떤 필터를 버릴지** 정할 수 있다.
🔵 우리 크롤 계수(`CrawlWeightRule` 1~5)와 붙이면 강력하다 — **매출 나는 필터의 계수를 올린다.**

## 🆕 검색필터의 「종류」가 6가지다 (`admin_group.php` 필터 select 실측)
`전체 검색필터` / **`비그룹 검색필터`** / **`그룹 검색필터`** / **`별도관리 검색필터`** / **`수동등록 검색필터`** / **`복사된 검색필터`**

\+ 상품수집사이트 select 맨 위에 **`[수동등록상품]`** 항목이 따로 있다.

\+ 검색 종류에 **`적용정책명 검색`** 이 있다.

⇒ 필터에 **상태·출처 분류가 붙어 있다.** 🟢 채택 — 수천 개가 되면 반드시 필요하다.

### 🔵 접합점 (재구현 금지)
