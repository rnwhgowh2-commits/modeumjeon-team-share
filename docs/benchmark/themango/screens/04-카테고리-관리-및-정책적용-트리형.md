### 가로탭 2개 (검색필터 화면과 공유)
`✔ 상품수집조건(검색필터) 관리 및 정책적용` | **`✔ 카테고리 관리 및 정책적용`**

### 상단 컨트롤
- **소싱처 select** (위 11개) — 소싱처를 고르면 그 소싱처의 카테고리 트리가 뜬다
- **`- Depth -` select** — 몇 단계까지 펼칠지

### 표 (5열)
| 열 | 내용 |
|---|---|
| **카테고리명** | 📁 트리. `➕` 로 펼침. 예: `29CM.co.kr` → `남성모자 [2단계]` |
| **상품정책적용** | `[상품정책적용]` 버튼 |
| **카테고리설정** | `[카테고리매핑&카테고리설정]` 버튼 · 헤더에 🎯**`[AI 자동 매핑]` 배지** |
| **저장개수** | `[1개 확인]` — 그 카테고리에 저장된 상품 수 + 확인 버튼 |
| **기능** | `[마켓전송]` · `[삭제]` |

### 🔴 화면 하단 경고
> **"카테고리 삭제시 해당 카테고리에 등록되어 있는 모든 상품이 삭제됩니다."**

검색필터 화면의 *"필터 삭제 = 그 상품 전부 삭제"* 와 **같은 위험 구조**다.
⇒ 🟡 **우리는 이 설계를 따라가지 않는다.** 분류를 지웠다고 물건을 버리면 안 된다. 삭제 시 **① 소속 상품 수를 먼저 보여주고 ② 상품은 「미분류」로 옮기는** 것이 옳다.

### 🎯 카테고리 행에 `[마켓전송]` 버튼이 직접 있다
= **카테고리 단위 일괄 전송.** 검색필터·상품·카테고리 **세 축 모두에서 전송을 걸 수 있다.**
우리는 전송 진입점이 `send` 탭 하나다. 🟢 **채택 검토** — 다만 진입점이 늘면 「무엇이 언제 나갔는지」 추적이 어려워진다. 우리 업로드 게이트 로그와 묶어야 한다.

## 모음전·대량등록 대응 (6칸 규격)

### ① 카테고리 상속
| 칸 | 내용 |
|---|---|
| **Job** | 카테고리 하나에 정책을 걸면 그 아래 전부에 적용되게 해서 예외 설정 비용을 줄인다 |
| 우리 Job | **있음** |
| 더망고 해법 | *"적용된 정책은 하위 카테고리에는 자동 적용됩니다"* |
| **우리 해법** | ❌ 카테고리 축 정책 없음. 우리 정책 축은 **구성 > 상품 > 기본**(`SetPolicyLink`·`BundlePolicyLink`·`is_default`) |
| **동일성** | 다름 — 저쪽은 **분류 트리**, 우리는 **판매 단위** |
| **판정** | 🟡 — 우리는 카테고리가 정책 축이 **아니다**. 무리하게 축을 늘리면 정책 출처가 5갈래로 흩어진다. **먼저 「우리에게 카테고리 단위 예외가 실제로 필요한가」를 확인**하고 결정 |

### ② 소싱처 카테고리 트리 보유
| 칸 | 내용 |
|---|---|
| **Job** | 소싱처가 상품을 어떻게 분류했는지를 우리 쪽에 갖고 있어 마켓 카테고리로 옮긴다 |
| 우리 해법 | ✅ **있음** — `source_category_ingest.py` (M3 소싱처 카테고리 수집) · `CategoryMapRow`(소싱처→마켓 맵핑, 제안/확정/재확정 하이브리드) |
| **동일성** | 같음 |
| **판정** | 🔵/🟢 — 수집은 우리도 한다. 없는 것은 **① 중간 표준층(THE MANGO 카테고리) ② 트리 화면에서 바로 정책·전송** |
