# 용어 대응 사전 · 역방향 대조

> 사장님 지적(2026-08-06): *"단어나 워딩이 달라서 우리 프로그램 기능과 더망고 기능 매칭을 제대로 못 했을 수도 있겠다."*
> **맞았다. 그리고 주의력 문제가 아니라 방법의 구조적 결함이었다.**

---

## 1. 왜 반드시 틀리게 돼 있었나 — 「단방향 검색」의 거짓 음성

지금까지 내 절차는 이랬다.
```
더망고 화면에서 단어를 본다  →  그 단어로 우리 코드를 grep 한다  →  0건이면 「우리에겐 없다」
```
🔴 **우리가 그걸 다른 이름으로 부르면 결과는 항상 0건이다.** 거짓 음성이 방법상 보장돼 있었다.
실제로 이 방식으로 **금지어 · KC인증 · 수집제한 · 정책 상속** 네 번을 틀렸다.

### 고치는 법 = 양방향 + Job 검색
| 방향 | 절차 | 잡는 것 |
|---|---|---|
| **① 더망고 → 우리** (기존) | 저쪽 기능을 보고 우리 코드에서 찾는다 | 우리에게 없는 것 |
| **② 우리 → 더망고** (신규) | **우리 코드의 전 기능을 먼저 열거**하고, 각각에 대해 「더망고에 이게 있나」를 묻는다 | 🎯 **우리에게 있는데 내가 못 찾은 것** |
| **③ Job 검색** | 단어가 아니라 **문제**로 찾는다. 「등록 실패를 막는다」로 찾으면 `banned_words`·`required.py`·`preflight`가 같이 걸린다 | 이름이 전혀 다른 대응물 |

**②의 출발점 = 우리 ORM 테이블 132개** (`lemouton/**/models.py`). 화면이 아니라 **데이터 모델**에서 시작해야 한다 — 화면은 기능을 감추지만 테이블은 못 감춘다.

## 2. 🔴🔴 역방향 대조가 즉시 잡은 최대 오판 — **우리는 이미 상속을 갖고 있다**

내가 「우리는 평면, 더망고는 4단 상속」이라 단정했다. **틀렸다.**
이유는 명확하다 — **나는 대량등록의 `ProcessPolicy` 만 보고 모음전의 `MarketPolicy` 를 안 봤다.** 사장님이 경고한 *"기능이 두 곳에 퍼져 있다"* 가 정확히 이 사고를 냈다.

### 우리 모음전 정책 시스템 실체 (`lemouton/policy/`)
| 테이블/파일 | 실제 내용 (주석 원문) |
|---|---|
| `MarketPolicy` | *"정책 한 벌. 여러 상품에 같은 정책을 붙일 수 있다"* · `name` `memo` **`brand`** `enabled_markets` **`is_default`** |
| `MarketPolicyValue` | *"(정책 × 마켓 × 항목) 값 한 칸. **비어 있으면 「안 정함」 — 0 이 아니다**"* |
| ↳ `from_common_at` | *"「마켓 공통」에서 받은 시각"* → **마켓 공통 → 마켓별 상속** |
| `BundlePolicyLink` | *"상품 하나에 정책 하나. ★ **구성(벌)에 따로 정하지 않았을 때 쓰는 바탕값**"* |
| `SetPolicyLink` | *"어느 **구성(벌)** 에 어느 정책을 붙였나 — 「한 상품에 여러 정책」의 실체"*<br>🔴 *"**되받기(fallback)를 반드시 지킨다** — 구성에 정책이 없으면 상품 정책, 그것도 없으면…"* |
| `common_sync.py:124` | `out[v.field_key] = 'common' if v.from_common_at else 'own'` |
| `fields.py` / `required.py` | 정책 항목 정의 + **마켓별 필수 판정** |
| `copy.py` | 정책 복사 |

### 나란히 놓으면
| 축 | 더망고 | **모음전 (실코드)** | 우열 |
|---|---|---|---|
| 정책 상속 | 개별 > 검색필터 > 카테고리 > 기본정책 (4단) | **구성 > 상품 > 기본정책(`is_default`)** (3단) | ≈ |
| 항목 단위 오버라이드 | 검색필터에서 **8항목만** | `MarketPolicyValue` — **(정책×마켓×항목) 전 항목** | 🔵 **우리 우위** |
| 「안 정함」과 「0」 구분 | 미확인 | **명시적으로 구분** (주석에 못박음) | 🔵 |
| **값의 출처 표시** | ❌ 없음 | ✅ **`'common'` / `'own'`** 로 화면에 표시 | 🔵🔵 **우리 우위** |
| 마켓 on/off 3상태 | 체크박스 2상태 | `enabled_markets` — **NULL=전부켜짐 / `'[]'`=전부끔 / 배열=선택** | 🔵 |
| 브랜드별 분류 | **정책명에 문자열로** (`무_나이키`) → 138개 폭발 | **`brand` 컬럼** | 🔵🔵 **폭발을 구조로 막음** |
| 마켓별 필수 판정 | *"모든 설정값은 필수입니다"* 문구뿐 | `required.py` — 마켓별 필수 항목 판정 | 🔵 |

> **§4에서 내가 「상속 도입 조건 = 이 값이 어느 층에서 왔는지 표시」라고 썼다.
> 우리는 이미 그걸 하고 있었다.** 도입할 게 아니라 **대량등록으로 옮길** 문제다.

### ⇒ 진짜 결론이 바뀐다
따라할 것은 **「상속」이 아니다.** 우리 진짜 문제는 이것이다:

🔴 **우리 프로그램 안에 정책 시스템이 두 벌이다.**
| | 모음전 | 대량등록 |
|---|---|---|
| 테이블 | `MarketPolicy` + `MarketPolicyValue` + `BundlePolicyLink` + `SetPolicyLink` | `ProcessPolicy` + 13항목 규칙 |
| 상속 | ✅ 구성>상품>기본, 공통>마켓별, 출처표시 | ❌ `PolicyConflict` — 한 구성에 정책 하나, 겹침 금지 |
| 항목 | 마켓 전송값 (fields.py) | 가공 규칙 13항목 |
| 화면 | `/templates` 가격 정책 | `/bulk/?tab=process` |

**더망고는 이걸 하나로 통합해 갖고 있다.** 우리가 배울 진짜는 「상속을 만들기」가 아니라 **「두 벌을 하나로 합치기」**다.

## 3. 역방향 대조로 잡은 추가 오판 3건

### 🔄 「수집제한」(상품번호 블랙리스트) — 🟢 → 🔵 + 🟢
| | |
|---|---|
| **Job** | 다시는 안 가져올 것을 못 박는다 |
| 더망고 | 수집제한 관리 — **상품번호** 단위 블랙리스트 |
| **우리** | ✅ **크롤 계수 0 = 제외** (`crawl_schedule.py:124` — *"0~5로 클램프(**0=크롤 제외**)"*, `:69` *"계수 0 = 크롤 제외 → 한 번도 안 긁었어도 영원히 마감 안 됨"*)<br>범위: `CrawlWeightRule.scope_type = source｜brand｜model｜url` **4단** |
| **판정** | 🔵 **우리 우위** — 더망고는 상품번호 1건씩, 우리는 **소싱처·브랜드 통째로** 뺄 수 있다<br>🟢 채택할 것은 **「이 상품 다시 안 가져오기」 원클릭 버튼 + 제외목록 조회 화면**뿐 |

### 🔄 「마켓 등록/업데이트 개수 제한」 — 🟢 → 🔵
| | |
|---|---|
| **Job** | 마켓 일일 한도를 넘겨 전송이 통째로 실패하는 것을 막는다 |
| 더망고 | 매뉴얼 경고 문구뿐 — *"마켓마다 아이디별로 상품 등록개수 제한 또는 일일 업데이트 개수 제한이 있을 수 있습니다"* + 마켓아이디별 「최대등록상품개수」 입력칸 |
| **우리** | ✅ **엔진이 막는다** — `uploader/daily_cap.py::decide_cap` → `CapDecision(reason_code='daily_cap_reached'\|'within_daily_cap')`, `daily_cap_service.py` 가 **실제 업로드 이력을 세서** 판정. `is_sold_out` 인자 = 품절은 별도 취급 |
| **판정** | 🔵 **우리 우위** — 저쪽은 경고, 우리는 차단 |

### 🔄 「상세페이지 템플릿」 — 앞서 정정한 것 재확인
우리 `mode='frame'` + `top_images`/`bottom_images`/`common_notice`/**`hide_source_logo`**.
**🔵 `hide_source_logo`(소싱처 로고 가리기)는 더망고에 없다** — 저쪽은 워터마크를 **얹기**만 한다.

## 5. 이 사고에서 배운 규율 (남은 27화면에 적용)

1. **화면이 아니라 테이블에서 시작한다.** 우리 132개 테이블 명부를 옆에 두고 대조한다.
2. **양방향으로 본다.** 「저쪽에 있는데 우리에게?」 뿐 아니라 **「우리에게 있는데 저쪽에?」**
3. **모음전과 대량등록을 항상 둘 다 뒤진다.** 이번 최대 오판(정책 상속)이 정확히 한쪽만 봐서 났다.
4. **단어로 못 찾으면 Job 으로 찾는다.** 「금지어」로 0건이어도 「등록 실패를 막는다」로는 걸린다.
5. **「없다」는 판정에는 근거를 단다.** 「grep 0건」은 근거가 아니다 — **어느 Job 으로 어디를 찾았는지**를 적는다.
