## A. 상품관리 — 수집 후 가공의 전부

### A-1. ★ 「수기 수정 = 자동 잠금」 규칙 — 더망고 설계의 정수

더망고는 **사람이 손댄 항목을 자동 업데이트에서 빼는 규칙**을 일관되게 적용한다.

| 수기로 바꾼 것 | 자동으로 벌어지는 일 |
|---|---|
| 상품 **가격** 수정 | `상품가격업데이트` → **자동 OFF** |
| 상품 **재고** 수정 | `상품재고업데이트` → **자동 OFF** |
| **상품명** 수동 변경 | 이후 상품업데이트해도 상품명 안 바뀜 |
| **상세페이지** 수동 수정 | 이후 상품업데이트해도 상세페이지 안 바뀜 |
| **번역** 완료 | 이후 상품업데이트해도 번역본 유지 |

되돌리려면 `상품업데이트 ON/OFF` 를 다시 **ON** 으로.

🟢 **채택 판정: 반드시 따라할 것.** 우리에게 이 개념이 명시적으로 없다. 「사람이 고친 값을 크롤이 덮어쓰는」 사고는 이 프로젝트에서 가장 비싼 종류의 버그다.

### A-2. 검색 조건 12종 (모든 상품 화면 공통)
`상품관리` · `상품업데이트&마켓전송` · `전송마켓삭제` · `상품번역/복원` 이 **같은 검색기**를 쓴다.

| 축 | 내용 |
|---|---|
| 수집사이트 | 원문 사이트 선택 |
| 수집사이트 카테고리 | 소싱처 카테고리 |
| **마켓 등록/미등록** | 마켓별로 「등록됨/안 됨」 |
| 상품 상태 | 기본값 = **재고+품절 모두** |
| 상품명 | |
| **상품번호** | 더망고 번호. **콤마로 여러 개 동시** |
| 수집사이트상품번호 | 원문 번호 |
| **전송마켓상품번호** | 마켓 번호. **콤마로 여러 개 동시** |
| **검색필터명** | 그 필터로 수집된 모든 상품 |
| **적용정책명** | 그 정책이 적용된 모든 상품. ⚠️**마켓 전송 완료 상품만 검색됨** |
| 상품메모 | |
| 브랜드명(원문) | 수집 당시 기준 |

🟢 **채택**: 검색필터명·적용정책명으로 상품을 되찾는 축. 대량 운영에선 이게 없으면 상품을 잃어버린다.

### A-3. 삭제 2단계 (휴지통 → 영구삭제)
```
삭제 → 휴지통(삭제된상품)  →  영구삭제 → 완전 소멸
                            ↘  복원 (영구삭제 전까지만)
```
- 🔴 **영구삭제 시 마켓에 등록된 상품도 함께 삭제된다.**
- 마켓 등록 직후 또는 **주문 진행 중인 상품은 마켓에서 삭제 안 될 수 있음** → 시간 두고 재시도
- 영구삭제한 상품은 복원 불가 → 다시 수집해야 함

### A-4. 연속 품절상품 일괄삭제
- **N일 연속 품절**인 상품을 검색해 일괄 삭제
- 판단 근거 = **가격재고이력**. 상품업데이트를 자주 해야 정확해짐
- 논리: "20일 연속 품절이면 영구 품절로 간주"

🟢 **채택**: 대량등록은 필연적으로 죽은 상품이 쌓인다. 자동 청소 장치가 필요.

### A-5. 마켓 상품만 삭제 (`110`)
- 수집 상품은 남기고 **마켓 등록분만** 삭제
- 💡 존재 이유: **"마켓 카테고리를 잘못 등록하면 마켓에서 카테고리 변경이 불가능"** → 삭제 후 재등록 외엔 방법이 없음

⚠️ 이건 우리도 반드시 알아야 할 마켓 제약. 카테고리 오등록 = 삭제·재등록 확정.

### A-6. 옵션 다루기
| 기능 | 내용 |
|---|---|
| **옵션 사용/미사용** | 체크 해제한 옵션은 **마켓 전송 제외 + 재고·가격 업데이트도 중단** |
| **옵션명 변경** | 개별 변경 |
| **옵션명 자동 넘버링** | 접두어 입력 → 자동 번호 부여. 💡중국·일본 사이트처럼 옵션명이 못 읽을 글자일 때 |
| **옵션 수집 제외 설정** | 환경설정에서 소싱처별로, 특정 문자열 포함 옵션은 **수집 자체를 안 함**. 💡예: "세트", "묶음" |

### A-7. 상품명 변경 3층

🟢 **채택**: 마켓별 상품명 분기. 마켓마다 금지어·글자수 제한이 달라 실무상 필수.

🟢 **채택**: "이건 다시는 안 가져와" 를 한 번에. 신규상품수집을 반복하면 반드시 필요해진다.

## B. 환경설정 — 운영 레버

### B-1. 🎯 「업데이트 반복설정」 (`160`) = 사장님 5단계 ⑤의 실체
> "상품업데이트 및 마켓전송이 완료되었을 때 **반복해서** 업데이트할 수 있습니다."
> 🔴 Notice: **"업데이트 완료 후에 브라우저를 닫으면, 반복업데이트가 되지 않습니다."**

⇒ **더망고의 지속 갱신은 「브라우저 탭이 계속 켜져 있어야 도는」 구조다.**

🔴 **여기가 더망고의 가장 큰 구조적 약점이자, 우리의 최대 기회다.**
- 더망고: 브라우저 살아 있어야 함 → PC 끄면 멈춤 → 밤새 못 돎
- 우리: `crawl_schedule.py` 가중 라운드로빈 랩 + 워커 큐 + `CrawlLapRun` — **엔진이 이미 서버/워커 기반**
- 우리는 여기에 **P0/P1/P2 업로드 게이트**까지 갖고 있다

### B-2. 수집 차단 3종 세트
| 설정 | 내용 |
|---|---|
| **금지어설정** (`154`) | **상품명/상품설명**에 특정 문구 → 저장 또는 마켓전송 차단 |
| **가격제한설정** (`155`) | **화폐단위별 가격범위** → 저장 또는 마켓전송 차단 |
| **금지어/가격제한 처리** (`156`) | 🎯 **이미 저장된 상품**이 걸리면 → **품절 처리 또는 삭제 처리** 선택 |

⇒ ③이 핵심이다. 규칙을 나중에 바꿔도 **과거 상품에 소급 적용**된다. 대량등록에선 필수 장치.

### B-3. 재고·수집 정책
| 설정 | 내용 |
|---|---|
| **최대 재고수량** (`161`) | 수집 재고가 이 값보다 크면 **이 값으로 캡** (상품·옵션 모두) |
| **품절상품 수집설정** (`163`) | 신규수집 시 품절 상품을 가져올지. 가져오면 상태 = "품절상품" |
| **브랜드명 설정** (`162`) | 브랜드 없는 상품에 **기본 브랜드명 부여** |
| **카테고리 고정** (`158`) | 신규수집 시 기존 상품의 카테고리 변경 여부 |
| **검색필터 고정** (`159`) | 🎯 신규수집 대상이 **이미 저장된 상품**일 때, 그 상품의 검색필터를 **바꿀지 말지** |

⇒ `159`가 미묘하지만 중요하다. 같은 상품이 검색필터 A·B 양쪽에 걸릴 때 **어느 그룹의 정책을 받을지**가 여기서 갈린다. 정책 3단 상속의 숨은 4번째 변수.

### B-4. 🎯 마켓분산등록 설정 (`58`)
> "1개의 상품을 **1개의 마켓에만** 등록하여, 마켓에 등록 가능한 수량을 최대한으로 이용하기 위한 설정"
> Notice: **"같은 마켓의 서로 다른 아이디에는 분산등록되지 않습니다."**

+ **마켓아이디 관리(`134`)의 「최대등록상품개수」** — 초과 시 마켓상품등록 제한

⇒ 마켓별 등록 한도가 병목일 때, **같은 상품을 여러 마켓에 중복 등록하지 않고 흩뿌려서 총 노출 상품 수를 최대화**하는 전략. 🟡 검토 대상 — 우리 6마켓 전송 방침과 상충할 수 있음(사장님 판단 필요).

### B-5. 마켓별 세부설정 (`135`)
마켓 **아이디별로** 설정: 전송 가격 · 옵션가격 · **전송 옵션개수** · 금지어 · 송장 전송 시 택배사

### B-6. 🎯 정산금액 계산식 설정 (`195`)
> 정산예정금액이 제공되지 않는 마켓도 **계산식으로 예측**
> - 정산확정 시점에만 알 수 있는 마켓: 쿠팡·롯데온·신세계몰
> - 정산금액 자체가 없는 마켓: 트렌비·카페24·고도몰·아임웹
> - Tip: *"대략적인 순마진·역마진 계산에 활용"*

⇒ 우리 「정산예정금액 탭」·마켓별 수수료율 표와 정확히 대응. **우리가 이미 실측 기반으로 더 정확하다**(스스6·쿠팡11.55·롯데온18·11번가11→체크시8·옥션지마켓15). 다만 **「계산식을 사용자가 편집한다」**는 발상은 채택 가치 있음.

### B-7. 편집모드 설정 (`150`)
- 상품관리에서 **편집모드로 전환했을 때 어떤 항목을 인라인 편집 가능하게 할지** 미리 고름

## C. 주문관리 · CS · 통계 (비교용)

### C-1. 주문 수집 (`33`)
- 마켓별 또는 **전체마켓 한번에** — 주문/클레임/문의내역을 동시에
- 🎯 수집하면서 **2가지를 자동 검사**:
  - **통관부호오류** 체크 (해외 전용)
  - **[가격변동]** — *"마켓 등록 당시의 해외가격과 현재 해외가격이 다르면 표기"*

⇒ **후자가 중요하다.** 사장님이 말한 *"주문 시점에도 그 가격 그대로 주문되는 것이 관건"* — 더망고도 같은 문제를 인식하고 **주문 화면에 「가격변동」 딱지**를 붙인다. 우리 설계(등록시점가 vs 주문시점가 전후 표시)와 같은 방향.

### C-2. 주문 검색축
주문자명 · 주문번호 · 전화번호 · 주문상품명 · 더망고상품번호 · 해외트래킹번호 · **국내송장번호** · 해외상품번호 · 마켓상품번호 · 메모

**보기 기준 5종**: 배송대행지별 / **마켓별·마켓아이디별** / 원문사이트별 / 마켓상태별 / 주문상태별

### C-3. 🎯 예상수익계산기 (`46`)
> "해외쇼핑몰의 가격이 변동되었을 때 예상 수익을 계산해본 후 **해당 주문건을 취소할지, 구입할지 결정**"
> "계산에 포함되는 **어떤 항목이든 자유롭게 변경**하여 수익을 계산"

🟢 **채택 가치 큼.** 역마진 주문을 만났을 때 **버릴지 살릴지 판단하는 도구**. 우리 마진계산기와 성격이 다르다 — 우리는 사후 정산 분석, 이건 **주문 건별 사전 의사결정**.

### C-4. 주문내역 엑셀 (`36`) — 실제 컬럼 (우리가 이미 파싱 중인 그 파일)
주문일자 · 쇼핑몰주문번호 · 마켓 · 마켓아이디 · 마켓상품번호 · 마켓상품URL · 결제금액 · 수취인명 · 수취인주소1 · 수취인주소2 · 우편번호 · 휴대폰번호 · 통관고유부호 · 택배사 요청메시지 · **국내송장번호** · 원문사이트 · 해외상품번호 · 해외주문번호 · 브랜드 · 상품명 · 수량 · 옵션1 · 옵션2 · 상품URL · 상품이미지 · **구입가** · 트랙킹번호

⇒ 우리 `buy_parser`·배송검사 탭이 읽는 그 엑셀의 **공식 컬럼 정의**. 문서화 가치 있음.

### C-5. 발송·배송대행
- **송장번호 마켓전송** — 여러 주문 선택 → 마켓에 발송처리
- **배송대행신청서 연동** — 별도 유료 솔루션. 신청서 자동작성 → **배송대행지가 만든 국내송장번호를 자동 수집** → 그걸로 마켓 발송처리
- ⚠️ 주문정보 수정은 **엑셀 다운로드에만 반영**되고 **마켓 배송정보는 안 바뀜**

### C-6. CS
문의내역 수집 → **답변하기 → 마켓으로 전송** / **답변 템플릿 관리** / 관련·과거 문의내역 확인

### C-7. 통계
매출 / 상품별 매출 / **마켓 접속통계** / **마켓 상품별 접속통계** / 더망고 API 접속통계

⇒ **접속통계(조회수)** 는 우리에게 없다. 🟡 어떤 상품이 보이기만 하고 안 팔리는지 = 상품명·이미지·가격 문제 진단. 대량등록에선 상품이 수천 개라 이 신호가 필요하다.
