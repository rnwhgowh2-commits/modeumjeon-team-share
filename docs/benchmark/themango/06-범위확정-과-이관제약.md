## 2. 🔴🔴 이관(마이그레이션) 제약 — 설계의 전제

> 사장님 확정: *"마켓에 저장되어 있는 상품은 현재 세션에서 안 하고 다른 세션에서 진행할거야.
> 다만, **꼭 기억은 해둬! 프로그램 이관은 해야된다는 점.**
> 우리 프로그램에 맞도록 하는 건 당연하겠지?
> **우선적으로 프로그램 갖추어놓고 이관할 예정**이야."*

### 순서가 정해졌다
```
① 우리 대량등록 프로그램을 먼저 갖춘다   ← 지금 이 프로젝트
② 그 다음 더망고 자산을 우리 쪽으로 옮긴다  ← 별도 세션
```
**②는 지금 하지 않는다. 그러나 ①의 설계가 ②를 가능하게 만들어야 한다.**

### 🔴 이관 대상 자산 (실측 규모)
| 자산 | 규모 | 왜 어려운가 |
|---|---|---|
| **수집 상품** | **167,921개** (한도 20만) | 소싱처 URL·옵션·이미지·상세 |
| **정책** | **138개** | 가격 구간 마진 · 마켓별 21항목 |
| **검색필터** | N개 (그룹핑 포함) | 수집 URL·수집개수·오버라이드 8항목 |
| **카테고리 매핑** | 소싱처→THE MANGO→6마켓 | 중간 표준층이 우리에게 없음 |
| 🔴 **마켓 상품번호** | 마켓×계정×상품번호 | **이게 가장 중요하다 (아래)** |
| 상세페이지 템플릿 · 치환정책 · 금지어 템플릿 | 각 N개 | |
| 주문·CS 이력 | — | 별도 판단 |

### 🔴🔴 이관에서 절대 놓치면 안 되는 것 — **마켓 상품번호**

이미 마켓에 올라가 팔리고 있는 상품이 있다. 그 상품의 **마켓 상품번호**를 가져오지 못하면:
- 우리가 같은 상품을 **신규 등록**한다 → **마켓에 중복 상품** → 정책 위반·계정 위험
- 또는 우리가 그 상품을 **수정할 수 없다** → 가격·재고가 영영 안 맞는 유령 상품이 남는다

⇒ **이관의 성패는 「소싱처 URL ↔ 마켓 상품번호」 짝을 온전히 옮기느냐**에 달렸다.

#### 🔴 이관 통로 판정 — **확정** (2026-08-06 실측)

| 통로 | 판정 | 근거 |
|---|---|---|
| 상품 목록 **엑셀 내보내기** | 🔴 **없음** | 상품관리 화면에 내보내기 버튼 없음. `[엑셀 상품등록]`은 **넣기**(우리→더망고) 전용 |
| **더망고 API** | 🔴 **미구독 + 유료** | `통계 > 더망고 API 접속통계` = `등록된 API 가 없습니다`. 매뉴얼 `t_api`: *"더망고 API 솔루션을 **신청하신 후**에 발급 가능… `[Qmenu]-[서비스추가/업그레이드]` 에서 추가"*. 통계 컬럼에 **`Call 차감`** = **호출량 과금** |
| 주문내역 엑셀 (`마켓상품번호` 포함) | 🟡 **부분** | 주문 난 상품만 |
| **마켓 API 직접 조회** | 🟢 **채택** | 우리가 이미 `catalog/`·`MarketProduct`·`MarketProductCount` 로 마켓 상품을 읽는다 |
| 화면 긁기(스크래핑) | 🟡 최후수단 | 16.8만 건 × 카드형 10개씩 = 비현실적 |

### ⇒ 이관 방식 확정안 (이관 세션 인수인계)
```
① 소싱처 URL·상품번호·옵션·가격  ←  더망고 화면/엑셀에서 확보 (경로 재확인 필요)
② 마켓 상품번호                  ←  🟢 마켓 API 로 우리가 직접 조회
③ 짝 맞추기                      ←  우리 쪽에서 (소싱처URL ↔ 마켓상품번호)
```
🎯 **짝을 맞출 열쇠 후보 = `판매자상품관리코드`** — 더망고 엑셀 R컬럼이자 **마켓의 판매자상품코드**다.
사장님이 이 값을 채워 운영해 왔다면 **양쪽이 같은 열쇠를 이미 공유하고 있다.**
🔴 **확인 과제**: 사장님 상품에 `판매자상품관리코드` 가 실제로 채워져 있는가.

🟡 **사장님 판단 필요**: 더망고 API 를 **한시적으로 유료 신청**해서 깨끗하게 뽑을 것인가, 아니면 마켓 API + 화면으로 우회할 것인가. (이관 세션에서 결정)

#### 우리 쪽 받을 그릇 (실코드 — 이미 있다)
| 테이블 | 역할 |
|---|---|
| `MarketProduct` | *"마켓 × 계정 × 상품번호 = 1행"* |
| `MarketProductGroup` | *"내가 관리하는 상품 1건 — 여러 마켓 상품을 하나로 묶는 그릇"* |
| `BundleAccountRegistration` | 모음전 × 계정 → 마켓 상품 ID |
| `ProductDraftMarket` | 대량등록 초안 × 마켓 × **`account_key`** (`'default'` 센티넬 — NULL 이면 유니크 제약 무력화) |

🎯 **그릇은 이미 있다.** 이관 설계 시 재구현 금지.

⚠️ 단 **더망고는 「마켓 상품번호」를 어디에 들고 있고 어떻게 꺼내는지 아직 모른다.**
- 상품관리 화면에 `[마켓 바로가기]` 링크가 있으니 **DB 에는 분명히 있다**
- 꺼내는 길: **주문내역 엑셀에 `마켓상품번호` 컬럼이 있다**(매뉴얼 `36` 확인) → 단 주문 난 상품만
- 전 상품을 꺼내려면 **상품관리 목록 엑셀 내보내기**가 있는지 확인 필요 → **Phase B 상품관리 화면에서 최우선 확인**

### ① 설계에 미리 넣어야 할 것 (지금 프로젝트 범위)
| # | 제약 | 이유 |
|---|---|---|
| 1 | **소싱처 URL 을 상품의 1급 식별자로** 보관 | 더망고와 짝을 맞출 유일한 공통 열쇠 |
| 2 | **마켓 상품번호를 「우리가 등록한 것」과 「받아온 것」으로 구분** | 받아온 건 등록 이력이 없다. 구분 안 하면 「등록 안 됨」으로 오판해 중복 등록 |
| 3 | **외부 유입 표시(imported flag)** + 유입 출처 | 나중에 값이 이상할 때 원인 추적 |
| 4 | **중복 등록 방어** — 등록 직전 `(소싱처URL, 마켓, 계정)` 로 기존 등록 여부 확인 | 중복 = 계정 위험 |
| 5 | 정책·필터를 **가져올 수 있는 모양**(이름·값 쌍)으로 설계 | 138개를 손으로 옮길 수 없다 |
| 6 | **이관 검증 도구** — 옮긴 뒤 개수·짝 일치 대조 | 조용한 유실 방지 |

## 3. 「내스토어 상품수집」이란 무엇인가 (범위 밖이지만 기록)

`상품데이터수집 > 내스토어 상품수집` (`shop/getGoods.php?type=2`)
전송 화면에는 `#쿠팡(내스토어)` `#스마트스토어(내스토어)` 로 나온다.

**= 이미 내가 마켓에 올려둔 상품을 더망고로 되가져오는 기능.**
소싱처에서 새로 긁는 게 아니라, **내 스토어가 소스**다.

🎯 **이게 곧 이관의 더망고식 해법이다.** 다른 솔루션에서 옮겨올 때 이 기능으로 마켓 상품을 흡수한다.
⇒ **우리도 같은 것이 필요하다** — 다만 사장님 지시대로 **다른 세션**에서 다룬다.
관련 우리 자산: `catalog/`(마켓 상품 현황) · `MarketProductCount` · `MarketProduct` — **이미 마켓 상품을 읽어오는 배선이 있다.**
