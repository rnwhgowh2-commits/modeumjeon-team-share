## ★ 가장 중요한 발견 — 「검색필터」가 더망고의 척추다

더망고에는 **상품수집조건(검색필터)** 라는 1급 개체가 있다.

- **상품을 수집할 때마다 자동 생성된다.** 사람이 만드는 게 아니라, "무신사에서 나이키로 검색했다"는 행위 자체가 그룹이 된다.
- 같은 조건으로 수집된 **상품 개수**를 세어 보여준다.
- 이름을 바꿀 수 있고, `상품관리`·`상품업데이트&마켓전송` 화면에서 **검색어로 쓸 수 있다**.
- **이 그룹 단위로 정책을 적용한다.**
- **이 그룹을 재실행해 새 상품만 가져오는 게 「신규상품수집」이다.**

⇒ 사장님이 말한 *"무신사에 나이키 검색하면 수많은 상품 나와서 하나씩 크롤"* — 더망고는 그 **검색 행위를 영구 객체로 저장**해서, 수집·정책·재수집·전송의 공통 축으로 쓴다.

🔴 **위험 설계**: 검색필터명을 **삭제하면 그 조건으로 저장된 모든 상품이 일괄 삭제**된다. (매뉴얼 명시)

## 1) 소싱처에서 크롤한다 — 상품데이터수집 (6편)

수집 경로가 **5가지**다.

| 경로 | 화면 | 입력 | 특징 |
|---|---|---|---|
| **① 대량수집 (리스팅 URL)** | `getGoodsNew.php` 🆕 / `getGoods.php` | 수집사이트 선택 + **검색어 또는 리스트 URL** | 검색결과 리스트에서 **선택저장** 또는 **전체저장**. 전체저장은 **페이지 끝까지 자동 순회** |
| **② 개별저장 (세팅방식)** | `getGoods2.php` | 상품상세 URL 1개 | 가져오기 → 확인 → 저장 |
| **③ 개별저장 (구독방식)** | (구독형 사이트) | 상품상세 URL **여러 개, 줄바꿈 구분** | 구독형 부가서비스. **등급별 사이트 수·URL 수 제한** |
| **④ 웹페이지에서 직접저장** | (크롬 익스텐션) | 소싱처 서핑 중 `⇄상품데이터 전송` 버튼 | 브라우저에서 즉시 |
| **⑤ 내스토어 상품수집** | `getGoods.php?type=2` | (자사몰) | 매뉴얼 미문서화 |

### 🔴 수집의 물리적 제약 (매뉴얼 Note)
> "저장 도중 페이지를 이동하시거나 창을 닫으시면 저장이 중단됩니다."

⇒ **크롬 익스텐션이 브라우저에서 직접 도는 구조.** 서버 크롤이 아니다. 우리와 같은 구조 — 우리도 크롤은 로컬 PC 원칙.

### 「상품 저장 설정」 — 수집 시점 필터 5종
| 항목 | 내용 |
|---|---|
| **상품명 금지어** | 상품명에 이 키워드 있으면 수집 안 함. **`;` 세미콜론으로 여러 개** |
| **저장상품수** | 검색 결과 순으로 **N개만** 수집. (최저가 정렬 + N개 = 최저가 N개만) |
| **적용정책** | 🎯 **수집하면서 즉시 정책 적용**. 수집 후 별도 적용도 가능 |
| **번역 후 저장** | 상품명/옵션명/상품설명/스펙 번역하며 저장 |
| **랜덤키워드 설정** | 템플릿 선택 + **개수·위치(상품명 앞/뒤)** — 상품명 중복 회피용 |

### 「대량 수집 작업관리」 (Pro 전용)
- 수집 작업(검색URL·카테고리URL)을 **미리 등록**해 두고
- 원하는 작업을 **골라서 한번에 시작**
- **여러 작업 동시 진행** 현황 확인

⇒ 우리 `crawl_schedule.py`(가중 라운드로빈 랩)과 성격이 다르다. 더망고는 **작업 예약·일괄 실행**, 우리는 **변동성 기반 가중 반복**. 우리 쪽이 더 정교하지만 「예약 등록」 UI는 없다.

## 2) 정책 만든다 — 정책생성&관리 (7편)

정책은 **3덩어리 + 부속 4종**이다.

### 2-1. 가격계산 정책 (`116`)
| 항목 | 의미 | 모음전 대응 |
|---|---|---|
| 국제운송료 | 상품금액에 더할 배송비. **배송무게**는 선편요금 계산용 | ❌ 해외 전용 (불필요) |
| **마진율 / 마진금액** | 둘 중 하나 입력. **동시 입력 시 마진금액 우선** | ✅ 있음 |
| **상품가격별 범위 마진** | 🎯 **가격 구간별 마진율 다르게** | ✅ 판매가 15칸 템플릿 |
| 현지배송비 | 소싱처 배송비. 상품별 별도표기 사이트는 실제값 사용 | △ 우리는 국내 |
| 별도 추가요금 | 통관료 등 **일괄 정액 가산** | ❌ 없음 (도입 가치 있음) |
| 관부가세 | **관세율만 입력하면 부가세 10% 자동 가산** | ❌ 해외 전용 |
| **최소마진금액** | 마진율 계산액 < 최소마진금액이면 **최소마진금액으로 대체** | ✅ `min_margin_amount` (단 우리는 역마진 가드용) |
| **할인율 / 할인금액** | **할인금액 입력 시 할인율 무시** | ✅ 즉시할인 배선 있음 |
| 개별소비세 | 개소세 + 교육세 | ❌ 해외 전용 |

계산식(매뉴얼 명시): `상품원가(현지통화) × 환율 × 마진율`

🔴 **결정적 차이**: 더망고 원가 = **소싱처 표면 판매가**. 우리 원가 = **최종매입가**(카드·캐시백·N쇼핑 경유 순차차감 후). **우리가 압도적으로 정교하다.** 더망고에는 혜택 차감 개념 자체가 없다.

### 2-2. 마켓정책 (`117`) — 13항목
| 항목 | 내용 |
|---|---|
| 마켓 전송여부 | 마켓별 체크. 해제하면 그 마켓엔 안 보냄 |
| **전송대상 ID** | 같은 마켓 아이디 여러 개 중 **1개 선택** |
| 판매자 형태 | 틀리면 전송 실패 |
| **수수료율** | 계산된 금액에서 **수수료율만큼 높은 금액으로 전송** (수수료 얹기) |
| 발송정책 | **마켓에서 가져오기** 버튼 → 목록에서 선택 |
| **배송비정책** | 🎯 아래 별도 설명 |
| 출하지/반품지 | **마켓에서 가져오기** 버튼 → 선택 |
| 반품배송비/택배사 | 마켓에 따라 편도/왕복 |
| AS 안내메세지 | 자유 입력 |
| 원산지 | 해외구매대행은 보통 「기타 국가」 |
| 청소년구매불가 | Y/N |
| **카테고리** | 직접 선택 **또는 「카테고리 매핑 사용」 체크 → 미리 매핑한 것 자동 적용** |
| 상품고시정보 | 선택 카테고리에 해당하는 고시정보 |
| 상세페이지 템플릿 | 미리 만든 템플릿 적용 |

#### 🎯 「배송비정책」 = 노출가 조작 장치 (매뉴얼 원문 그대로)
> 계산된 총액이 199,000원일 때
> - **무료배송** → 상품가 199,000 + 배송비 0
> - **유료배송(3만원)** → 상품가 **169,000** + 배송비 30,000
> - **총액은 199,000 으로 동일**
> - *"유료배송비를 높게 조정하시면 상품원금액이 낮게 보여질 수 있는 효과가 있습니다."*

⇒ **총액 고정 + 상품가/배송비 분배를 돌려서 검색 노출가를 낮추는 기법.** 우리 「표시가 vs 업로드가」 개념과 같은 계열이나, 더망고는 **정책 항목으로 명시적 제공**. **채택 후보 1순위.**

### 2-3. 상품정보 세부설정 (`118`) — 부속 정책 4종 연결
`상세페이지 템플릿` / `상품·옵션명 관리` / `번역 관리` / `워터마크 관리`

### 2-4. 상품명 치환 정책 (`119`)
- 문자열 → 문자열 치환. **위에서부터 순차 적용, 중복 조건이면 제일 아래 것이 승리**
- 대소문자·공백·특수문자 구분. **「대소문자 구분안함」 체크박스** 별도
- 예: `ralphlauren → 폴로`, `polo → 폴로`, `Ralphlauren → 폴로`

### 2-5. 상품명 조합 정책 (`120`)
- 수집된 정보(상품명·브랜드명·모델명 등)를 **조합해 상품명 재구성**
- **상품명은 필수 선택**. 없는 값은 빈값 처리
- 💡 매뉴얼 조언: *"마켓 상품명 50바이트 제한이 있으니 가장 긴 상품명을 마지막에 조합하라"*

### 2-6. 상세페이지 템플릿 (`23`) — **HTML + 변수 치환 엔진**
| 변수 | 내용 |
|---|---|
| `{goods_name}` | 원문 상품명 |
| `{goods_rename}` | 변경된 상품명 (없으면 원문) |
| `{goods_imageN}` | 전체 이미지. **`[IMAGE_SET]~[/IMAGE_SET]` 사이에서 반복**, `[IMAGE_SIZE]600[/IMAGE_SIZE]` 로 크기 지정(기본 600px) |
| `{goods_video}` | 상품 동영상 (수집 가능 사이트만) |
| `{goods_price}` | 원문 판매가 |
| `{goods_site}` | 수집사이트명 (amazon, ebay …) |
| `{goods_brand}` / `{goods_model}` | 브랜드 / 모델명 |
| `{goods_condition}` | 중고·새상품·리퍼비시·전시 |
| `{goods_number}` / `{goods_site_number}` | 더망고 상품번호 / 원문 상품번호 |
| `{goods_desc}` | 상품설명. **`[GOODS_DESC]~[/GOODS_DESC]` 는 설명 없으면 통째 숨김** |
| `{goods_spec}` | 상세 스펙. **`[GOODS_SPEC]~[/GOODS_SPEC]` 동일** |
| `{line_space}` | 10px 여백 |

⇒ **조건부 블록(`[…]~[/…]`)이 있는 진짜 템플릿 엔진.** 값 없으면 빈칸이 남는 게 아니라 블록째 사라진다. **채택 가치 높음.**

## 3) 정책 적용한다 — 정책적용 (4편)

### 🎯 정책 적용 계층 = 3단 우선순위
```
① 상품별 개별 정책        ← 최우선 (상품관리 > 적용정책 > 상품별 개별 정책설정)
② 검색필터(수집조건) 그룹 정책
③ 카테고리 그룹 정책       ← 상위 카테고리 → 하위 자동 상속
```
매뉴얼 원문: *"상품별 개별 정책으로 적용된 정책이 다른 그룹 정책보다 우선하여 적용됩니다."*

| 축 | 화면 | 성격 |
|---|---|---|
| 개별 | 상품관리 안 | 상품 1개 |
| **검색필터** | `admin_group.php` | 수집 행위 단위 (자동 생성) |
| **카테고리(트리형)** | `admin_category.php` | **소싱처 카테고리** 기준, 상속됨 |
| 카테고리(단계형) | `admin_category_new.php` | 매뉴얼 미문서화 — 트리형의 신버전 추정 |

### 카테고리 = **소싱처 카테고리**
- 수집 시 **자동으로 분류**되어 들어옴. 일부 사이트는 카테고리가 안 들어올 수 있음
- 소싱처별 카테고리명 + 카테고리별 수집 상품 수 표시

### 🎯 AI 마켓 카테고리 자동매핑 (`199`)
- **자체 AI 모델**로 소싱처 카테고리 → 마켓 카테고리 매핑
- **최대 5개 유사 카테고리 추천 + 가장 적합한 것 자동 선택**
- 마켓에 국내/해외 카테고리가 따로 있으면 **한번에 검색해 추천**
- 개별 매핑 / **사이트별 일괄 매핑** 둘 다
- 환경설정 > AI 관련 설정에서 **「기존 수동 매핑 카테고리 제외」** 옵션

⇒ 우리 M2 제안엔진(쿠팡 추천 앵커 + 이름 유사도, **자동확정 금지**)과 정면 대응. 더망고는 **자동 선택까지 함**. 우리는 사장님 확정 방침이 「자동확정 금지」였음 — **이 차이는 의도된 것이니 유지**하되, 「5개 추천」 UX는 채택 가치 있음.

## 4) 판매처 업로드 + 5) 지속 갱신 — 상품업데이트&마켓전송 (1편)

**두 일이 한 화면·한 버튼에 묶여 있다.**

### 입력
1. **수집사이트 선택**
2. **업데이트할 항목 선택** (원문사이트에서 다시 읽어올 것들)
3. **전송할 마켓 선택**
4. `[상품업데이트 & 마켓전송 시작 (검색결과 모든상품)]`

### 실행 순서
```
원문사이트 업데이트 (선택 항목만)  →  마켓 전송
```
- **업데이트 항목을 하나도 선택 안 하면** → 업데이트 건너뛰고 **기존 수집정보로 전송만**
- 마켓 전송은 **upsert** — 이미 등록된 상품이면 수정, 없으면 신규 등록
- 전송 시 **그 상품에 적용된 가격정책·마켓정책**을 따름

### ⚠️ 매뉴얼 경고
> "마켓마다 아이디별로 상품 등록개수 제한 또는 일일 업데이트 개수 제한이 있을 수 있습니다."

🔴 **더망고에는 업로드 게이트가 없다.** 「검색결과 모든상품」을 통째로 밀어넣는다. 우리 P0/P1/P2 게이트(가격변동 즉시 / 품절 즉시 / 재고 3↑ 구간 변동 스킵)가 **명확한 우위**. 더망고 방식은 마켓 API 한도를 의미없는 재고 업데이트로 태운다.

---

## 6) 신규상품수집 (1편) — 5단계에 없던 6번째 축

**기존 검색필터를 재실행해 「새로 생긴 상품만」 자동 저장.**

- 검색필터를 한 번만 잘 만들면, 이후엔 버튼 하나로 신상품 확보
- 매뉴얼 논리: *"신규상품을 수집하지 않으면 기존 상품은 점점 품절이 되어 판매가능 상품이 줄고, 매출도 줄어든다"* → **1~2주에 한 번 누르면 매출 유지**
- 여러 검색필터 **선택 후 일괄 실행**

### 🔴 결정적 제약
> **「검색된 상품 모두저장」으로 수집한 필터만 신규상품수집이 가능하다.**
> 일부만 골라 저장한 필터는 **불가**.

⇒ 이유가 명백하다 — 「일부 선택」은 재현 불가능한 사람의 판단이라 재실행할 수 없다. **설계 제약이 정직하게 드러난 지점.**

⇒ 우리에겐 이 축이 **통째로 없다.** 우리는 옵션별 URL을 사람이 넣으므로 "새 상품"이라는 개념이 아예 없다. **대량등록에 반드시 필요한 기능.**
